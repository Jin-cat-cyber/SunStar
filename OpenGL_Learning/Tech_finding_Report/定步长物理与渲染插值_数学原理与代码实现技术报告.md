# 定步长物理与渲染插值 —— 数学原理与实现

> 涉及文件：`src/Spaceship.h`、`src/SpaceShip22.A.cpp`、`src/PhysicsSelfTest.h`
> 对照文件：`src/SpaceShip22.0.cpp`（重构前形态，休眠存档）

## 1. 问题的提出

### 1.1 符号约定

| 符号 | 含义 | 单位 | 代码 |
|---|---|---|---|
| $h$ | 物理固定步长 | s | `Spaceship::FIXED_DT`（`Spaceship.h:105`），取 $1/120$ |
| $M$ | 单帧允许补算的时间上限 | s | `Spaceship::MAX_ACCUM`（`Spaceship.h:106`），取 $0.25$ |
| $dt_k$ | 第 $k$ 帧的真实耗时 | s | `deltaTime` |

| $\alpha_k$ | 渲染插值因子 | 无量纲 | `alpha`（`SpaceShip22.A.cpp:381`） |

| $v,\ a$ | 速度、加速度（沿机头方向） | 单位/s、单位/s² | `speed`、`accel` |
| $\omega$ | 角速度矢量，分量为偏航/俯仰/滚转 | rad/s | `yawAV / pitchAV / rollAV` |
| $F$ | 单步更新算子 | — | `Update(dt)`（`Spaceship.h:139-165`） |

后文凡出现 $S_k$ 与 $t_k$，都不是程序中的变量，而是为分析引入的中间量；程序中实际保存的状态只有 $A_k$、上一步状态与当前状态三者。

### 1.2 帧步长积分的位置截断误差

原实现每一步先更新速度，再用**更新后的速度**乘整帧时间计算位移。设该步内加速度为常数 $a$，步首速度为 $v$，则格式给出

$$x' = x + v'\,dt, \qquad v' = v + a\,dt,$$

即 $x' = x + v\,dt + a\,dt^2$。而常加速度下的精确解为

$$x(t+dt) = x + \int_0^{dt} v(\tau)\,d\tau = x + v\,dt + \tfrac{1}{2}a\,dt^2 + O(dt^3).$$

两者之差（局部截断误差）为

$$e_{\text{loc}} = x' - x(t+dt) = \tfrac{1}{2}a\,dt^2.$$

每单位时间的漂移量为 $e_{\text{loc}}/dt = \tfrac{1}{2}a\,dt$。代入 $a=20$、$dt=1/60$，得 $0.167$ 单位/s。

两点限定：其一，该误差只在加减速段存在，进入匀速段后 $a=0$，误差不再累积；其二，误差随 $dt$ 线性变化，故同一段操作在 60 fps 与 120 fps 下走过的距离不同。误差的量级不大，问题在于它**依赖帧率**。

### 1.3 姿态积分的格式误差

原实现的姿态更新是三个绕局部轴的小旋转依次复合：

$$R' = R \cdot \exp(\omega_y\,dt\,\hat z)\cdot \exp(\omega_p\,dt\,(-\hat x))\cdot \exp(\omega_r\,dt\,\hat y)\,\big/\|\cdot\|.$$

旋转不可交换。由 Baker–Campbell–Hausdorff 公式，两个指数之积可以合并为单个指数：

$$\exp(A)\exp(B) = \exp\Big(A + B + \tfrac{1}{2}[A,B] + \cdots\Big),$$

其中 $[A,B]=AB-BA$ 为对易子。因此三个小旋转的合成结果为

$$\exp\Big((\omega_y+\omega_p+\omega_r)\,dt + \tfrac{1}{2}\big[\omega_y,\omega_p\big]\,dt^2 + \cdots\Big).$$

一阶项与 $dt$ 无关，是这部分转角的本体；二阶项与 $dt^2$ 成正比，且只由不同轴之间的对易子产生。换算成每单位时间的姿态偏差，量级为 $\tfrac{1}{2}\big|[\omega_i,\omega_j]\big|\,dt$。以 `turnRate = 10°/s` 估算约为 $10^{-4}$ rad/s，肉眼不可辨，但它是**格式误差**：步长改变，姿态轨迹随之改变。

步长固定后，这两个误差项都成为常数级的、可复现的格式偏差，而不再随帧率浮动。

### 1.4 真正的动机：确定性

上述两项误差都很小，真正不可接受的是**不可复现**：

- 同一段输入在 60 fps 与 144 fps 下产生不同的终态，因此无法录放验证、无法建立回归基线；
- 一次偶发卡顿即改变轨迹，故障无法复现；
- 后续接入重力或碰撞时，变步长的显式积分在刚度较大时会发散，而固定步长把这一风险化为一个可控参数 $h$。

因此定步长的目标不是提高精度，而是把物理改写为一个确定性映射：给定初始状态 $s_0$ 与输入序列 $u_0,\dots,u_{N-1}$，状态序列由

$$s_{i+1} = F(s_i,\ u_i)$$

唯一确定，且与这些步数如何分配到各帧无关。

## 2. 定步长格式

### 2.1 累加器

真实帧时间 $dt_k$ 是抖动的，物理步长 $h$ 是常数。两者的联系由累加器给出：**把真实时间累加起来，攒够一个 $h$ 就推进一步，不足一个 $h$ 的部分留到下一帧继续使用。**

```cpp
int AdvanceFixed(float& accum, float frameDt, float& alpha)
{
    accum += frameDt;                            // 累加：A = A + dt_k。A 中还保留着上一帧的余数
    if (accum > MAX_ACCUM) accum = MAX_ACCUM;     // 截断：A = min(A, M)，多余时间被舍弃
    int steps = 0;
    while (accum >= FIXED_DT)                    // 循环条件：A 是否已达到一个步长
    {
        FixedUpdate(FIXED_DT);                   // 推进一步，步长恒为 h
        accum -= FIXED_DT;                       // 消耗：A = A − h
        ++steps;
    }
    alpha = accum / FIXED_DT;                    // 余数化为比例：alpha = A / h
    return steps;
}
```

对应的递推关系为

$$A_k = \operatorname{clamp}\big(A_{k-1}+dt_k,\ \le M\big) - n_k h, \qquad n_k = \left\lfloor \frac{\operatorname{clamp}\big(A_{k-1}+dt_k,\ \le M\big)}{h} \right\rfloor, \qquad \alpha_k = \frac{A_k}{h},$$

其中 $\operatorname{clamp}(x,\le M)=\min(x,M)$。

注意 $A_{k-1}$ 出现在第 $k$ 帧的表达式里，即**余数跨帧保留**。这是全部性质的来源；§4 讨论它被破坏时的后果。

循环的退出条件给出一个不变量：

$$0 \le A_k < h, \qquad \text{从而} \qquad 0 \le \alpha_k < 1 .$$

下界由 $A_0=0$、每次只加非负量、且只在 $A\ge h$ 时减 $h$ 保证；上界由退出条件保证。$\alpha_k<1$ 即"只用内插、不用外推"的依据。

### 2.2 单步与状态快照

每个物理步在积分前先把当前状态保存为"上一步"，使内存中始终存在相邻两步的状态：

```cpp
void FixedUpdate(float dt)
{
    prevPosition = position;      // 保存快照：把当前状态记为 s_{i-1}
    prevHeading  = heading;
    Update(dt);                   // 积分：把当前状态推进为 s_i
}
```

调用结束后，$(prevPosition,\ position)=(s_{i-1},\ s_i)$，两端恰好相差一个步长。若把两行的顺序颠倒，则 $s_{i-1}$ 与 $s_i$ 恒等，插值区间长度为零，插值退化为直接返回当前状态，$\alpha$ 失去作用。

`Update()` 本身未作任何改动：物理模型（匀加速与前后向限速）与全部手感参数保持不变，改变的只是它的调用时机与传入的步长。

### 2.3 渲染插值

物理状态只定义在整数步上，渲染需要任意时刻的姿态，因此在相邻两步之间取内插：

```cpp
glm::vec3 RenderPosition(float a) const { return glm::mix(prevPosition, position, a); }
glm::quat RenderHeading (float a) const { return glm::slerp(prevHeading, heading, a); }
glm::vec3 RenderForward (float a) const { return RenderHeading(a) * glm::vec3(0.0f, -1.0f, 0.0f); }
```

即位置取线性内插

$$\mathrm{pos}(\alpha) = (1-\alpha)\,s_{i-1}^{\text{pos}} + \alpha\,s_i^{\text{pos}},$$

姿态取单位四元数的球面线性内插 $\mathrm{slerp}$。对四元数而言，$\mathrm{slerp}$ 等价于对旋转角做线性内插，角速度为常数；若改用线性内插后再归一化，位置正确但角速度不均匀。

## 3. 定理：渲染位移与帧时间成正比

### 3.1 命题

定义**连续步坐标**

$$t_k = S_k - 1 + \alpha_k,$$

其含义是：渲染姿态取在"第 $S_k-1$ 步与第 $S_k$ 步之间、比例为 $\alpha_k$ 处"。例如累计 3 步、$\alpha_k=0.996$ 时 $t_k=2.996$，表示几乎走到第 3 步。

命题：相邻两帧之间

$$t_k - t_{k-1} = \frac{dt_k}{h}.$$

即渲染姿态每帧推进的量只由该帧的真实耗时决定，与该帧内部执行了多少个物理步无关。

### 3.2 证明

需要三条关系，均直接来自 §2.1 的代码：

| 编号 | 关系 | 出处 |
|---|---|---|
| (R1) | $\alpha_k = A_k/h$ | 函数最后一行 |
| (R2) | $A_k = A_{k-1} + dt_k - n_k h$ | 第 1 行与循环内的减法 |
| (R3) | $S_k = S_{k-1} + n_k$ | 循环计数器的累计效果 |

由 $t$ 的定义出发，逐步代入：

$$
\begin{aligned}
t_k &= S_k - 1 + \alpha_k \\
    &= S_k - 1 + \frac{A_k}{h} && \text{由 (R1)} \\
    &= (S_{k-1}+n_k) - 1 + \frac{A_{k-1} + dt_k - n_k h}{h} && \text{由 (R3) 与 (R2)} \\
    &= S_{k-1} + n_k - 1 + \frac{A_{k-1}}{h} + \frac{dt_k}{h} - n_k && \text{除法展开} \\
    &= S_{k-1} - 1 + \frac{A_{k-1}}{h} + \frac{dt_k}{h} && n_k \text{ 项相消} \\
    &= \Big(S_{k-1} - 1 + \alpha_{k-1}\Big) + \frac{dt_k}{h} && \text{由 (R1)} \\
    &= t_{k-1} + \frac{dt_k}{h}. &&
\end{aligned}
$$

证毕。

证明的核心是第六行：$+n_k$ 与 $-n_k$ 相消，于是 $n_k$ 从表达式中消失。步数如何被分配到各帧，不影响渲染姿态的时间推进。

### 3.3 讨论

**(a) 帧率无关。** 60、120、144、240 fps 下均有 $t_k-t_{k-1}=dt_k/h$，故渲染位移严格与帧时间成正比，换算成速度后为同一常数。

**(b) 抖动无关。** 帧时间突变只在 $dt_k$ 中体现，不会产生"某帧推进两步、某帧推进一步"的量化台阶，台阶被 $\alpha$ 的连续变化吸收。

**(c) 内插而非外推。** 由 §2.1 的不变量 $\alpha_k<1$，渲染姿态始终落在 $[s_{i-1},s_i]$ 内部，代价是滞后物理至多一步，即 $h=8.33$ ms（$v=30$ 单位/s 时为 $0.25$ 单位）。

**(d) 输入的帧级量化。** 输入仍按帧采样（`processInput` 每帧读取一次键态），故 60 fps 与 144 fps 下第 $i$ 步看到的 $u_i$ 可能相差至多一帧的按键状态。这是"定步长配合帧采样输入"的固有量化，其误差以帧为界，与渲染平滑无关。

## 4. 反例：余数不保留时的误差

### 4.1 误差表达式

设实现中累加器每帧从零开始（等价于把 `accum` 参数按值传递，见 §6.1）。此时

$$A_k = r_k \equiv dt_k \bmod h, \qquad n_k = \left\lfloor \frac{dt_k}{h} \right\rfloor,$$

记 $r_k \in [0,h)$。代入 $t_k$ 的定义并取差：

$$t_k = S_k - 1 + \frac{r_k}{h}, \qquad t_k - t_{k-1} = n_k + \frac{r_k - r_{k-1}}{h}.$$

而由 §3.2 的结论，正确实现的推进量为

$$t_k - t_{k-1} = \frac{dt_k}{h} = n_k + \frac{r_k}{h}.$$

两者相减，得到错误实现的逐帧偏差

$$e_k = -\frac{r_{k-1}}{h} \in (-1,\ 0].$$

即**每帧少推进"上一帧余数"所对应的时间量**，最大接近整整一步。由于 $r_{k-1}$ 逐帧变化，$e_k$ 也随之摆动，宏观表现是速度不恒定。

### 4.2 数值验证

取 $h=1/120\,\text{s}=8.3333\,\text{ms}$、$v=30$ 单位/s，则单步位移 $vh=0.25$ 单位。以下是同一组帧时间 $dt=(16.0,\ 17.3,\ 16.2)$ ms 下两种实现的逐步结果。

**正确实现**（余数跨帧保留）：

| 帧 $k$ | $A_{k-1}$ (ms) | $dt_k$ (ms) | $n_k$ | $A_k$ (ms) | $\alpha_k$ | $S_k$ | $t_k$ | 渲染位置 | $\Delta$ | $v\,dt_k$ |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 0.000 | 16.0 | 1 | 7.667 | 0.920 | 1 | 0.920 | 0.2300 | — | — |
| 2 | 7.667 | 17.3 | 2 | 8.300 | 0.996 | 3 | 2.996 | 0.7490 | 0.5190 | 0.5190 |
| 3 | 8.300 | 16.2 | 2 | 7.833 | 0.940 | 5 | 4.940 | 1.2350 | 0.4860 | 0.4860 |

三帧的步数分别为 1、2、2，互不相同；而逐帧位移与 $v\,dt_k$ 逐位相符（精确到表中 4 位小数），符合 §3.2 的结论。

**错误实现**（每帧从零开始）：

| 帧 $k$ | $dt_k$ (ms) | $n_k$ | $r_k$ (ms) | $\alpha_k$ | $S_k$ | $t_k$ | 渲染位置 | $\Delta$ | $v\,dt_k$ | $e_k$ |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 16.0 | 1 | 7.667 | 0.920 | 1 | 0.920 | 0.2300 | — | — | — |
| 2 | 17.3 | 2 | 0.633 | 0.076 | 3 | 2.076 | 0.5190 | 0.2890 | 0.5190 | $-44\%$ |
| 3 | 16.2 | 1 | 7.867 | 0.944 | 4 | 3.944 | 0.9860 | 0.4670 | 0.4860 | $-4\%$ |

第 2 帧：正确实现中 $t$ 从 $0.920$ 增至 $2.996$，推进 $2.076$ 步；错误实现中 $t$ 只增至 $2.076$，推进 $1.156$ 步，位移为应得值的 $56\%$。用 §4.1 的表达式核对：$r_1=7.6667$，$e_2=-r_1/h=-0.920$ 步，故推进量 $2.076-0.920=1.156$ 步，与表中一致。

另可注意 $\alpha_k$ 的表现：正确实现中它稳定在 $0.9$ 以上，错误实现中在 $0.920,\ 0.076,\ 0.944$ 之间大幅摆动。$\alpha$ 的摆动本身就是余数丢失的特征。

## 5. 实现

### 5.1 主循环

```cpp
float physAccum = 0.0f;                       // 必须在主循环之外，否则余数每帧丢失
while (!glfwWindowShouldClose(window))
{
    ...
    processInput(window);                                     // 输入按帧采样
    float alpha = 0.0f;
    ship.AdvanceFixed(physAccum, deltaTime, alpha);           // 推进物理，得到 alpha
    const glm::mat4 shipModel = ship.GetModelMatrix(alpha);   // 本帧唯一的飞船姿态
    ...
}
```

`GetModelMatrix(float a)` 与无参版本的区别仅在于姿态取值：前者用 $\mathrm{pos}(\alpha)$ 与 $R(\alpha)$，后者用当前物理状态 $s_i$。矩阵构造公式完全相同：

```cpp
glm::mat4 GetModelMatrix(float a) const
{
    glm::mat4 m = glm::mat4(1.0f);
    m = glm::translate(m, RenderPosition(a));       // 平移量取插值位置
    m = m * glm::mat4_cast(RenderHeading(a));       // 旋转取插值姿态
    m = glm::scale(m, glm::vec3(0.0005f));          // 缩放常数，须与 shipBoundR 一致
    return m;
}
```

后者所依据的关系是：`shipBoundR` 在 `SpaceShip22.A.cpp:221` 由 `shipBoundR *= 0.0005f` 得到，与此处的 $0.0005$ 必须是同一常数，否则阴影分面剔除的中心与阴影实际位置不一致。

### 5.2 一致性要求

**同一渲染帧内，飞船姿态只计算一次，其余各处一律复用。** 需要用到该姿态的位置及其后果如下：

| 位置 | 行号 | 若改用非插值姿态的后果 |
|---|---|---|
| 相机跟随：机头方向 | 390 | 镜头随物理步逐格跳动 |
| 相机跟随：目标点 | 392 | 相机被物理步的量化台阶牵动 |
| 相机跟随：视线方向 | 399 | 飞船相对背景游移（此处在第三人称视角下最易被察觉） |
| 阴影 pass 模型矩阵 | 472 | 影子相对船体滑开 |
| 阴影分面剔除中心 | 475 | 船位于立方体深度图分面边界附近时阴影闪断 |
| 前向 PBR 模型矩阵与法线矩阵 | 813 / 817 | 法线矩阵与几何错位，高光跳动 |

其共同原因是：帧内不允许出现第二个"飞船在哪、朝哪"的答案。

## 6. 三处必须注意的实现细节

### 6.1 累加器必须传引用

```cpp
int AdvanceFixed(float accum, float frameDt, float& alpha)   // 缺少 &
```

按值传递时函数内修改的是副本，调用方的 `physAccum` 恒为 $0$，每帧余数被丢弃。后果即 §4.1 的误差表达式与 §4.2 的数值表。附带症状：物理平均步频低于 $120$ Hz（时间被舍弃），且若加运行时探针，"累加器剩余"一栏恒为 $0.000$ ms。

### 6.2 循环条件用 `>=`

$$A \ge h \quad\text{而非}\quad A > h .$$

在余数跨帧保留的前提下，两者的差别仅在于把某一步推迟一个极小量；但使用 `>` 时退出条件变为 $A \le h$，$\alpha_k<1$ 的严格性不再成立（§2.1 的不变量）。统一使用 `>=`。

### 6.3 快照顺序

见 §2.2：`prev = cur` 必须在积分之前。写反则插值区间长度为零，插值静默失效，且不产生任何编译或运行错误。

## 7. 参数选取

| 参数 | 取值 | 依据 |
|---|---|---|
| $h$ | $1/120$ s | 物理为解析积分，增加步数不增加可观开销；144 fps 下每帧约 $1.2$ 步，插值占比适中。取 $1/60$ 亦可，此时 240 fps 下每帧 $0.25$ 步，由插值承担更多 |
| $M$ | $0.25$ s | 单帧补算上限为 $M/h=30$ 步。其作用是阻断补算的正反馈：若某帧停顿 $3$ s，不设上限时下一帧需补算 $3/h=360$ 步，这些步本身又延长该帧，逐帧放大（螺旋死亡）。设上限后物理相对墙钟至多落后 $M$，但不会追帧 |

边界情形：

- **帧时间小于 $h$**（如 240 fps，$dt_k=h/2$）：多数帧 $n_k=0$，$\alpha$ 在同一对快照之间连续增大，渲染仍然平滑；
- **首帧**：`lastFrame` 初值为 $0$，首帧 $dt$ 等于整个初始化耗时（数秒），被 $M$ 截断为 $0.25$ s；此时速度仍为 $0$，实际位移为 $0$，因此不会出现开局窜出的现象；
- **长时间运行**：`float` 累加器存在舍入误差，量级约 $10^{-7}$，小时级运行无感知；如需完全消除可将 `physAccum` 换为 `double`。

## 附录 B：22.0 与 22.A 的差别

两个入口文件的全部差异分为两类：

| 方面 | `SpaceShip22.0.cpp` | `SpaceShip22.A.cpp` |
|---|---|---|
| 累加器实现 | 内联于主循环，`MAX_ACCUM` 亦定义于主循环 | 调用 `Spaceship::AdvanceFixed`，常量收归类内，实现只有一处 |
| 启动自测 | 无 | `main` 第一行执行 `phys_test::Run()` |
| 渲染路径 | 相同 | 相同 |

因此 `22.A` 是 `22.0` 的功能超集：渲染一致，多出启动回归，且消除了一处重复实现。新版本应由它顺延：复制文件后修改门控两行（文件头的 `//#ifdef` 与文件末尾的 `//#endif`，两者必须同时修改，否则无法编译），并保留自测接入的两行。两个门控不可同时打开，否则将出现两个 `main` 函数。
