# 时间抗锯齿（TAA）失败记录与方向性复盘

> 对象：`src/SpaceShip26.0.cpp`（及 `src/TAA.h`、`res/shader/00_SpaceShip/TAA/` 下五个着色器）。
> 结果：该版本废弃，画面回退到 TAA 之前的形态（`SpaceShip27.0.cpp` 继承 `25.0`）。
> 本文记录：目标与实测差距、方向性错误的根源、实施中踩到的坑、以及"若还要碰时间维"的前置条件。
> 与 `尘埃星环_TAA时间累积的失败尝试记录.md` 配套：那篇记的是叠加层进时间累积的三轮尝试，本篇记的是 TAA 本身。

---

## 0. 结论

发起这项工作的目标是**压掉画面里"小光点随相机移动闪"的混叠闪烁**。实测结果是闪烁没被压掉，反而多出三样：整体变糊、面状沸腾（旧内容在动）、鬼影（火星的像投在星带上、背景透到物体上）。净效果比不做更差。

定性结论三条：

1. **方向搞错了。** 被抱怨的"闪烁"主要不是"边缘不够平滑"，而是**每像素每帧只有一个样本**造成的混叠。时间累积能救它的前提是"内容在屏幕空间近似静止且重投影精确"；本工程相机几乎一直在动，前提不成立，于是时间累积把这个问题的形态从"点"放大成"面"，同时用"糊"与"鬼影"换掉了它原本想买到的那点收益。
2. **计划书的设计选择本身有七处偏差**（§4），其中"用深度反投影当主重投影"与"全屏一个全局混合权重"两处直接决定了后续每一类症状。
3. **最根本的一条与 TAA 无关：没有判据。** 计划书 §10 定义了四类量化判据，实施过程中一次都没跑过，全程以肉眼看与用户报现象为准。没有客观刹车，任何"再重一点"的调整都不会被立即否决，工作点因此一路挪到最糊的角落（历史权重 0.1、锐化 0.40）。这一条是"越调越重"的直接原因。

处置：**不做逐处摘除，直接版本回退**。`SpaceShip27.0.cpp` 由 `25.0` 整份继承，`26.0` 恢复休眠留档，`TAA.h`、五个 TAA 着色器、`Globals.h` 的 `gTaa` 与那几张历史/速度/上一帧深度资源随之一并留档。

## 1. 目标与实测的逐项对照

| 预期收益 | 实测 | 判定 |
|---|---|---|
| 几何边缘被时间维的亚像素样本抹平 | 静止与慢速下看得出来；运动下被"糊"盖过 | 收益存在但很小 |
| 顺带把 SSAO 与高光的噪声收敛掉（曾据此删掉 SSAO 的 4×4 盒式模糊） | 静止时成立；运动时有效样本数下降，噪声以面状形态回潮 | 收益不稳定 |
| 画面更"稳" | 多出面状沸腾；轮廓处仍有闪烁 | 反向 |
| 代价预计只是"轻微发软"、少量鬼影 | 运动方向上的细节被整体抹平（§3.2 给出定量），鬼影可达"半个火星" | 代价被严重低估 |

对照的另一侧：TAA 之前的状态是"小光点随相机移动闪"；TAA 之后该现象仍在（低对比区域的钳制与轮廓处判据都在逐帧丢历史），并且叠加了面状沸腾与鬼影。**结论是净负，不是"没调好"。**

## 2. 方向性错误的根源：闪烁不等于抗锯齿不足

屏幕空间里，一个像素一帧只有一个样本，样本位置由当时的光栅化决定。设屏幕空间频率为 $k$（单位 rad/px），一个像素的采样对应 Nyquist 频率

$$k_N = \pi \ \text{rad/px}$$

（依据：采样间隔为一个像素，Nyquist 角频率为 $\pi$ 除以采样间隔。）

投影尺度接近或超过一个像素的特征（细几何轮廓、亚像素高光、高频法线/粗糙度）其 $k$ 逼近或超过 $k_N$，在任何单帧里都被混叠，表现为随相机移动而跳变的亮暗点。**这是采样不足，不是"边缘不平滑"**；两者需要的手段不同：

- 边缘不平滑，用增加覆盖率样本的手段解决（MSAA、超采样）；
- 采样不足造成的闪烁，需要的是**提高采样密度**（空间超采样）或**让高频内容不再高频**（预滤波）。

时间累积属于第三条路：在投影矩阵里加亚像素抖动，使同一像素在不同帧覆盖不同的亚像素位置，再靠历史把这些样本平均起来。它的立论成立需要两个前提：

1. 该特征在**屏幕空间**近似静止（否则历史对应的是别处的像素）；
2. 历史复用是**精确**的（否则每帧的搬动本身就在重采样）。

本工程的用法把两条都破坏了：

- 相机几乎一直在动，特征每帧在屏幕上平移 $\delta$ 像素，重投影只能把历史"搬"到新位置，而搬动是一次重采样，高频内容在搬动中被低通（§3.2 定量）；
- 判据一旦判定"历史失效"（越界、去遮挡、天空与几何类别不一致），该像素那一帧退回**单次抖动采样**。这个退回是逐帧随机的，比不做更刺眼 —— 这正是"点状闪"反复出现的原因。

由此得到本项工作最重要的一条认知：**先分清"边缘不平滑"与"每像素一个样本"，再决定上什么手段。** 本工程长期抱怨的"小光点随移动闪"属于后者。

## 3. 时间累积的数学模型

### 3.1 递推式与有效样本数

设第 $n$ 帧的累积结果为 $I_n$，本帧渲染结果为 $C_n$，当前帧权重 $w \in (0, 1]$。解算器的输出是

$$I_n = (1-w)\,I_{n-1} + w\,C_n \tag{1}$$

依据：解算着色器的最后一行是 `mix(hist, cur, uWeight)`，其中 `hist` 是上一帧结果经重投影采样后的值；在"内容不变且重投影精确"的近似下 $\text{hist} = I_{n-1}$。

取 $C_n \equiv C$ 为常数。将 (1) 两边同减 $C$：

$$I_n - C = (1-w)\,(I_{n-1} - C) \tag{2}$$

依据：由 (1) 得 $I_n - C = (1-w)I_{n-1} + wC - C = (1-w)I_{n-1} - (1-w)C = (1-w)(I_{n-1} - C)$。

对 (2) 递推 $n$ 次：

$$I_n = C + (1-w)^n (I_0 - C) \tag{3}$$

依据：(2) 每一步都乘同一个因子 $(1-w)$，共 $n$ 步。

由此得到三个可直接读数的量：

- 有效样本数 $N_{\text{eff}} = 1/w$。依据：等比级数 $\sum_{k\ge 0}(1-w)^k = 1/w$，即历史对输出的等效权重相当于这么多个样本的平均。
- 半衰期 $n_{1/2} = \ln 0.5 / \ln(1-w)$。依据：令 (3) 中的残差因子 $(1-w)^n = 0.5$ 后取对数。
- 收敛到 1% 所需帧数 $n_{1\%} = \ln 0.01 / \ln(1-w)$。

数值：$w = 0.1$ 时 $N_{\text{eff}} = 19$，$n_{1/2} = 6.58$ 帧（60 fps 下约 0.11 s），$n_{1\%} = 43.7$ 帧（约 0.73 s）；$w = 0.25$ 时 $N_{\text{eff}} = 4$，$n_{1/2} = 2.41$ 帧，$n_{1\%} = 16.0$ 帧（约 0.27 s）。

**读法**：$w = 0.1$ 意味着**输出里九成是旧内容**。这不是"借一点历史来压噪"，而是"画面以历史为主、本帧为辅"。糊、面状沸腾、长鬼影三者的严重程度都由这个占比直接给出；把它调到 0.25 才勉强算"本帧为主、历史为辅"。

### 3.2 运动方向上的低通：糊与"面"的定量来源

把"相机在动"简化成"每帧历史相对当前画面整体平移 $\delta$ 像素"，用平移算子 $S_\delta$ 表示重投影采样：

$$H_n = S_\delta I_{n-1}, \qquad I_n = (1-w) H_n + wC \tag{4}$$

依据：重投影就是"按上一帧的 VP 把点投到上一帧屏幕、按本帧的 VP 从当前屏幕反算世界点"，在"纯平移、无遮挡变化"的近似下，对历史的作用就是一个整体平移。

取单个空间频率 $k$ 的分量，$S_\delta$ 的特征值为 $e^{-ik\delta}$。令稳态 $\hat I_n = \hat I_{n-1} = \hat I$，对 (4) 做傅里叶变换：

$$\hat I \left(1 - (1-w)e^{-ik\delta}\right) = w\hat C \tag{5}$$

依据：$\hat H = e^{-ik\delta}\hat I$，代入 (4) 的变换并把含 $\hat I$ 的项合并。

于是稳态幅频响应

$$\left| \frac{\hat I}{\hat C} \right| = \frac{w}{\sqrt{1 - 2(1-w)\cos(k\delta) + (1-w)^2}} \tag{6}$$

依据：$|1 - (1-w)e^{-ik\delta}|^2 = 1 - 2(1-w)\cos(k\delta) + (1-w)^2$，由 $|a-b|^2 = a^2 + b^2 - 2ab\cos\theta$。

$k = 0$ 时 (6) 取值为 1：依据是 $\cos 0 = 1$，分母化为 $|1 - (1-w)| = w$，直流分量不被衰减。

半增益频率由 $|\hat I / \hat C| = 1/2$ 解出：

$$\cos(k_{1/2}\delta) = \frac{1 + (1-w)^2 - 4w^2}{2(1-w)} \tag{7}$$

依据：令 (6) 的分母等于 $2w$（即 $w/\text{分母} = 1/2$），两边平方后移项。

取每帧位移 $\delta = 0.5$ 像素（抖动幅度量级）：

| $w$ | $\cos(k_{1/2}\delta)$ | $k_{1/2}$ (rad/px) | 半增益周期 $\lambda_{1/2} = 2\pi/k_{1/2}$ (px) |
|---|---|---|---|
| 0.10（本次工作点） | 0.98333 | 0.3654 | 17.2 |
| 0.25（唯一次调轻后） | 0.87500 | 1.0107 | 6.2 |

**读法**：$w = 0.1$ 时，运动方向上**周期粗于 17 像素的细节已经被削掉一半以上**。这不是"轻微发软"，而是把沿运动方向的细节整体抹平 —— 这正是锐度肉眼可见下滑的来源。把 $w$ 提到 0.25 可以把这条线收到 6.2 像素，代价是降噪能力同比下降（$N_{\text{eff}}$ 由 19 降到 4）。**"要么糊要么噪"这个二选一，就是 (6) 与 $N_{\text{eff}} = 1/w$ 的数学表述**，而全屏只有一个 $w$ 意味着无法对不同的像素各取所需。

### 3.3 为什么症状是"面"而不是"点"

历史在混合之前先被拉进"当前帧 $3\times3$ 邻域"的统计区间里（variance clipping），计划书 §5.3 自己写明这是**有意引入的偏置**。该区间的上下沿由邻域统计量逐帧给出：

- 运动时邻域内容在变，区间上下沿随之逐帧移动；
- 落在区间内的历史原样保留，超出的被拉到边界，而边界本身在动。

于是**整片低对比区域一起呼吸**，表现为"面"。这是推断而非实测：实测只确认了"面状沸腾"这一现象，把它的成因归到钳制边界移动属于机制推断，成色低于 §3.1、§3.2 的量化部分。

同时钳制是非对称的：亮侧取 $\max(m_1 + \gamma\sigma,\ c_{\max})$（邻域最大值兜底，几乎不钳制），暗侧只取 $m_1 - \gamma\sigma$（钳得紧）。这个不对称是为了救"孤立高光被整块夹掉"补上的，它把"高光点闪"换成了"暗侧被压出的面"。

## 4. 计划书层面的七处方向性偏差

### 4.1 主重投影用深度反投影，而不是全屏运动矢量

当时理由：全场景只有舰体会动，为它写满屏速度缓冲不划算。
代价：天空没有可比深度，只能单开一条"按朝向重投影"的支路，而那条支路**没有、也无法有**"这块内容是否属于本像素"的判据 —— 相机一转，火星刚腾出的那圈像素重投影落回"上一帧火星所占的纹素"，历史里存的正是火星的颜色，于是"半透明火星圆弧投在星带上"。这个缺口只能靠临时特殊判据去堵，而特殊判据在"严"与"松"之间反复（§5.4、§5.5）。几何侧的判据同样只能比"距离"，对陡坡与轮廓处一个纹素的偏移极其敏感。

### 4.2 全屏一个全局混合权重

代价见 §3.2：无法"该重的地方重、该轻的地方轻"。这是朴素版 TAA 最本质的标志。

### 4.3 钳制在 RGB 三通道上各自硬夹

三个通道独立夹会改变色相（在 YCoCg 或"对数亮度 + 色度"空间做才保持色相），并且如 §3.3 所述带来面状呼吸。

### 4.4 当前帧不做空间预滤波

历史一失效就裸出单次抖动采样，那一帧该像素没有任何抗锯齿 —— "点"照旧。

### 4.5 用事后高通（反锐化）补糊

补糊的同时把残余的时间噪声一起放大；而且它作用在写回最终画面那一步，历史里存的却是未锐化的版本 —— **显示的不是被累积的东西**，任何时间残留都被放大到显示端。$w = 0.1$ 造成的糊需要 0.40 的锐化去补，两者是一对互相掩盖的错误。

### 4.6 叠加层没有速度也没有排除机制

尘埃星环与折跃各层既没有速度也不能被排除在历史之外，进历史即拖影。推导与三轮尝试见 `尘埃星环_TAA时间累积的失败尝试记录.md`。

### 4.7 抖动序列只有 8 帧

Halton(2,3) 取 8 项，静止画面下累积结果以 8 帧为周期重复；序列偏短会把该周期暴露成可见的低频图案。正规实现取 16 至 32 项。

### 4.8 单独一条：没有判据

计划书 §10 定义了收敛度 $D_n$、噪声/尖峰计数、鬼影半衰期、SSAA 真值四类量化判据，实施过程中**一次都没跑过**。全程以肉眼看与用户报现象为准，于是工作点一路挪到最糊的角落。这一条与 TAA 本身无关，是本项目在时间维上的主要教训：**没有量化判据的时间滤波不许开工。**

## 5. 实施过程中踩到的坑

### 5.1 速度缓冲被清成"处处有速度"

现象：小行星带里"照出"了舰船 —— 舰体的像被粘在背景上。
机制：用 `glClear(GL_COLOR_BUFFER_BIT)` 清速度纹理，而本工程的清屏色是 `glClearColor(0.1f, 0.1f, 0.1f, 1.0f)`，**alpha 为 1**，于是整屏 $a = 1$。解算器以 $a > 0.5$ 作为"这个像素有速度可用"的标志，遂认为处处有速度，`uvPrev` 退化成当前像素自身，等于完全不重投影：每个像素保留自己的历史，上一帧画过舰体的像素把舰体一直留在屏幕上。
处置：改用 `glClearBufferfv(GL_COLOR, 0, values)` —— 它显式给值、只作用于指定附件、不碰深度附件，也不看 `glClearColor`。

### 5.2 把"上一帧距离"存在历史颜色的 alpha 里

现象：静止画面出现高频抖动，尤其小物体与轮廓一带。
机制：历史颜色纹理被双线性过滤，天空哨兵值 0 与物体的真实距离在交界处插值出中间值，与真实距离相差很大，被去遮挡判据误判成"新露出"，历史被丢。
处置：上一帧深度单独一张 `GL_DEPTH_COMPONENT24` + `GL_NEAREST` 纹理，与颜色完全分开。这一点计划书 §9 批次 3 本来就写明了，第一次实现时没照做。

### 5.3 `prevCamPos` 只在读取处出现、从未归档

现象：抖动在修好 5.2 之后反而更重。
机制：判据比较的两个距离里，一个来自当前帧反算的世界点到"上一帧相机"的距离，而"上一帧相机位置"从未被写入，读到的是初值（世界原点附近），于是几乎所有像素都被判为不一致，历史被大面积丢弃。
处置：帧末补归档 `gTaa.prevCamPos = camera.Position;`。

### 5.4 天空支路完全没有判据

现象：相机转动经过火星时，一片"半透明火星圆弧"投在小行星带的背景上，约 0.3 s 才淡掉（$w = 0.1$ 时残差按 $(1-w)^n$ 衰减，20 帧剩 12%）。
机制：见 §4.1。
处置与反复：先加**单纹素**判据（`d >= 1.0` 且重投影落点深度 $< 1$ 则丢历史），圆弧消失；随后为压"轮廓处误丢历史"改成 **3×3 邻域**判据（邻域里只要有一个纹素是天空就放行），放行条件变宽，陈旧历史在大片区域内存活，症状由"点"变"面"。**同一处判据在严与松之间来回，本身就是"没有判据"的症状。**

### 5.5 几何侧判据只看一个纹素

现象：随相机移动时不时颤一下。
机制：轮廓与陡坡处，重投影落点常常压在相邻纹素上（那是另一个表面，或同一表面的另一侧），算出的距离必然超阈值，合法历史被丢，那一帧该像素退回单次抖动采样。
处置：改 3×3 邻域（任一纹素与当前表面同源即承认历史）。此改消掉了点状闪，但如上条所述引入面状问题 —— 即"点"与"面"是同一处判据的两个端点，中间没有客观判据可选点。

### 5.6 GLSL 的 `const` 要求编译期常量

现象：着色器编译报 `C1059: non constant expression in initialization`，指向 `const float tol = max(0.05 * prevCamDist, 2.0);`。
机制：`prevCamDist` 是逐片元计算出来的量，不是编译期常量，GLSL 不允许用它初始化 `const` 变量。
处置：去掉 `const`。

### 5.7 UTF-8 BOM 丢失（血的代价）

现象：改完不报错，一编译就是一大片"未声明的标识符 / 必须初始化 const 对象 / 语法错误"，报的行离肇事注释很远。
机制：`SpaceShip26.0.cpp` 是 UTF-8 **带 BOM**。BOM 丢失后 MSVC 按系统 ANSI 代码页（cp936）解码其中的 UTF-8 中文注释，三字节汉字被拆成 GBK 对之后留下**悬空的引导字节并吞掉行尾换行**（`0x0A` 不是合法的 GBK 尾字节，不需要出现 `0x5C` 也会发生）。
处置：改完必查前三字节是否为 `EF BB BF`；排查顺序**先查 BOM，再查括号**（本次先查了括号与 `main` 入口，白绕两轮）。

### 5.8 `JITTER_PX` 是死常量

现象：无任何报错，但改这个常量对画面没有任何影响。
机制：`jitter(i)` 返回 `vec2(radicalInverse(n, 2) - 0.5f, radicalInverse(n, 3) - 0.5f)`，值域 $[-0.5, 0.5)$ 像素，幅度被硬编码成 $\pm 0.5$ 像素，**没有乘 `JITTER_PX`**。
处置：补上乘法 `(radicalInverse(n, b) - 0.5f) * (2.0f * JITTER_PX)`（该改动随 `26.0` 休眠）。

### 5.9 门控宏撞名

现象：无（当时恰好不发作）。
机制：`26.0` 由 `25.0` 整份复制，门控宏 `SHIP_25_0` 一并带了过来。该宏全项目无定义，所以只有 `26.0` 参与编译，功能上恰好正确；但一旦有人定义它，两份会同时编译出两个 `main`（LNK2005 / LNK1169）。
处置：`26.0` 休眠时订正为 `SHIP_26_0`，`27.0` 使用 `SHIP_27_0`。

### 5.10 帧内相机位置与归档的相机位置不一致

现象：未观测（推断存在）。
机制：折跃抖动把位移加进 `camera.Position` 生成 `view`，随后又减回去；解算用的 `uCamPos` 与归档的 `prevCamPos` 都取减回去之后的值，于是折跃那几帧的重投影与距离判据整体差一个 `camShake`。
处置：已定位未修，随 `26.0` 一并休眠。

## 6. 若以后还要碰时间维：前置条件

以下六条按重要性排列，任一不满足都不建议开工。

1. **先建判据再调参。** 至少要有：收敛度（静止画面在 $n$ 帧后的残差 $D_n$ 应满足 $(1-w)^n$ 的理论值）、噪声/尖峰计数、鬼影半衰期、超采样真值对照。没有量化判据的时间滤波不许开工。
2. **重投影用全屏运动矢量**：每个写颜色的 pass 都写速度，天空、叠加层、透明层同样写；深度只当校验，不当主来源。
3. **混合权重逐像素给**（由历史有效性与局部方差决定），不要全屏一个常数。
4. **钳制在 YCoCg 或"对数亮度 + 色度"空间做**，并且用软钳制（向区间中心混合）而不是硬夹。
5. **当前帧先做空间预滤波**，历史失效时输出滤波结果而不是单次采样。
6. **不要用锐化补糊**；要补就提高权重或加长抖动序列。抖动序列不少于 16 帧。

## 7. 去路（本次实际采用）

- **版本回退**：`SpaceShip27.0.cpp` 由 `25.0` 整份继承（TAA 之前的形态），`26.0` 恢复休眠留档；`src/TAA.h`、`res/shader/00_SpaceShip/TAA/` 下五个着色器、`Globals.h` 的 `gTaa` 与历史/速度/上一帧深度三组资源随 `26.0` 一并留档。不做逐处摘除 —— 版本管理就是为了这一步。
- **抗锯齿的候选方向**（本次未实施，按对本工程的适配度排列）：
  - **SSAA（离屏渲染尺寸放大，最终合成时降采样）**：对本工程最坏的情形（星带里成片的亚像素高对比轮廓）天然正确，且不会鬼影、不会沸腾、不需要历史与速度缓冲。代价是填充率按线性倍数的平方增长。
  - **SMAA**：对合成图做形态学后处理，几乎不花时间、无时间维缺陷；但对亚像素尺度的小物体基本无能为力，也不给 SSAO 与体积光噪声降噪。
  - **MSAA**：本工程曾经启用，因延迟着色（星带在 G-Buffer 里）而舍弃。要恢复需做 MSAA G-Buffer 与逐样本解析，且它不解决任何着色噪声。
- **取向修正**：先分清"边缘不平滑"与"每像素一个样本"这两件事。前者是抗锯齿问题，后者是采样问题；本工程长期抱怨的"小光点随移动闪"属于后者，用空间超采样解决比用时间累积直接、可靠。
