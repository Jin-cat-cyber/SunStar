> 适用版本：活跃文件 `OpenGL_Learning/src/SpaceShip24.0.cpp`，时间线 `src/WarpSC.h`（`namespace warp_sc`），
> 舰体着色器 `res/shader/00_SpaceShip/Forward_Shading/WarpSC/spaceship_{ver,frag}4.0.shader`。

## 0. 本文的定位与工作方式

本文是 SC 风格折跃的**管线计划**：把《星际争霸2折跃_逐帧观察.md》里逐帧读出来的动作，映射成这台渲染器
上可实现的 pass 与门控。公式与实现推导的完整版写在原版分支的《战列巡航舰折跃_设计与实现计划书.md》
（下称"原版计划书"）里，本文只写 SC 分支特有的部分，不重复。

推进方式：**按批次实施，每批次做完由人目视验收并给反馈**；批次的划分依据是"这一批能独立看出来"，
不是"这一批代码量相同"。**所有观感参数（数值）都不在批次内定死**，一律取一个能跑起来的占位值，
最后统一在 §7 的参数表上逐项调。判据是"管线的结构对不对"（顺序、门控、方向、接缝），不是"好不好看"。

三类读者要分清的三份文档：

| 文档 | 内容 |
|---|---|
| `星际争霸2折跃_逐帧观察.md` | 事实依据：SC2 的原片段逐帧读出来的动作序列 |
| `战列巡航舰折跃_设计与实现计划书.md` | 原版分支的公式、命题与实现（SC 分支沿用其推导） |
| 本文 | SC 分支的管线结构、批次划分、验收判据、参数清单 |

## 1. 目标形态：把逐帧观察写成阶段表

### 1.1 唯一时钟与四段

一切由唯一时钟 $\tau$（自按下 T 键起算的秒数）驱动，四段标称时长与原版一致：

| 段 | 区间（秒） | SC2 里对应的动作 |
|---|---|---|
| 蓄能 | $[0.00,\ 0.90)$ | 电弧在舰体各处闪起，青色能量壳成形（带多边形网格） |
| 隐没 | $[0.90,\ 1.10)$ | 扫描前沿扫过，舰体块状剥散；轴向拉长 + 横向收缩"被抽走"；$\tau^\ast$ 处闪现达峰并传送 |
| 线框 | $[1.10,\ 1.80)$ | 落点：半透明骨架自艉向艏长出（舰体本体此时完全不可见） |
| 实体化 | $[1.80,\ 2.05)$ | 材质自艉向艏补齐（块状）、拉伸收回、几何从"逻辑面"滑入骨架 |

$\tau^\ast = T_{\text{CHARGE}} + T_{\text{VANISH}} = 1.10$ 是传送时刻，也是闪现通道的峰值时刻；
$T_{\text{WIRE\_END}} = 1.80$ 是实体化起点；$T_{\text{TOTAL}} = 2.05$ 是时钟终点。

### 1.2 三条硬约束（工程侧，不可协商）

1. **相机不随舰体走**：跟随模式（`MODE_FOLLOW`）下相机与舰体在 $\tau^\ast$ 平移同一个向量，
   所以全屏闪现只需遮住 $\tau^\ast$ 一帧（原版计划书命题 2）。模式 1/2 的相机是玩家自己的，
   所有"相机侧"效果由 `camGate` 门控。
2. **落点严格串行**：SC2 的落点在舰船完全消失之后才出现，绝不与起飞段重叠。这一条决定了
   原版"蓄能期就画目的地蓝图"的做法必须删掉（见 §4.2）。
3. **本工程从未启用面剔除**（`GL_CULL_FACE` 全程未开），且一切加色 pass 都不写深度。
   由此得到一条有用的推论：加色混合满足交换律（$a + b = b + a$），所以外壳、碎屑、幽灵舰体、
   线框这几个 pass 的**绘制顺序不影响结果**，只要它们都排在 PBR 舰体之后且都不写深度。
   不要为它们做深度排序 —— 那会引入一套本工程没有的机制。

## 2. 现有实现与 SC2 要求的对照

原版五通道（`warp_sc::sample`）一个都没有删，SC 分支改的是**通道之外的三件事**：前沿的带宽、
生长与强度的相位、以及落点画什么。

| SC2 动作 | 现有实现 | 差在哪 |
|---|---|---|
| 青色能量壳 + 多边形网格 | `warp_shell_*`，菲涅尔 + 物体空间细丝，强度 `uShellStrength = u_c * 2` | 缺"多边形网格"这一层纹理（批次 5） |
| 扫描前沿扫过、块状透明 | `geoFront` / `matFront` 两级前沿 + 4.0 里的块状哈希 `discard` | 带宽 `FRONT_LEAD = 0.06` 太窄、扫描太快（都是参数，见 §7） |
| 轴向拉长 + 横向收缩 | `stretchAmount` / `stretchFactor` + `1.0 / pinch` 缩放 | 已具备 |
| 起飞时喷出方块碎屑 | 无 | 缺（批次 4） |
| 落点在舰船消失后才出现 | 蓄能期就画目的地蓝图（用线框） | 顺序错了，必须删（批次 2） |
| 落点半透明舰体 + 内部可见 | 无（线框段舰体本体全被 discard） | 缺（批次 3） |
| 骨架自艉向艏生长 | `wireGrow` 自艏向艉，且在蓄能期就长满 | 方向与相位都要改（批次 2） |
| 几何从"逻辑面"滑入骨架 | `slideAmount`：去程 $0$ 冲到 $+1$，抵达由 $-1$ 回到 $0$ | 已具备，逻辑面由它自然提供 |
| 材质最后补齐、略滞后 | `geoFront` 在实体化段退回、`matFront` 恒定领先 | 已具备 |

已经做完的一批（批次 1）：新着色器对 + 指向 + 块状抖动透明 + 亮青切口。

## 3. 批次划分与验收判据

每批次的"验收"都是**目视**的：三种相机模式下各按一次 T，看该批次应该改变的那一件事有没有出现，
以及有没有顺带弄坏别的（尤其太阳日冕、影子、其他 pass）。

| 批次 | 内容 | 验收判据（看什么） |
|---|---|---|
| 1 ✔ | 4.0 着色器对、指向、块状抖动透明、切口提亮 | 溶解带内出现硬格子，被扫到处偏青白 |
| 2 ✔ | 删蓄能期蓝图、骨架生长挪到 $\tau^\ast$ 之后、生长方向改艉向艏 | 起飞全程**看不到**落点；$\tau^\ast$ 之后骨架自艉向艏长出；线框亮度全程平滑无闪断 |
| 3 ✔ | 幽灵舰体（落点半透明舰体，加法混合） | 落点先出现半透明舰体轮廓，与骨架同步生长；实体化段淡出，不与材质打架 |
| 4 ✔ | 块状碎屑 | 起飞段舰体附近喷出方块并散去；不写深度、不挡背景、不影响影子 |
| 5 ✔ | 外壳的多边形能量网格 | 壳上读出多边形格；**寿命由 `shellAlpha(tau)` 决定、不再挂 `u_c`**，静止态无残留 |
| 6 进行中 | 参数统一调参 | 逐个走 §7 的表，一次只动一项，改完立刻看（剩余轮次见精读附录） |

批次的依赖关系是线性的，但 3/4/5 之间彼此独立，可以按兴趣换序。
本表的"✔"只表示**结构已落地**；每批次的具体取值、推导与剩余项，以
`星际争霸2折跃（两波模型：半透明波与消失波）_代码精读.md` 末尾附录为准。

## 4. 批次 2：抵达顺序重排（本批次有真正的结构改动）

### 4.1 符号与既有构造

| 符号 | 含义 | 取值 |
|---|---|---|
| $g$ | 轴向坐标，$0$ 在艏、$1$ 在艉 | $g = (\text{ObjPos}.y - \text{uAxisMinY})/(\text{uAxisMaxY} - \text{uAxisMinY})$ |
| $W$ | 噪声幅度 `NOISE_W` | $0.25$ |
| $L$ | `FRONT_LEAD`（材质前沿相对几何前沿的固定领先量） | $0.06$（待调） |
| `FRONT_LO` | 前沿下界 $= -W/2$ | $-0.125$ |
| `FRONT_HI` | 前沿上界 $= 1 + W/2$ | $1.125$ |
| $\sigma$ | `smoothstep01`（$\sigma(0)=0,\sigma(1)=1,\sigma'(0)=\sigma'(1)=0$，C¹） | — |
| $\varphi$ | `quintic01`（$\varphi(0)=0,\varphi(1)=1$，两端一阶二阶导为零，C²） | — |

探测用的带噪坐标是 $g_t = g + W\,(n - 1/2)$，$n$ 是物体空间值噪声，取值域 $[0,1]$，因此
$g_t \in [-W/2,\ 1+W/2]$；镜像坐标 $h = g_t$（去程）或 $h = 1 - g_t$（抵达），值域相同。

### 4.2 命题与推导

**命题 1（带宽恒定，两条前沿同速）** 对任意 $\tau$ 有 $\text{matFront}(\tau) - \text{geoFront}(\tau) = L$。

证明：由 `matFront(tau) = geoFront(tau) + FRONT_LEAD` 直接相减即得。这正是逐帧观察里
"两条前沿同速、间距固定"的实现：间距是常数而不是某个随 $\tau$ 变化的量，所以不可能出现
一条追上另一条的情形。

**命题 2（$\tau^\ast$ 那一帧舰体完全不可见）** $\text{geoFront}(\tau^\ast) = \text{FRONT\_HI}$，
且对一切像素有 $h \le \text{FRONT\_HI}$，故 `discard` 条件 $h < \text{uFrontGeo}$ 几乎处处成立。

证明：$\tau^\ast = T_{\text{CHARGE}} + T_{\text{VANISH}}$，而 `frontRamp` 在 $\tau \ge T_{\text{TAU\_STAR}}$
时返回 $1$，故进度 $r = 1$；代入 `geoFront` 的表达式
$$
\text{geoFront}(\tau^\ast) = (\text{FRONT\_LO} - L) + (\text{FRONT\_HI} - \text{FRONT\_LO} + L)\cdot 1
= \text{FRONT\_HI},
$$
最后一步是把 $(\text{FRONT\_LO} - L)$ 与括号内的 $(\text{FRONT\_HI} - \text{FRONT\_LO} + L)$ 相加，两项中的
$\text{FRONT\_LO}$ 与 $L$ 分别抵消。又由 §4.1，$h$ 的值域上确界是 $1 + W/2 = \text{FRONT\_HI}$，
所以除"噪声恰好取到上界且 $g = 1$"这一零测集之外，$h < \text{uFrontGeo}$ 恒成立，屏幕上看不到舰体。

这一条同时解释了滑入在 $\tau^\ast$ 处翻号（$+1$ 变 $-1$）为什么不可见：翻号发生在**不可见的一帧**上。

**命题 3（块状抖动的期望透光率等于真混合的目标值）** 对固定像素，`discard` 概率为 $\text{stripped}$，
故保留概率的期望等于 $1 - \text{stripped}$。

证明：格点哈希 $d_{th}$ 在 $[0,1)$ 上均匀，判定是 $\text{stripped} > d_{th}$ 时丢弃，于是
$P(\text{丢弃}) = P(d_{th} < \text{stripped}) = \text{stripped}$，$P(\text{保留}) = 1 - \text{stripped}$。
因此"抖散透明"与"真 alpha 混合"在**平均**意义上完全一致，区别只在空间上是离散的、
且在时间上不需要排序。这就是选择 `discard` 而不是开混合的全部理由。

**命题 4（生长位置与强度解耦之后不会有亮度接缝）** 在整个生长区间 $[\tau^\ast,\ T_{\text{WIRE\_END}}-0.05]$
上 `wireAlpha` 恒等于 $1$。

证明：`wireAlpha`$(\tau) = 1 - \sigma\big((\tau - W_{F0})/(W_{F1} - W_{F0})\big)$，而
$W_{F0} = T_{\text{WIRE\_END}} - 0.05$；当 $\tau \le W_{F0}$ 时括号内 $\le 0$，被 `clamp01` 压到 $0$，
$\sigma(0) = 0$，故 `wireAlpha`$(\tau) = 1$。于是生长段内线框亮度不随时间变化，唯一的"接缝来源"
只剩生长门本身，而它是 $\sigma$（C¹），不会跳变。

**命题 5（生长时长的上界）** 若要求生长在实体化开始前完成，且完成后留出纯骨架观察窗口 $\Delta$，
则 $T_{\text{GROW\_SPAN}} \le T_{\text{WIRE}} - \Delta$。

证明：要求 $\tau^\ast + T_{\text{GROW\_SPAN}} \le T_{\text{WIRE\_END}} - \Delta$，把
$\tau^\ast = T_{\text{CHARGE}} + T_{\text{VANISH}}$ 与 $T_{\text{WIRE\_END}} = T_{\text{CHARGE}} + T_{\text{VANISH}} + T_{\text{WIRE}}$
代入，两边同时减去 $T_{\text{CHARGE}} + T_{\text{VANISH}}$ 即得。取 $T_{\text{WIRE}} = 0.70$、$\Delta = 0.20$
得 $T_{\text{GROW\_SPAN}} \le 0.50$，故占位值取 $0.50$（正好用满）。

### 4.3 具体改动（三处）

**(a) 删掉蓄能期目的地蓝图。** 它违反 §1.2 的第 2 条。锚点是 `SpaceShip24.0.cpp` 里
`if (gWarp.active && gWarp.tau < warp_sc::TAU_STAR)` 那个**整块**（含花括号、含块内那句被注释掉的
`warpWireShader.setMat4(...gWarp.delta...)`），连同它上面那段解释蓝图的注释一起换成三行说明：

```cpp
        // ===== 折跃：目的地蓝图（SC 分支已删除）=====
        // SC2 的落点严格排在"舰体完全消失"之后，所以蓄能期不画任何落点几何。
        // 落点的第一件东西是线框骨架，它在 tau* 之后才自艉向艏长出（见 WarpSC.h 的 wireGrow）。
```

删掉之后不再需要 `gWarp.target - ship.RenderPosition(alpha)` 这个平移，其余 pass 不受影响；
`gWarp.target` 仍然被传送那一帧使用，不要顺手删。

**(b) 把生长挪到 $\tau^\ast$ 之后并留出观察窗口。** 锚点是 `WarpSC.h` 里那一行
`inline constexpr float WIRE_GROW_TIME = TAU_STAR;   // = T_CHARGE + T_VANISH`，改成两行常量：

```cpp
    inline constexpr float GROW_SPAN = 0.50f;                  // 骨架生长时长（上界见计划书命题 5）
    inline constexpr float WIRE_GROW_TIME = TAU_STAR + GROW_SPAN;
```

再把 `wireGrow` 的起点从 $0$ 挪到 $\tau^\ast$：

```cpp
    inline float wireGrow(float tau)
    {
        if (tau <= TAU_STAR)         return 0.0f;
        if (tau >= WIRE_GROW_TIME)   return 1.0f;
        return smoothstep01((tau - TAU_STAR) / GROW_SPAN);
    }
```

原先那三个被注释掉的旧版本（线性版、起步快收尾慢版）保持原样不动，它们是留档。
注意 `warp_sc_test` 的 P1 扫的是"可见性不中断"，不涉及 `wireGrow` 的相位，此改动不动自测；
但**启动时仍要确认控制台有 `===== warp_sc self test (P1..P7) =====`**，否则自测静默变成空函数。

**(c) 生长方向改成自艉向艏。** `warp_wire_frag.shader` 里的生长门是
`gate = 1 - smoothstep(uWireGrow - 0.06, uWireGrow, g)`，$g = 0$ 在艏，所以现在是**自艏向艉**生长，
与观察到的抵达顺序相反。因为这份 frag 是两条分支共享的，按项目约定**先复制一份到 SC 分支的目录**
（目录归属见 §8 问题 1），再在副本里把坐标镜像一次：

```glsl
    // SC 分支：落点骨架自艉向艏长出，所以把轴向坐标镜像（g = 0 在艏，镜像后 0 在艉）。
    // 起点不换成 1 - g 的写法，是因为 gate 的语义是"小于前沿的那一侧才画"，
    // 镜像之后"前沿从小变大"仍读作"从艉长向艏"。
    float gRev = 1.0 - g;
    float gate = 1.0 - smoothstep(uWireGrow - 0.06, uWireGrow, gRev);
```

改完之后，`SpaceShip24.0.cpp` 里构造线框程序的那三行的最后一行要指向副本（顶点与几何着色器两份
不含方向逻辑，继续共用共享件）：

```cpp
    Shader warpWireShader("res/shader/00_SpaceShip/Warp/warp_wire_ver.shader",
        "res/shader/00_SpaceShip/WarpSC/warp_wire_frag4.0.shader",
        "res/shader/00_SpaceShip/Warp/warp_wire_geo.shader");
```

目录布局已定（§8 问题 1 选 A）：SC 分支自有或改过的折跃着色器放 `res/shader/00_SpaceShip/WarpSC/`，
与 `Warp/` 平级；不含分支逻辑的那几件（wire 的 ver 与 geo、flash 两件）继续共用 `Warp/` 里的共享件。

## 5. 批次 3 至 5：管线搭建（已实施；本节保留当时的取向记录，实际取值见 §7 与精读）

### 5.1 批次 3：幽灵舰体

要的是"落点先出现一层半透明的舰体轮廓，能看见内部结构，随后透明度降低、材质接上"。
机制上它与线框骨架共享同一根生长前沿：把 `uWireGrow` 与轴范围一起喂给一个新的 frag 即可，
不需要新的时间线量。

- 复用舰体的同一份 mesh（`spaceship.Draw(...)`），与外壳 pass 同一套路：
  开加法混合、`glDepthMask(GL_FALSE)`、深度测试保持开启；
- 颜色取青白（与线框同色系），强度由"生长门 × 一个下降包络"决定，下降段与 `wireAlpha` 的
  下降段对齐，避免两件东西以不同节奏消失；
- 透明度上不做真混合，因此**不需要排序**（§1.2 第 3 条）。

### 5.2 批次 4：块状碎屑

SC2 起飞时喷出的是矩形/圆柱碎片。这一批要把"碎片"做成纯解析的运动：以 $\tau$ 为参数的
位置函数 $p_i(\tau) = p_i(0) + v_i\,\varphi\big((\tau - t_i)/T_{\text{debris}}\big)$，每个碎片一个
固定的随机种子（种子里带上时间线，保证同一趟折跃每次看都一样），生命末期用强度包络淡出。
几何上需要一份便宜的方块网格与一次实例化绘制，可用资源见 §8 问题 6。

### 5.3 批次 5：外壳的多边形能量网格

（本节是取向记录，大部分已按此实施；未落地的部分见段末。）要在壳上读出"多边形网格"，最省的构造是在物体空间里
取三向正交格线：$u = \text{fract}(q\,n)$，三条 $|u_k - 0.5|$ 的最小值给出格线距离，再用
`fwidth` 换算到屏幕空间做抗锯齿（线框 frag 里已经有这套写法可以照抄）。三向正交格在正对
视角处会读成方块，若嫌方，再叠加一组旋转 45° 的格线即可得到三角/六边观感。

**实施结果**：正交组与 45° 组两组格线都写进了 `warp_shell_frag2.0.shader`，由 `uGridMix` 混合；
频率 / 线宽 / 混合 / 强度四个观感参数见 §7。**但上文"用 `fwidth` 换算到屏幕空间做抗锯齿"这句没有实施**：
`lattice()` 用的是物体空间的固定宽度 `smoothstep(0.5 - w, 0.5, c)`，所以相机拉远、格线缩到亚像素时会闪。
补不补属于 C-4 的开放项。

## 6. 已知风险与工程约束

| 风险 | 说明与对策 |
|---|---|
| 删蓝图误伤传送 | 蓝图块里的 `gWarp.target` 只被传送那一帧读，删块时不要删 `WarpState::target` 本身 |
| 线框副本忘记指向 | 副本复制了但 `Shader` 构造仍指共享件，现象是"改了没反应"；反之路径写错会加载失败 |
| 自测静默失效 | 只在 `Debug\|x64` 有 `DEBUG_PHYS`；看不到 `===== ... self test =====` 就是宏没开 |
| 加色 pass 越画越亮 | 三星叠加时亮度会饱和成白，属观感参数（§7），结构上不要靠"关掉某一层"来救 |
| 抖散的零测集 | 命题 2 里 `h = FRONT_HI` 的边界情形不 discard，是零测集；**不要**为了它加 epsilon，也不要给它套 `clamp`（那正是原版计划书 §3.5 踩过的坑） |
| 图层目录混用 | 新着色器必须放在代码里写上去的那个目录，路径不一致会直接加载失败 |

## 7. 参数索引（调参时看这里，别抄数值）

数值**不再抄在本文件里** —— 抄一遍就会随代码漂移（本节初版就是这么过时的）。参数按职责分成三处，
调哪一类就翻哪个文件；每个常量行末都带"现值 + 调大调小的后果"。

| 参数类别 | 文件 | 里面有什么 | 怎么调 |
|---|---|---|---|
| 时间线、几何、幅度（纯数学，不含 glm 也不含 GL） | `src/WarpSC.h` | 四段时长与 `FILL_TIME` / `WIRE_TAIL`、五个通道的梯形边界、两条前沿与 `FRONT_*`、`NOISE_W`、`E_STRETCH` / `PINCH_K`、`STRETCH_*`、`SLIDE_*`（含两个 `K`）、`GROW_SPAN`、`SOLIDIFY_*`、`FOV_KICK` / `SHAKE_*`、`KAPPA_BACK`、`TIME_SCALE` | 靠数字：临时 `printf` 探针 + 自测；改完必须重跑 P1–P7 |
| 碎屑运动学（纯数学） | `src/WarpDebris.h` | `D_COUNT`、出生时刻、寿命、淡入淡出、三轴尺寸、长条倍率、飞出速度、出生范围 | 靠画面（可加一次性探针核对数字） |
| 着色器观感常量（颜色 / 强度 / 频率 / 宽度 / 厚度） | `src/WarpTuning.h` | 二十多个按 pass 分组的 `U_*` / `RIM_*` 常量 | 只靠画面 |

三类之外另有两个**全局量**（`src/Globals.h`）：`WARP_DISTANCE` / `WARP_COOLDOWN` / `WARP_MIN_DIST`
（折跃距离、冷却、落点否决门限）。

**规矩：调参只动这三份文件里的常量**，不要在 cpp 里塞新字面量（`WarpTuning.h` 就是为这件事建的）。

几条容易踩的耦合，动手前先看一眼：

- `FRONT_LEAD` 同时决定去程带宽与抵达重建带的宽度；`FRONT_GEO_START` 只决定去程扫描时长。
- `SLIDE_DEPART_K` 与落点合法性余量是**一对**：前冲量放大多少，余量里的
  `SLIDE_DEPART_K * gShipBowOffset` 就跟着多少（见 `SpaceShip24.0.cpp` 的落点合法性段）。
- `FILL_TIME` / `T_APPEAR` 一改，`STRETCH_HOLD_EXT = T_APPEAR - STRETCH_FALL` 会自动让"保持 + 收回"
  用满实体化段，通道表的 `W_F0` / `W_F1` 也是相对它们写的。
- 拉伸峰值必须落在**可见窗口**里（舰体在骨架段被整段剔除），否则那段时间白做。
- 通道梯形必须满足 `r1 <= f0`，否则峰值到不了 1 而且不报错（自测 P2 守这条）。
- 加色通道的可用阈值远低于直觉：线性值要按 gamma 折算再定（`0.01` 仍可见，见精读第 6 段）。

本轮已定的取值、推导与截图对照，见 `星际争霸2折跃（两波模型：半透明波与消失波）_代码精读.md`；
它末尾的附录列了截至当前**所有已完成项与剩余轮次**。

   （即 `GROW_SPAN = 0.50`，正好用满命题 5 的上界）。

### 8.2 已结（原来的「待定」五项，全部定案）

- **镜头冲击**：**保留** `FOV_KICK` 与 `SHAKE_AMT`，**白闪也保留**。SC2 里相机是静止的、完全没有这两样，
  这是有意偏离参考画面：跟随视角下若没有镜头语言，折跃会读成"画面切了一下"。
- **起飞段的扫描方向**：定为**艏先消失**（`geoFront` 升、不加镜像）；SC2 逐帧记录未给出反证。
  若要反过来，把 `uFrontRev` 的切换时机挪到起飞段即可，不涉及结构改动。
- **幽灵舰体是否新增 pass**：新增独立加色 pass（`warp_ghost_ver` / `warp_ghost_frag`），
  与骨架共享生长前沿，强度用单调的 `1 - solidify(tau)`，得到半透明轮廓 + 内部可见。
- **碎屑的方块几何从哪来**：不走点光源阴影的立方体、也不借小行星网格，`WarpDebris.cpp`
  内建一份 1×1×1 立方体（VAO/VBO + 实例缓冲，一次实例化绘制）。
- **壳的网格类型**：物体空间两组格线（正交组 + 旋转 45° 组）按 `uGridMix` 混合；
  四个观感参数见 §7。
