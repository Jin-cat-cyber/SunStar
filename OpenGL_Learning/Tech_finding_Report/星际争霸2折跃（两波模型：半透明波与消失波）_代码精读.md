# 第 1 段 · 两条前沿：`geoFront` 与 `matFront`

这一段要解决的问题：**"先变半透明、再消失"这个两段结构，在代码里到底由什么承担**。
答案是一对同速、间距固定的前沿，它们都在 `src/WarpSC.h` 里，都是唯一时钟 `tau` 的纯函数。

```cpp
    inline constexpr float NOISE_W = 0.25f;                     // 噪声抖动权重

    inline constexpr float FRONT_LO = -0.5f * NOISE_W;          // -0.125
    inline constexpr float FRONT_HI = 1.0f + 0.5f * NOISE_W;    //  1.125
    inline constexpr float FRONT_LEAD = 0.25f;                  // 材质领先几何的空间量
```

```cpp
    inline float frontRamp(float tau, float start)
    {
        if (tau <= start)       return 0.0f;
        if (tau >= TAU_STAR)    return 1.0f;

        return smoothstep01((tau - start) / (TAU_STAR - start));
    }

    inline float geoFront(float tau)
    {
        float r;
        if (tau <= TAU_STAR)        r = frontRamp(tau, FRONT_GEO_START);
        else if (tau <= T_WIRE_END) r = 1.0f;                    // 线框段：全剥完
        else                        r = 1.0f - smoothstep01((tau - T_WIRE_END) / FRONT_RETREAT);

        return (FRONT_LO - FRONT_LEAD) + (FRONT_HI - FRONT_LO + FRONT_LEAD) * r;
    }

    inline float matFront(float tau) { return geoFront(tau) + FRONT_LEAD; }
```

## 带宽为什么恒为常数

**命题 1**：对任意 $\tau$，`matFront(tau) - geoFront(tau) = FRONT_LEAD`。

证明：把 `matFront` 的定义代入左边，得 `(geoFront(tau) + FRONT_LEAD) - geoFront(tau)`，
同类项相消，等于 `FRONT_LEAD`。证毕。

这一步就是逐帧观察里"两条前沿同速、间距固定"的全部实现：间距是常数而不是某个随
$\tau$ 变化的量，所以不可能出现一条追上另一条的情形，也不需要每帧重新同步。

用白话讲：**"半透明波"和"消失波"不是两套机构，而是同一根扫描线量出来的两点**。
后一点（`geoFront`）扫过就整块剔除，前一点（`matFront`）扫过就开始变半透明，
两点之间的距离固定为 `FRONT_LEAD`，因此"半透明"这个状态在**去程**持续的时间也是固定的
（抵达段另有 `uSolidify` 把它与前沿速度解耦，见第 4 段）。

## 端点为什么要超出取值范围

带噪坐标的取值域是 $[-W/2,\ 1+W/2]$（$W$ 就是 `NOISE_W`），所以 `FRONT_LO` 与 `FRONT_HI`
被特意定成这个域的上下界。`geoFront` 在 $r=0$ 时取 `FRONT_LO - FRONT_LEAD`（比下界还低
一个带宽）、在 $r=1$ 时取 `FRONT_HI`（正好等于上界），于是"起手"与"收尾"两端都精确，
不靠任何手调的余量常数。

这里有一个历史上踩过的坑：曾经给带噪坐标套过 `clamp(..., 0, 1)`，结果噪声的负半程被压成
一整片平台，而静止态两条前沿恰好落在 0 附近，`smoothstep(a, b, x)` 遇到 $a = b$ 的退化输入，
艏部就在**静止态**冒出一块青绿伪影。修法不是加 epsilon，而是让两个取值范围对齐（前沿的域
覆盖噪声的域），本条就是那次修正的结果。

## 稳态为什么必然实心

**命题 2**：静止态（$\tau \le 0$）与折跃结束态（$\tau \ge T_{\text{WIRE\_END}} + \text{FRONT\_RETREAT}$）
下 `stripped = 0`，与 `FRONT_LEAD`、`uTranslucency` 取多少都无关。

证明：两种状态下 $r = 0$（前者因为 `frontRamp` 在 $\tau \le \text{start}$ 时返回 0，后者因为
retreat 段的进度降到 0），代入 `geoFront` 得

$$
\text{geoFront} = (\text{FRONT\_LO} - \text{FRONT\_LEAD}) + (\text{FRONT\_HI} - \text{FRONT\_LO} + \text{FRONT\_LEAD}) \cdot 0
= \text{FRONT\_LO} - \text{FRONT\_LEAD},
$$

第二个等号是第一项保留、第二项因乘以 0 而消失。再由 `matFront = geoFront + FRONT_LEAD` 得
`matFront = FRONT_LO`。而第 2 段会看到带噪坐标恒有 $g_t \ge -W/2 = \text{FRONT\_LO}$，
即 $g_t \ge \text{uFrontMat}$；`smoothstep(a, b, x)` 在 $x \ge b$ 时等于 1，
于是 `stripped = T \cdot (1 - 1) = 0`，全实心。证毕。

这条保证很重要：**"稳态干净"是构造出来的，不是调出来的**。每次动带宽或平台密度，
只要这两条关系不变，就仍然不需要在稳态担心伪影。

# 第 2 段 · 溶解块：从斜坡改成平台

这是本篇的核心。这一段要解决的问题：**为什么原来"看不到半透明这个状态"，
以及把公式改成什么样之后才表达得出这个状态**。

改动集中在 `spaceship_frag4.0.shader` 的溶解块，按执行顺序读：

```glsl
    float gt = g + uNoiseW * (noise3(q * uNoiseFreq) - 0.5);

    // SC 分支不做坐标镜像。同一套判断天然给出 SC2 要的两个方向：
    //   去程 geoFront 往【升】，被剔除的永远是 gt 小的一侧，所以艏先没；
    //   抵达 geoFront 往【降】，先满足 gt >= uFrontGeo 的是 gt 大的一侧，所以艉先长回来。
    // 因此 uFrontRev 这个旋钮在 SC 分支里不再需要。
    if (gt < uFrontGeo) discard;                      // 消失波：越过它的那块几何整段不画

    // SC 分支：两道前沿之间是【半透明平台】，不是渐变斜坡。
    // 模型半透明波（uFrontMat）扫过之后，这块立刻进入固定密度的抖散态 ——
    // uTranslucency 就是被丢弃的格子比例 —— 一直保持到消失波（uFrontGeo）把它整段剔除。
    // 于是读作"先变半透明、再消失"，而不是"逐渐溶解"；前沿本身只留 uFrontSoft 这么窄的过渡。
    //float stripped = 1.0 - smoothstep(uFrontGeo, uFrontMat, gt);
    float stripped = uTranslucency * (1.0 - smoothstep(uFrontMat - uFrontSoft, uFrontMat, gt));

    // 块状抖动透明：把物体空间量化到格子，每格取一个阈值；剥离程度超过阈值就整格丢弃。
    // 用 discard 而不是真混合：真混合要按深度排序、还得开面剔除，而本工程从未开剔除。
    // 乘 2.0 是块大小旋钮：值越大格子越细（沿一个轴的格子数约为 2 * uNoiseFreq）。
    float dth = hash13(floor(q * uNoiseFreq * 2.0));
    if (stripped > dth) discard;
```

## `gt` 为什么不夹 clamp

`gt = g + uNoiseW * (noise3(...) - 0.5)`，其中 $g \in [0,1]$ 是轴向坐标（0 在艏、1 在艉），
`noise3` 的值域是 $[0,1]$，所以

$$
g_t \in \left[0 - \frac{W}{2},\ 1 + \frac{W}{2}\right] = [\text{FRONT\_LO},\ \text{FRONT\_HI}],
$$

第一个等号是把噪声项的最小值与最大值分别代入，第二个等号用的是 `FRONT_LO` 与 `FRONT_HI`
的定义式。**这个域是被构造出来覆盖前沿的），所以不需要夹**。夹了反而会制造平台，
就是第 1 段末尾讲的那个坑。

## 消失波：一行 discard

`if (gt < uFrontGeo) discard;` 一行同时管两件事：去程是"扫过即消失"，抵达段是"退回即重建"。
它不需要知道方向，因为方向完全由 `geoFront` 是升还是降决定（第 3 段展开）。

## 半透明波：平台公式

**命题 3（平台的期望透光率）**：平台内像元的期望保留率等于 $1 - T$，其中 $T$ 是
`uTranslucency`。

证明：`dth` 取自 24 位整数哈希，在被量化的格子里取值均匀且与位置无关，故
$d_{th} \sim U[0,1)$。丢弃条件是 `stripped > dth`，即 $d_{th} < T$，于是

$$
P(\text{丢弃}) = P(d_{th} < T) = T, \qquad P(\text{保留}) = 1 - T,
$$

第一个等号是均匀分布的定义，第二个等号是"概率之和为 1"。证毕。

这条是敢用 `discard` 代替真 alpha 混合的定量依据：**平台在统计上等价于一层固定的 alpha**，
区别只在空间上离散（块状）而在时间上不需要排序。

## `uFrontSoft` 为什么不能是 0

平台公式里 `smoothstep(uFrontMat - uFrontSoft, uFrontMat, gt)` 的两个边界是
`uFrontMat - uFrontSoft` 与 `uFrontMat`。光滑化宽度取 0 时两边相等，
`smoothstep(a, a, x)` 是退化输入（分母为 0）。这与第 1 段那个 `clamp` 坑是同一类问题：
**退化输入不会在静止态报警，只会在某个角落冒出一块看不出原因的伪影**。
所以 `uFrontSoft > 0` 是硬约束，不是建议。

顺带一个尺度关系：`uFrontSoft = 0.03` 轴向单位，换算到世界约
$0.03 \times 2 \times 26.8 \approx 1.6$ 世界单位；而抖散格子边长约
$26.8 / (2 \times 9) \approx 1.5$ 世界单位。两者同量级，所以**前沿是一格一格的台阶，
不是一条光滑直线** —— 这是特性（与 SC2 的块状观感一致），不是走样。

## 块状抖散：阈值按格子取

`dth = hash13(floor(q * uNoiseFreq * 2.0))` 里 `floor` 是关键：同一个格子内的所有像素拿到
同一个阈值，于是**丢弃是整格整格的**，读起来是"方块在消失"，而不是"像素在闪烁"。
`q` 是归一化后的物体空间坐标，所以格纹锁在舰体上，舰体平移旋转时不会游动。

## 外观混合跟着 `stripped` 一起变

```glsl
    albedo    = mix(albedo,    uDissolveColor * 1.4, stripped);
    metallic  = mix(metallic,  0.0,  stripped);
    roughness = mix(roughness, 1.0,  stripped);
    N         = mix(N, normalize(Normal), stripped);
```

`stripped` 既是"被丢弃的比例"，也是"外观被剥离的程度"。平台里它是常数 $T$，
所以保留下来的那些格子会**稳定地**带 $T$ 比例的"剥离外观"（偏亮青白、粗糙、无贴图细节），
于是那层半透明壳是**发光**的 —— 这正是 SC2 的样子。

代价要说清楚：`uTranslucency` 一拧两用（既管密度又管"热度"）。要分开就得拆成两个 uniform，
目前没必要。

## 改之前是什么样

改之前那一行是 `float stripped = 1.0 - smoothstep(uFrontGeo, uFrontMat, gt);`：
它在带内从 0 **连续升到** 1，也就是一条斜坡。斜坡能表达的只有"越来越淡"，
而"半透明"是一个**状态** —— 状态必须有一个保持区间，斜坡没有。这就是"船跟着波直接没了"的
全部原因：不是缺了一个效果，而是缺了一段平坦的函数。

# 第 3 段 · 方向：材质与骨架为什么反向

这一段要解决的问题：**四个方向各自从哪来** —— 去程艏先没、抵达材质自艏向艉、
骨架与幽灵舰体自艉向艏 —— 以及为什么坐标镜像只对材质那一路有用。

## 判据的单调性（不加镜像时）

**命题 4**：剔除判据是 $g_t < \text{uFrontGeo}$，存活集合是 $\{g_t \ge \text{uFrontGeo}\}$；
它的扩张与收缩方向完全由 `geoFront` 是升还是降决定，与"哪一端应该先动"无关。

证明：$g_t$ 是连续的轴向坐标，$g_t = 0$ 在艏、$g_t = 1$ 在艉。于是

- 去程：`geoFront` 从 `FRONT_LO - FRONT_LEAD` 单调**升**到 `FRONT_HI`，存活集合单调**收缩**，
  且总是从 $g_t$ **最小**的一端开始，即**艏先消失**；
- 抵达：`geoFront` 从 `FRONT_HI` 单调**降**到 `FRONT_LO - FRONT_LEAD`，存活集合单调**扩张**，
  且总是从 $g_t$ **最大**的一端开始，即不加镜像时是**艉先长回来**。

所以"去程艏先没"是判据的自然结果、不需要镜像；而抵达要的方向恰好与它相反。

## 抵达段为什么要镜像

逐帧观察里抵达段是材质**自艏向艉**填充，也就是与去程**同一端领先**。命题 4 已经说明：
同一套判据在"升"与"降"两种走向下给出的是相反的两端，所以要让它也艏先，就必须把坐标翻一次。

**命题 4′**：令 $h = 1 - g_t$（`uFrontRev = 1`），存活条件 $h \ge \text{uFrontGeo}$ 等价于

$$
g_t \le 1 - \text{uFrontGeo}.
$$

抵达段 `geoFront` **降**，故右端 $1 - \text{uFrontGeo}$ **升**，存活集合从 $g_t$ 小的一端（艏）
开始扩张，即**艏先长回来**，与去程同端领先。证毕。

镜像只在实体化段打开（`uFrontRev` 取 `(tau > T_WIRE_END) ? 1 : 0`）。在 `T_WIRE_END` 处切换
看不见：那一帧 `geoFront = FRONT_HI`，存活集合是零测集（见命题 5 前半段）。

## 骨架与幽灵舰体走的是另一门

它们不经过这个判据：骨架的生长门在 `warp_wire_frag2.0.shader` 里自成一门，用的是镜像坐标
`gRev = 1 - g`，幽灵舰体与它共用同一个 `uGrow` —— 于是它们天然**自艉向艏**。四个方向合起来是：

| 阶段 | 方向 | 由什么决定 |
|---|---|---|
| 去程消失 | 艏先没 | 判据 + `geoFront` 升（不加镜像） |
| 抵达材质填充 | 艏先长 | 判据 + 镜像 + `geoFront` 降 |
| 骨架生长 | 艉先长 | `warp_wire_frag2.0.shader` 的 `gRev = 1 - g` |
| 幽灵舰体生长 | 艉先长 | 与骨架共用 `uGrow` |

**材质与骨架反向是有意的**，不是 bug：观察到的画面就是这样。这也是把镜像保留下来的全部理由。

## 一次被纠正过的推断（留档）

本篇初版曾把镜像判成"多余"，理由是"同一套判断天然给出两个方向"。那句话只对了一半：
它给出的两个方向是"去程艏先没、抵达**艉**先长"，而画面要的是抵达**艏**先长，两者差一次
坐标翻转。所以 `uFrontRev` 不是冗余旋钮，它就是"去程与抵达同端领先"这个设计的实现。
这里的教训是：**把方向写成单调性之后，还要核对"哪一端的坐标更大"** —— 两句话分开看都成立，
合起来却会把方向推反。

## $\tau^\ast$ 那一帧的翻号为什么看不见

**命题 5**：传送那一帧舰体完全不可见，且"平台"不会救活任何像素。

证明：$\tau^\ast = T_{\text{CHARGE}} + T_{\text{VANISH}}$，`frontRamp` 在 $\tau \ge T_{\text{TAU\_STAR}}$
时返回 1，故 $r = 1$，代入得

$$
\text{geoFront}(\tau^\ast) = (\text{FRONT\_LO} - \text{FRONT\_LEAD}) + (\text{FRONT\_HI} - \text{FRONT\_LO} + \text{FRONT\_LEAD}) \cdot 1 = \text{FRONT\_HI},
$$

第二个等号是括号内各项与括号外各项相消。又由第 2 段的取值域，$g_t \le \text{FRONT\_HI}$，
所以 `gt < uFrontGeo` 除"噪声恰好取到上界"这一零测集之外处处成立，整艘舰体都被剔除。

再看平台：平台区是 $g_t < \text{uFrontMat} - \text{uFrontSoft}$，而该帧
$\text{uFrontMat}(\tau^\ast) = \text{FRONT\_HI} + \text{FRONT\_LEAD}$（由 `matFront = geoFront + FRONT_LEAD`
与命题 5 前半段），于是平台区的上界

$$
\text{uFrontMat}(\tau^\ast) - \text{uFrontSoft} = \text{FRONT\_HI} + \text{FRONT\_LEAD} - \text{uFrontSoft}
> \text{FRONT\_HI} \ge g_t,
$$

第一个不等号用的是 `FRONT_LEAD > uFrontSoft`（0.25 对 0.03）。所以**没有任何像素落在平台里**，
平台不可能把已经被剔除的像素"留下"。证毕。

这一条的实际意义：滑入在 $\tau^\ast$ 处要翻号（去程 $+1$ 变抵达 $-1$），
翻号之所以看不见，是因为它发生在一个全舰不可见的帧上；而把斜坡改成平台之后，
这个性质仍然成立（平台在那一帧是空的）。

# 第 4 段 · `SpaceShip24.0.cpp` 的接线

这一段要解决的问题：**时间线给出的量，在 cpp 里怎么落到 uniform 上**，
以及这一轮删掉/新增了哪几行。

```cpp
        const float frontGeo = warp_sc::geoFront(gWarp.tau);
        // SC 分支不做坐标镜像：同一套判断天然给出"去程艏先没、抵达艉先长"两个方向
        // （推导写在 4.0 片元着色器里），所以 uFrontRev 这个旋钮不再需要。
        spaceshipShader.setFloat("uFrontMat", warp_sc::matFront(gWarp.tau));
        spaceshipShader.setFloat("uFrontGeo", frontGeo);
        spaceshipShader.setFloat("uTranslucency", 0.40f);   // 半透明平台：丢弃六成格子、保留四成
        spaceshipShader.setFloat("uFrontSoft", 0.03f);      // 半透明波前沿的过渡宽度，必须大于 0
```

## 删掉了哪一行，为什么

删掉的是 `spaceshipShader.setFloat("uFrontRev", (gWarp.tau > warp_sc::T_WIRE_END) ? 1.0f : 0.0f);`
连同它上面那句解释"返程镜像坐标，艏先长回来"的注释。理由见第 3 段：
镜像把抵达方向翻反了，而 SC 分支要的方向不需要它。**着色器里的 `uFrontRev` 声明也一并删掉**，
于是这条数据流上不再有一个"看着像可选、其实只会帮倒忙"的旋钮。

## 名字写错会静默无效

`Shader::setFloat` 内部是 `glGetUniformLocation` + `glUniform1f`。名字不存在时位置是 -1，
而 `glUniform1f(-1, v)` 是**合法的空操作**（不报错、不打日志）。所以新加 uniform 时的
第一验收项永远是"这个效果有没有出现"：如果 `uTranslucency` 拼错，现象就是
"平台没出现、还是老样子"，而编译、运行、自测全都正常。这是本工程复用过多次的结论：
**着色器侧的拼写错误只能靠目视发现，编译器不会帮忙**。

## 与骨架、幽灵舰体的相位

三个东西共用"从一端到另一端"的语义，但各有一根自己的曲线，必须对齐：

| 东西 | 曲线 | 方向 |
|---|---|---|
| 材质恢复（本段） | `geoFront` 反跑（`FRONT_RETREAT`）+ 坐标镜像（`uFrontRev`） | 判据加镜像，得到**艏先**（第 3 段命题 4′） |
| 线框骨架 | `wireGrow`（`GROW_SPAN`） | 门里写的是 `gRev = 1 - g`，艉先 |
| 幽灵舰体 | 与骨架同一个 `uGrow` | 艉先 |

三者同向是这一轮修正之后的结论。改之前材质那一路是反的，而由于它当时只有一帧的过渡，
肉眼几乎看不出来 —— 这正是"斜坡"把它藏住了。

# 第 5 段 · 外壳 pass：没有溶解门，以及它自己的退场曲线

这一段要解决的问题：**那层青色能量壳什么时候在场、什么时候退场**，
以及为什么它的寿命**不能**跟着通道表走。

## 没有溶解门意味着什么

外壳是独立的一次绘制，片元里只有菲涅尔、细丝与网格，**没有 `geoFront` 判据**：

```cpp
            warpShellShader.setMat4("model", spaceshipModel);   // 贴在舰体表面上，含前冲与拉伸
            warpShellShader.setFloat("uShellStrength",
                warp_sc::shellAlpha(gWarp.tau) * warp_tune::U_SHELL_GAIN);
```

也就是说，它照着舰体的表面在画，不管那块表面上的 PBR 像素有没有被 `discard` 掉。所以**它有能力**
盖在"已经被扫掉"的区段上 —— 只要那一刻它的强度还不是 0。这个能力保留着备用（例如将来要做
"消失之后残留一层壳"），但**当前设计刻意不走这条路**：外壳在半透明波够到舰首之前就退干净了
（见下一小节），于是画面上不会出现"舰体没了、壳还在"的东西。

顺带一个实测结论：强度不是"小到看不见"就等于关掉 —— `U_SHELL_GAIN = 0.01` 时那层壳**清楚可见**
（线性 `0.01 × 3.7 ≈ 0.037`，经 gamma 约 22% 的灰），而调到 `0.5` 反而会把舰体细节糊掉。

## 外壳自己的退场曲线：`shellAlpha(tau)`

强度不再挂 `u_c`，改挂一条独立包络，**整条用"扫描进度"表达**（所以改四段时长不会把相位带偏）：

| 时刻 | 扫描进度 `p` | 强度 |
|---|---|---|
| 蓄能段内 | `p < 0` | 由 0 升到满，正好在扫描开始（τ = `TAU_STAR - SCAN_TIME`）到顶 |
| τ ≈ 0.55 | `p = 0.08`（`SHELL_FADE_P0`） | 开始变暗 |
| τ ≈ 0.61 | `p = 0.18`（`SHELL_FADE_P1`） | **归零** —— 那一刻正是"材质前沿刚越过艏"，也就是半透明波开始扫描 |

直觉版：**蓄能期壳在场，波一开始扫就退场**。这也解释了为什么"残留壳"这件事最终没有做 ——
壳与半透明波是**接力**关系，不是叠加关系。

下面那一小节讲的是**旧的**做法（挂 `u_c`）以及"为什么不能靠挪通道表来改它的寿命"，
它的价值在于把通道表的互锁关系讲清楚了，结论仍然成立：`V_R0 = C_F0`，动 `C_F0` 会连锁白化段。

## 一次真实的翻车：把外壳的寿命拉过 τ\* 之后（案例）

这一节按"现象 / 当时错在哪 / 根因 / 修法 / 教训"记一次真实的设计错误，因为它的形状很容易重犯。

**现象**。舰体已经被抽走、外壳本来也该没了，但画面上外壳**在折跃前的位置闪了一下**，
同时影子也在跳。

**当时错在哪**。前一轮我把外壳的寿命从"随 `u_c` 在 1.07 归零"改成"保持到 τ\*、再用
`SHELL_TAIL = 0.10 s` 淡出"，理由是"外壳 pass 没有溶解门，所以它是'消失之后那层残留壳'的
唯一来源"。这个理由**机制上没错、意图上错了**：外壳与半透明波是**接力**关系（波一开始扫，
壳就该退场），不是叠加关系。意图一错，就把壳拖进了本该没有它的相位。

**根因（两条叠在一起）**。

1. 外壳的强度不受 `geoFront` 约束（它本来就没有溶解门），所以它会一直画到自己那条包络归零；
2. 外壳用的矩阵是 `spaceshipModel`，而这份矩阵在 τ\* 前后带着**滑入**（去程 `+K`、抵达 `−K`
   个半舰长，`K = SLIDE_ARRIVAL_K = 2.2`，即约 59.6）。于是 τ\* 之后它被甩到**起点那一侧**，
   而相机已经跟着舰体传送到落点 —— 屏幕上就是"壳留在了折跃前的位置"。

**修法**。把退场时间改成"半透明波够到舰首之前"：`shellAlpha(τ)` 整条用扫描进度表达，
`SHELL_FADE_P1 = 0.18` 正是"材质前沿刚越过艏"的进度，于是壳在 τ ≈ 0.61 就归零、**根本活不到
τ\***，滑入自然不会作用于它。（将来若真要"残留壳"，必须让它改用不含滑入的 `shipWireModel`。）

**教训（两条，都可复用）**。

- **给一个效果"延长寿命"之前先问两件事**：它挂的包络是谁在管、它挂的矩阵里有没有随时间变化的
  位移或缩放。这次的答案分别是"没人管"与"有滑入"，于是"延长寿命"等于把它拖进一个它从没待过的
  相位。
- **"机制成立"不等于"意图成立"**：`discard` 之外的东西确实能盖在被剔除的区段上（机制成立），
  但**要不要**让它盖是设计选择，必须回到参考画面去问，而不是从机制反推意图。

同一类耦合在影子那里也发作过（分面指派用了不含前冲的逻辑位置），修法见附录"影子分面指派"那一行。


## `u_c` 的寿命比舰体早 0.03 s

外壳的强度挂的是电流通道 `u_c`，它的下降沿是 `C_F0 = T_CHARGE = 0.90` 到 `C_F1 = TAU_STAR - 0.03 = 1.07`：

| 时刻 | `u_c` | 舰体 |
|---|---|---|
| 0.90 s | 1.0（开始衰减） | 扫描进行到约六成 |
| 1.00 s | $\sigma(0.588) = 0.63$ 的补，约 **0.37** | 只剩艉部一点 |
| 1.07 s（`C_F1`） | **0** | 还没剥完 |
| 1.10 s（$\tau^\ast$） | 已归零 | `geoFront = FRONT_HI`，整艘剥完 |

1.00 s 那一格是这样算的：归一化自变量 $(1.00 - 0.90) / (1.07 - 0.90) = 0.588$，
$\sigma(0.588) = 0.588^2 (3 - 2 \times 0.588) = 0.63$，通道值 = 该下降沿的补 $= 0.37$。

结论：**外壳比舰体早 0.03 s 熄灭，而且 1.0 s 之后就已经很暗了**。所以就算把强度调回去，
那层壳也只盖得住消失过程的前三分之二，最后一截仍是空的。要让壳"活过"舰体，必须给它
一条**独立的包络**。

## 为什么不能靠挪通道表延长

看起来最省的办法是把 `C_F0`、`C_F1` 往后挪。但通道表是互相咬合的：

```cpp
    inline constexpr float
        V_R0 = C_F0,
        V_R1 = FLASH_RISE,
        V_F0 = C_F1,
        V_F1 = TAU_STAR + 0.03f;
```

白化通道（`u_v`）的上升段起点就是 `C_F0`，而它的上升终点 `V_R1 = FLASH_RISE = TAU_STAR - 0.05`
是钉死的。把 `C_F0` 从 0.90 挪到 1.00，上升段的长度就只剩

$$
V_{R1} - V_{R0} = (\tau^\ast - 0.05) - 1.00 = 1.05 - 1.00 = 0.05\ \text{s},
$$

也就是**白化与拉伸只剩 0.05 s 起步**，整条观感会崩。所以正确的做法是加一条与通道表无关的
独立包络（例如给外壳一个自己的 `shellAlpha(tau)`），而不是动那张互锁的表。

# 第 6 段 · 加色通道的可见阈值

这一段要解决的问题：**为什么 `uShellStrength = u_c * 0.01f` 仍然看得见**，
以及这个通道的可用区间到底在哪。

外壳片元的输出是"要加多少"（加法混合），它的最大亮度由三项之和给出：

```glsl
    vec3 col = uShellColor * (fres * 1.6 + wire * 0.9 + grid * uGridStrength);
    FragColor = vec4(col * uShellStrength, 1.0);
```

菲涅尔项、细丝项、网格项都取到峰值时，括号内约为 $1.6 + 0.9 + 1.2 = 3.7$。
乘上 `uShellStrength = 0.01`，进入 HDR 缓冲的线性亮度是

$$
0.01 \times 3.7 \approx 0.037.
$$

显示前要过 gamma（约 $1/2.2$ 次幂），于是

$$
0.037^{1/2.2} \approx e^{-3.297 / 2.2} \approx e^{-1.499} \approx 0.22,
$$

也就是**约 22% 的灰**，肉眼当然看得见。结论：

- 这个通道的可用区间是 **0.05 ~ 0.3**，而不是想当然的 $[0, 1]$；
- 取到 2.0 的时候不是"亮一点"，而是"糊成一片"；
- 教训是：**调加色强度之前，先把线性值折算成 gamma 之后的观感再定数**，
  否则会把"0.01 应该等于关掉"当成常识，起点给高十倍。

# 第 7 段 · 验证方法：慢放 + 时间戳反推 `tau`

这一段要解决的问题：**怎么把"观感调参"变成可测量的事**。方法是把慢放开关与视频时间戳
结合起来，反推出每一帧对应的 `tau`。

## 两条锚定线

扫描区间是 `[FRONT_GEO_START, TAU_STAR] = [0.50, 1.10]`。这里有两个不同的"进度"，**不能混用**：

- $r$ = `frontRamp` 的输出，是前沿的**位置**参数，在 0.60 s 内由 0 走到 1，但**不是时间的线性函数**；
- $p = (\tau - \text{FRONT\_GEO\_START}) / (\tau^\ast - \text{FRONT\_GEO\_START})$ = **归一化时间**。

两者由 $r = \sigma(p)$ 联系（σ 就是 `smoothstep01`）。所以反解"前沿越过舰首（$g_t = 0$）"要两步：
先由位置方程求 $r$，再由 $\sigma(p) = r$ 反解 $p$。

- 消失波（`geoFront`）：`geoFront = 0` 等价于 $(\text{FRONT\_LO} - L) + 1.5\,r = 0$，
  即 $-0.375 + 1.5r = 0$，得 $r = 0.25$；由 $\sigma(p) = 0.25$ 解得 $p \approx 0.33$，
  即 $\tau = 0.50 + 0.33 \times 0.60 \approx 0.70$。
- 半透明波（`matFront`）：`matFront = 0` 等价于 $\text{FRONT\_LO} + 1.5\,r = 0$（$\text{matFront}(r)$ 括号外的
  $-L$ 与后加的 $+L$ 相消），即 $-0.125 + 1.5r = 0$，得 $r = 0.0833$；由 $\sigma(p) = 0.0833$
  解得 $p \approx 0.18$，即 $\tau = 0.50 + 0.18 \times 0.60 \approx 0.61$。

两者相差约 $0.09$ s，量级上等于带宽除以平均速度（$0.25 / 2.5 = 0.10$）—— 这就是第 1 段命题 1
在时间上的样子。**"先求 $r$、再反解 $p$"这一步不能省**：本节初版直接把 $r$ 当成时间的线性函数，
于是把两条锚定线都算早了（0.55 / 0.65），差的就是 σ 在两端那段慢起步。

同一套换算下，一组更有用的位置对照：

| 前沿扫到哪 | $r$ | $p$ | $\tau$ |
|---|---|---|---|
| 材质前沿过艏（开始出现半透明） | 0.083 | 0.18 | 0.61 |
| 几何前沿过艏（艏开始整块消失） | 0.250 | 0.33 | 0.70 |
| 前沿到舰体一半 | 0.583 | 0.56 | 0.83 |
| 前沿到舰尾 | 0.917 | 0.67 | 0.90 |
| 整艘剥完（含噪声上界） | 1.000 | 1.00 | 1.10 |

## 拟合与互证

把两帧画面按"舰体还全实"与"只剩艉部一点"分别对齐到 $\tau \approx 0.50$ 与 $\tau \approx 0.90$
（后者取上表"前沿到舰尾"那一行），用视频时间戳（`分:秒:帧`，30 fps 换算成秒）算斜率：

$$
\frac{\Delta \tau}{\Delta t_{\text{视频}}} = \frac{0.90 - 0.50}{10.53 - 6.60} = \frac{0.40}{3.93} \approx 0.10,
$$

与源码里设定的 `TIME_SCALE = 0.1f` 相符。**两边是独立得到的**（一边来自代码常量，
一边来自画面），所以这条互证同时验证了：慢放确实生效、时间线与画面同步、
以及"用截图定参数"这条路是可靠的。

## 截图与 `tau` 的对照

| 截图（电脑时间） | 视频时间 | 估算 `tau` | `geoFront` | 画面应该是什么 |
|---|---|---|---|---|
| 235001 | 6.60 s | ≈ 0.50 | `-0.375` | 舰体全实（两条前沿都还在艏之前），碎屑已在飞 |
