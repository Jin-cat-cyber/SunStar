# 尘埃星环 与 TAA：叠加层进时间累积的失败尝试记录

> 对象：活跃版本 `src/SpaceShip26.0.cpp` 及其 TAA（时间抗锯齿）。
> 关联：`时间抗锯齿（TAA）_设计与实现计划书.md`（重投影式 (18)(19)(21)、帧内插入位置 §8.2、叠加层边界 §8.4、已知伪影 §12）；`星际争霸2折跃_冲击波（收束与发散）_设计与实现计划书.md`（深度纹理与"按深度反算世界坐标"的约定）。
> 状态：**未完成、暂时接受**。星环目前保持"画在 TAA 之前、不参与深度测试、加法混合"的原样；它进入时间累积后产生的拖影是已知缺陷。本文留档机制、数量级、三次尝试、踩到的四个坑，以及将来接着做时的两条接口方案。

---

## 1. 结论先行

1. 尘埃星环是**加法体光叠加层**：它写颜色、不写深度，本身没有"自己的深度"。把它放进 TAA 的时间累积后，它的历史只能按**它后面那层背景的深度**取回，于是必然出现两类伪影：环上浮出小行星形状的"倒影"，以及相机移动时朝**反方向**一起滑走的拖影。
2. 这类问题的正解由计划书 §8.4 给出：**叠加层不进时间累积**（镜头光晕早已按这条处理：它画在 `PostProcessing` 之后）。星环没有照此处理，是这次的主要缺口。
3. 三次尝试的结论：
   - **尝试 A（把星环 pass 挪到 TAA 之后）**：拖影消除，但环变成叠在舰体之上（去掉遮挡的代价）。
   - **尝试 B（环写自己的深度 + 开深度测试）**：舰体遮挡正确，但雾在小行星轮廓上变成**刀切**，"雾漫过石头"的观感消失；期间另外踩到三个实现坑（见 §5）。
   - **尝试 C（不参与深度测试，改为按场景深度做软截断）**：机制上同时满足前两者的诉求，代码已写出但**随该版文件被删除而未定格**，本文记录接口与要点。
4. 现在采用的临时状态是"不管"：星环维持原样，拖影保留。这不改变结论 1，只是把它挂起。

## 2. 现象与判别实验

观察到的三种现象，以及它们对应的机制（逐条对应，不是并列罗列）：

| 现象（用户描述） | 机制 |
|---|---|
| "环上像是有小行星的倒影，移动的时候会反方向一起移动" | 环的像素按背景深度重投影，历史取回的位置与实际不符；错位量随相机平移累积，方向与运动相反 |
| "黑色的隔断层，像是把 VAO 的完整形状漏出来了" | 三次尝试期间由三个不同的实现错误各自产生过（见 §5）：深度写开启导致同一次绘制内自遮（块状缺口）、混合方式被改成 alpha 混合（背景被 $(1-a)$ 压暗）、以及未设 uniform 导致 `gl_FragDepth` 为 NaN |
| "环打在小行星上的感觉没有了" | 尝试 B 里深度测试的**二值性**：遮挡边界必然是 1 像素硬切，雾不再"漫过"石头 |

**判别实验（成本为零，结论最强）**：把 resolve 的当前帧权重临时固定为 $w=1$（等价于关闭时间累积），环上的倒影与拖影**当场消失**。这说明伪影来自历史，而不是环自身的光照或几何。任何"环上的异常"在做昂贵改动之前，先做这一步。

## 3. 机制与数量级

### 3.1 错位有多少像素

重投影要求每个像素知道"它上一帧在哪"。相机只做平移时，深度 $z$ 处表面在屏幕上的位移由小孔投影给出。设 $x_c$ 为相机空间横向坐标，$\Delta$ 为沿横向的平移量，则

$$x_{ndc}=\frac{f}{z}x_c,\qquad f=\frac{H/2}{\tan(\mathrm{FOV}/2)} \tag{1}$$

对 $x_c$ 求差得到位移的像素数

$$\Delta x_{px}=f\,\frac{\Delta}{z} \tag{2}$$

代入本工程参数：窗口高 $H=600$、`camera.Fov` $=45^\circ$，故 $f=300/\tan(22.5^\circ)=724.3$ 像素。于是

| 该像素的真实距离 $z$ | 每平移 1 世界单位，像位移 |
|---|---|
| 150 | 4.83 px |
| 260 | 2.79 px |
| 400 | 1.81 px |
| 无穷远（天空，深度恰为 1） | 0 |

星环相对相机的距离随位置在几十到约 460 世界单位之间变化（`ringInner = 150`、`ringOuter = 260`，相机默认位于 $z=+200$，正处在环的内外半径之间）。巡航速度约 1 世界单位每帧，因此**每帧错位 1 到 5 像素**；而折跃传送那一帧整舰平移 100 世界单位，错位可达上百像素——远超一屏，这就是当时"整屏拉伸残影"的来源。

环的几何尺度与阈值的一致性可另作校验：环厚 `ringThickness = 15`（半厚 7.5），相对 150 到 260 的半径是小量，因此"用单一深度代表整条视线上的环"这种近似在视差层面误差远小于 1 像素（§3.3 用到这一点）。

### 3.2 同一个像素有三种可能的错法

| 该像素背景是什么 | 重投影走的支路 | 结果 |
|---|---|---|
| 天空（深度 $=1$） | 天空支路，只按朝向旋转（计划书式 (21)） | 环被当成无穷远，平移视差完全丢失 |
| 小行星、行星（深度 $<1$） | 实体支路，按**背景**的深度做视差 | 环的视差被换成背景的视差 |
| 环同时压在小行星轮廓两侧 | 上面两支**混用** | 轮廓两侧映射不同，环的亮度在轮廓上出现接缝 |

第三行是最刺眼的一种：它不需要相机快速运动，只要环与实体在画面上相接就会显现。

### 3.3 硬切与软化的区别

深度缓冲是逐像素的二值信息：一个像素要么被遮挡、要么不被遮挡。因此**用深度测试做遮挡，边界必然是 1 像素的硬切**，无论环本身多柔。要让边界变柔，需要的是一个**连续的距离差场**，而不是一个布尔量。做法是在 ray march 的每个采样点上，按"该采样点比场景表面远多少"给一个连续衰减

$$\mathrm{att}(t)=1-\mathrm{smoothstep}\left(z_s,\; z_s+W,\; t\right) \tag{3}$$

其中 $z_s$ 是该像素上不透明场景离相机的距离（由深度反算），$t$ 是采样点沿视线的距离（射线方向已归一化，故 $t$ 直接就是距离），$W$ 是过渡带厚度（当时取 60 世界单位）。采样点的密度乘上 $\mathrm{att}$ 之后再累加，于是：实体**之前**的雾照旧叠加（$\mathrm{att}=1$），实体**之后**的雾在 $W$ 内平滑淡出。$W$ 是唯一的旋钮：太小接近硬切，太大则"石头挡不住雾"。

## 4. 三次尝试

### 4.1 尝试 A：把星环 pass 挪到 TAA 之后

**改动**：把星环那一段整体剪切，插到 TAA resolve 之后、`PostProcessing` 之前（与镜头光晕同一个位置）。

**期望**：环不进历史，拖影消失（计划书 §8.4 对叠加层的处理方式）。

**实测**：拖影确实消失；但环变成画在舰体之上——因为环画在舰体之后且不参与深度测试，舰体再也盖不住它。

### 4.2 尝试 B：环写自己的深度 + 开深度测试

**改动**：环的片元着色器写出自己的窗口深度

$$z_{write}=\frac{\sum_i s_i\,t_i}{\sum_i s_i} \tag{4}$$

其中 $s_i$ 是第 $i$ 个采样点的散射贡献（即当时累加的 `scatter`），$t_i$ 是它的距离；也就是**贡献加权质心深度**。配合 `glEnable(GL_DEPTH_TEST)` 与 `glDepthMask(GL_FALSE)`：写出的深度只参与测试、不污染深度缓冲。

**期望**：环被更近的不透明几何（舰体、小行星）挡住；同时因为环已在 TAA 之后，不存在历史问题。

**实测**：舰体遮挡正确；但雾在小行星轮廓上变成刀切（§3.3），"雾漫过石头"的观感消失。这条是**几何与其表示的固有矛盾**：环是介质，遮挡它的石头是不透明的，介质被不透明体整齐切掉本来就是"对"的，只是不好看。

### 4.3 尝试 C：不参与深度测试，改为软截断

**改动**（已写出，未定格）：

1. 环画进一个**只挂颜色附件的 FBO**（`color0 = hdrColorBuffer`，**不带深度附件**）。原因是环要**采样** `hdrDepthTex` 来做 §3.3 的衰减，而把该纹理当深度附件挂在当前 FBO 上采样就是反馈回路（未定义行为）。
2. 环的片元着色器新增 `uniform sampler2D uDepth`，进入主函数时求一次 $z_s$：深度 $d<1$ 时用 `invProjView` 把该像素反算成世界点、再取到相机的距离；$d\ge 1$（天空）时 $z_s$ 取一个大值，使式 (3) 恒为 1。
3. march 循环里每个采样点乘上式 (3)。环本身不再写深度、不再参与深度测试。

**期望**：既无刀边（没有布尔遮挡），也不会整片盖在舰体上（落在舰体之后的雾淡出）。

**实测**：代码完成，但承载它的那一版文件被删除，未获得定格结论。要点与接口留在本文 §6。

## 5. 踩到的四个坑（都发生在尝试 B/C 期间）

这四条共同的特征是：**编译期零警告、画面才出问题，而且症状离肇事点很远**。

### 5.1 没被设过的 uniform 默认是全零

`uProjView` 在一次清理里被删掉了对应的 `setMat4`，而着色器仍在用它把采样点投成窗口深度。GL 里未设置的 `mat4` uniform 是**全零矩阵**（不是单位矩阵），于是

$$\texttt{cc}=P_{proj}\cdot p=(0,0,0,0),\qquad \texttt{gl\_FragDepth}=\frac{cc_z}{cc_w}=\frac{0}{0}=\mathrm{NaN} \tag{5}$$

`gl_FragDepth` 为 NaN 时深度测试结果未定义，实测表现是**成片碎块被丢弃**，边缘跟着光栅化块走（所以看起来像"把 VAO 的形状漏出来了"）。

**判据与防御**：换着色器版本或撤掉/恢复一处改动之后，逐个核对"它声明的每个 uniform 在 C++ 里都有人 `setXxx`"；着色器侧写 `gl_FragDepth = (cc.w != 0.0) ? ((cc.z/cc.w)*0.5+0.5) : 1.0;`，宁可当"最远"也不要让 NaN 进深度测试。

### 5.2 全屏 pass 打开深度测试时，深度写入必须关掉

同一次 draw call 内，后处理的片元会拿前面片元**刚写进去**的深度做比较。全屏四边形因此会**自己遮自己**：被切掉的部分按光栅化顺序呈块状。当时 `glDepthMask(GL_FALSE)` 那一行被夹在一段注释掉的旧代码块里（没有生效），于是环的深度被写进缓冲，画面上出现成块的黑带。

**判据**：全屏/叠加 pass 一律 `glDepthMask(GL_FALSE)`；症状是"块状缺口、边界跟着光栅化块"。

### 5.3 同一个状态被设两次，后设的赢

环那段代码里同时存在 `glBlendFunc(GL_SRC_ALPHA, GL_ONE)`（加法）与 `glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`（alpha 混合），后者在文件里出现得更晚，于是生效。alpha 混合会把背景乘上 $(1-a)$，$a$ 就是尘埃的不透明度 `1 - transmittance`，于是尘埃密的地方背景被压暗，形成**成片黑带**（加法混合永远不会变暗，所以这类症状一眼就能区分）。

**判据**：同一个函数里同一个名字出现几次调用；改一处 GL 状态之前，先看它在这段里是否已被设过。

### 5.4 UTF-8 BOM 丢失会把注释变成"吞行器"

活跃版本 `SpaceShipNN.cpp` 是 **UTF-8 带 BOM**。BOM 一旦丢失，MSVC 按系统 ANSI（936）解码文件里的中文注释：UTF-8 的三字节汉字被拆成 GBK 对之后会剩下**悬空的引导字节，把行尾换行吞掉**（0x0A 不是合法的 GBK 尾字节），于是注释吃掉下一行代码。症状是"编辑器里看着完全正常、一编译就是一大堆『未声明的标识符 / 必须初始化 const 对象 / 语法错误』"，而且报的行离肇事注释很远。

**判据**：见到"整个 `main` 的局部变量全部未声明"这类报错，**先查文件头三字节**（`EF BB BF` 为正常），再查括号。批量审计的办法是逐文件判"含非 ASCII 吗、有 BOM 吗、严格 UTF-8 解码能过吗"，三者组合里唯一危险的是"有效 UTF-8 + 无 BOM + 含非 ASCII"。

## 6. 若将来接着做：两条接口方案

两条方案都不需要动 TAA 的重投影本身，只改"环这一路怎么与历史相处"。

### 方案甲：环不吃历史（把叠加层排除在时间累积之外）

- **做法**：环那一趟写出一张 mask（要么复用 `hdrColorBuffer` 的 alpha 通道，要么单开一张 `GL_R8`）；resolve 里读 mask，`mask > 阈值` 的像素直接输出当前帧（$w=1$）。
- **收益**：观感与"环不在 TAA 之前"时一致，无拖影；改动集中在环 pass 与 resolve 着色器。
- **代价**：环自身的高频走样不做时间累积。环是低频介质，这一条通常可接受；若环的噪声图案本身在动（本例 `time` 驱动），时间累积本来也压不住它。

### 方案乙：软截断（尝试 C 的成品）

- **做法**：新增一个只挂颜色附件的 `ringFBO`（`color0 = hdrColorBuffer`）；环着色器加 `uniform sampler2D uDepth`，求 $z_s$ 并按式 (3) 在每个采样点上衰减；环不再写深度、不再参与深度测试。
- **收益**：机制上最正确——环在实体之前照旧叠加，在实体之后平滑淡出，没有刀边，也不会整片盖住舰体。
- **代价**：多一个 FBO、环着色器每像素多一次深度采样与一个 `smoothstep`；`W` 需要一个观感上的定值。

### 已写好的代码在哪

软截断那一版留在 `res/shader/00_SpaceShip/Stellar_Ring2.0/ring_frag3.0.shader`：它同时含"写 `gl_FragDepth` 做硬遮挡"与"按场景深度软截断"两段，前者已改为留档注释。现行 `SpaceShip26.0.cpp` 加载的是 `ring_frag2.0.shader`（实验前的版本），因此星环当前不依赖 `uDepth`，不存在"采样未绑定纹理"的暗坑。

## 7. 判据速查

| 想知道什么 | 怎么做 | 结论怎么读 |
|---|---|---|
| 伪影是不是历史造成的 | 把 resolve 的 $w$ 临时固定为 1 | 消失即历史所致，与环的光照/几何无关 |
| 重投影错位有多大 | 式 (2)，代入 $f=724.3$、该像素的 $z$ | 1 到 5 像素是常态，折跃传送帧上百像素 |
| 是硬切还是软化的边界 | 看边界在实体轮廓上是否 1 像素突变 | 突变即布尔遮挡（深度测试），渐变即距离衰减 |
| 黑带属于哪一类 | 反方向滑走（历史）／块状缺口（深度自遮）／整片压暗（alpha 混合） | 三者症状互不重叠，按表定位 |
| 编译报"局部变量全未声明" | 先查文件头三字节是否 `EF BB BF` | 不是就补回 BOM |
