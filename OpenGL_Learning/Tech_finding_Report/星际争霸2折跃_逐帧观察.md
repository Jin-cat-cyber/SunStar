# 星际争霸2 战列巡航舰折跃 · 逐帧观察

> **定位**：这是一份**参照素材的记录**，不是本工程的实现报告。用途只有一个：将来开"SC2 风格折跃"那一支时，照着它比，不用再翻聊天记录与截图。
> 与另外三份文档的分工：`战列巡航舰折跃_设计与实现计划书.md` 与 `战列巡航舰折跃_代码精读.md` 讲我们自己这一版；本篇讲**原版长什么样**。
>
> **数据来源与它的限制**：素材是在剪辑软件里**逐帧抽取**的截图（约每秒一帧）。因此：
> - **帧序只能按截图文件名里的时间戳从小到大读**（已确认与动画播放顺序一致）；
> - 截图时间戳是**截图时刻**而非视频时刻，所以**无法得到任何绝对秒数**，本篇只记"占比"与"先后"；
> - 被观察的那艘舰常贴在画面最右缘、约有 1/5 被裁掉，某些细节（例如分解残块的具体形状）无法从像素确认，凡此类情况本篇都标注为"待确认"。

---

## 1. 总览：去程与抵达是两段独立的过程

- 抵达**在去程完全结束之后**才开始（用户明确说明）。
- RTS 的相机是玩家自己的、不挂在舰体上，所以折跃期间**背景不会跳**——本工程之所以必须用全屏白闪，唯一原因就是跟随模式的相机随舰体平移了 100 单位。逐帧素材里地形与其它单位看起来完全一致，但**用户说明中途移动过镜头**，所以"背景逐帧不变"只能算弱证据，不能当结论。
- 因此"相机是否跟着舰体平移"是本工程与原版最根本的架构差异，后面所有观感差异几乎都能追到这一条。

## 2. 去程 · 第一阶段：电弧与电流外壳

| 顺序（按文件名时间戳） | 画面 |
|---|---|
| 1 | **电弧各处亮起**：蓝白火花散在舰体的好几个位置，不是从一个点连续长出来的；舰体仍为本色实体；地面圆环与绿色菱形标记已在（**后经确认：那是 RTS 的单位选取框与目标标记，不属于折跃特效**） |
| 2 | **外壳开始成型**：青色能量从舰体周围聚起并向外扩 |
| 3 | **外壳包裹完成**：青色壳加厚、完整裹住舰体，船体暗部从壳里透出，边缘有体积感 |

补充（由用户观察提供，像素上看不清）：

- 外壳上套着**正多边形能量方格**图案，随后**方格减弱消失**；
- 外壳不是一层薄皮，而是**有内部结构的体积**——后续那些"方块/矩形"不是新加的效果，而是**这层壳自己在分解**（同一样东西的三段时间：青壳、绿壳、壳碎成块）；
- 地面上的圆环是 **RTS 的单位选取框**，绿色菱形是目标标记，两者都**不属于折跃特效**（已确认）。所以"原版会提前标出落点"这条不成立，本工程"落点蓝图自己渐进画出来"与原版并不冲突。

## 3. 去程 · 第二阶段：扫描波、透明化、抽走

按用户解析（关键处已量化）：

1. **一道透明化波面自舰首向舰尾扫过**，扫过之处进入**透明**状态；
2. 波面扫到**模型中心的中垂面**（过模型中心、垂直于地面与纵轴的截面）**就停住**，与该平面"融合并被记录"——此后它是一个**固定在世界空间的平面**；
3. 停下那一刻，从艏到艉量：**约 1/4 已完全消失、1/4 处于透明带、1/2 仍是带完整信息的实体**；
4. 之后**舰体一边纵向拉长、横竖挤压，一边穿过那个被记录的固定平面**，读起来像"被吸进去"；
5. 穿过平面的部分继续变透、消失，并伴随**小矩形、柱体等残块**表示分解；
6. 舰尾完全穿过后，只剩那些残块，残块再淡出。

**修正记录**：早先曾判断"去程会把舰体变成线框、线框随之消解"，用户复核后否定——**去程没有线框**，是"直接变透明、透明度随时间单调下降直至消失"。相关结论已作废。

## 3.5 抵达 · 第一阶段：自艉向艏画出半透明的舰体

帧序（按文件名时间戳，共 8 帧）：223847、223855、223905、223914、223925、223934、223949、223956。

用户描述（已确认）：

1. **在落点自艉向艏画出一艘半透明的舰体**——注意画的**不是线框**，而是"透明材质的整船"；
2. 画到**快完成时**，这层半透明材质的**强度开始下降**（淡出）；
3. **线框被保留下来**作为过渡态，也就是说这一阶段结束时，场上留下的是一副线框。

像素上能确认的部分：落点（远离右上角那群舰的一片空地）出现绿色全息舰体，随后逐帧变密、变亮，轮廓与内部分块逐渐完整。"自艉向艏"这个方向在缩小到一百来像素的图上分辨不出，按用户观察记录。

**归属**：这批的时间戳紧接去程最后一帧，且 223847 那一帧里起点那艘舰仍是一团过曝的白绿、同时落点全息已经出现，所以它是"**去程末尾就已经开始在落点画它**"，也就是抵达的开端。

**与本工程的差别只有两处，都不在结构上**：

| | 原版 | 本工程 |
|---|---|---|
| 画的是什么 | **半透明舰体**（透明材质的整船） | **线框**（骨架） |
| 画的方向 | 自**艉向艏** | 自**艏向艉** |

方向这一条两份观察是冲突的（用户先前明确要求"自艏向艉"），最终按哪个走待定。

**待续**：线框被保留之后是什么——实体如何回来，见下一节。

## 3.6 抵达 · 第二阶段：从"逻辑面"冒出的拉伸体滑入线框

用户描述（六条，括号里给出与本工程的对应物）：

1. 在**目的地之前一小段距离**的位置有一个**逻辑竖直面**——它**不是真实绘制的几何**，只是一个位置判据（与本工程的 `geoFront` 同类：一个**阈值**，不是一条面）。
2. **飞船从这个面冒出来，冒出来时就已经是纵向拉伸、横竖压缩的状态**（与去程第二阶段的抽走形变同一种）。
3. 因为是**船向前穿过这个面**，所以**先露出来的是头部**——"从头部先抵达"由此有了机制解释：它不需要单独规定方向，方向是"穿过面"这个动作的必然结果。
4. **材质的绘制慢一步**：几何先到，材质后填（与本工程"几何与材质两级"同构，只是先后相反）。
5. 随后**模型滑入线框**（线框在目的地），**并在滑入过程中完成复位**（拉伸收回、材质填满）。
6. 面两侧有一组"**透明主体纵向排列组成的光束**"：面后方的光束逐渐变淡、变少；面前方的光束虽然消失，但数量增多。**用户交代这一段先不管**，本篇如实记录、不作解释。

**空间关系（用户确认，这一条把本工程与原版的异同钉死了）**：

- 第一阶段画出的线框**就在目的地、就是模型最终的位置**——这一点与本工程**完全一致**；
- 差别在于：**几何先在"目的地之前一段固定距离"处出现**（且出现时已经是拉伸压缩的状态），**材质滞后一步**才填上，整个模型**在这段距离里滑入线框**，并在滑入过程中完成复位；
- 也就是说，**抵达的最后一段位移是在材质化过程中走完的**，而不是"瞬移到落点、再原地重建"。
- （早先有一批帧里我把"全息的位置"与"实体舰的位置"判成两处，那是用户中途移动镜头造成的误读，已作废。）

**与去程第二阶段的关键共同点（值得单独记）**：两者都是"**一个固定在世界空间的面 + 舰体自身的运动**"驱动的。而本工程两处都是"**材料空间的阈值 + 时间**"。所以"要不要让舰体在折跃期间有一个前向运动"这一个决定，同时决定去程与抵达能不能贴合原版。

## 4. 由观察反推出的机制（本篇最有价值的部分）

### 4.1 双前沿：同速、固定间距

两个数据点：

- 波面停在 0.5 时，透明带宽度约为 0.25（舰长比例）；
- "完全消失的部分占被波面扫过部分的一半"。

这两条只有一种解释能同时成立：**存在两条前沿——"开始变透明"的边界与"完全消失"的边界——它们等速前进、间距恒定，只是相位不同**。（若两条前沿按比例缩放，速度就不等了，与观察矛盾。）

于是带宽与时间的关系是

```
带宽（以舰长计） = 前沿速度 × 透明所需时间
```

因为速度是同一个，**无量纲的带宽就完全等价于时间滞后**——所以即使拿不到秒数，也能描述它。

**与本工程的对应**：我们已经有同构的结构

```cpp
matFront(τ) = geoFront(τ) + FRONT_LEAD     // 同一条斜坡，等速 + 恒定相位差
```

差别只有两处：**带宽**（我们 `FRONT_LEAD = 0.06`，原版约 0.25）与**带内状态**（我们"压暗、拉满粗糙度"，原版"透明"）。**双前沿结构一行都不用改。**

### 4.2 拉伸是"抽走"，不是"拉长"

用户观察：拉伸发生在**模型中心的中垂面**，表现为**纵向拉长、横竖方向压缩**。写成矩阵就是

```
S = (1/w, s, 1/w)      s > 1 拉长，w > 1 横向收缩
```

它读起来是"把船吸成一条线"，而不是"把船拉长成橡皮船"。

**两个直接可用的推论**：

- 不动点是**模型原点**（也就是选中圈圆心、中垂面），而 `glm::scale` 本来就绕原点，因此原版那套形变**等价于一次普通的 `glm::scale`**，**不需要**本工程第 6 段做的 `T(a)·S·T(−a)` 锚点夹心（那个夹心只是为了把不动点挪到艏或艉）。
- 我们现在的 `vec3(1, stretch, 1)` 只拉长不收缩，这就是两者观感差别的来源。

### 4.3 拉伸的起点由前沿位置触发

用户观察：**隐没波到达舰体中垂面时才开始拉伸**。也就是说拉伸的起点不是一条独立的时间常量，而是**绑在前沿位置上**（前沿到 0.5 那一刻）。

本工程的做法是写死 `STRETCH_RISE = TAU_STAR - 0.15f`，两者不联动。要做 SC2 版时这条值得照抄。

### 4.4 波面停下后，前沿改由"舰体运动"驱动

波面停在中垂面之后不再按时间前进，而是**舰体前向穿过它**——穿过多少就消失多少。等价的说法是：前沿继续往艉走，但速度换成舰体自身的速度。

所以原版去程是**两段式变速**：先时间驱动扫到中垂面，后运动驱动扫完剩余。这也解释了为什么它"越到后面越干脆"。

**注意这一条的前提**：本工程折跃期间舰体**不动**（只有 1.5 世界单位的预备退距），所以要抄这条，得先让去程有一个"前向穿过"的运动。

### 4.5 分解残块

- 形态：**小矩形、柱体**（不是圆斑、不是细丝）；
- 行为：**出现又淡出**（瞬态），不是常驻在舰体上的结构层；能出的"碎块"本身就是外壳那层体积的分解单位；
- 用户主张用**噪声**实现，且强度**随时间衰减**。可行，要点是"块量化 + 时间包络"：掩码用 `floor(q * k)` 的哈希（形状天然是矩形/立方体，`noise3` 本工程舰体着色器里已有），再乘一个单调衰减的包络（例如 `(1-t/T)^2`）；加法混合、不写深度，因此不需要排序。
- 本条暂时搁置，先解决舰船主流程。

## 5. 更早一批素材（同一效果的另一段，顺序不可靠）

在另一段素材里还观察到（这几张没有可靠顺序，只记现象）：

- 舰体被一层**绿色块状能量**包住，能看出舰体分块；
- 舰体下方有绿色圆环/弧——**后经确认那是 RTS 单位选取框**，不属于特效；
- 中段出现**零散的白色小块碎片**；
- 过渡帧里出现**多重曝光式的叠影**（同一艘舰在路径上留下许多半透明副本）；
- 配色是**自发光绿/青**，另一阵营版本为**红/粉**。

## 6. 与本工程的对照总表

| 量 | 原版（SC2） | 本工程现状 | 差异性质 |
|---|---|---|---|
| 相机 | 不动，背景逐帧不变 | 跟随模式随舰体平移 100 单位 | **架构差异**，白闪由此而来 |
| 去程舰体 | 全程可见，越来越透 | 剥材质后 `discard` 剔掉几何 | 带内状态不同 |
| 双前沿 | 同速、间距约 0.25 | 同速、间距 `FRONT_LEAD = 0.06` | **只差一个常数** |
| 扫过后的状态 | 透明 | 压暗 + 粗糙度拉满 | 渲染路径（要混合与顺序） |
| 线框 | 去程**没有** | 传送后自艏长出 | 段位不同，需重定 |
| 拉伸 | 拉长 + 横竖挤压，锚在中垂面 | 只拉长，去程锚艉、抵达锚艏 | 形变与锚点都不同 |
| 拉伸起点 | 前沿到 0.5 时触发 | 写死 `STRETCH_RISE` | 联动方式不同 |
| 分解残块 | 矩形/柱体，瞬态淡出 | 无 | 缺失 |
| 落点标记 | 无（地面圆环是单位选取框，不算特效） | 空间里的线框骨架 | 不计入比较 |
| 全屏白闪 | 没有 | 有（跟随模式） | **架构差异的产物** |

## 7. 待补

- **抵达段**：两个阶段都已观察（见 3.5 与 3.6）。第一阶段是"自艉向艏画出半透明舰体，快画完时半透明强度下降、留下线框"；第二阶段是"从目的地之前的逻辑面冒出已拉伸压缩的舰体，自头部先出，材质慢一步，滑入线框同时复位"。
- 抵达段中还待确认：材质填充是不是严格"几何先、材质后"；复位与滑入是否同步完成；那组"纵向光束"的含义（用户交代先不管）。
- 抵达段与去程的关系：是另一套而非反向播放——去程没有线框、以"透明消失 + 残块"收尾，抵达却以"线框"作为中间态、以"滑入复位"收尾。
- 分解残块的实现（已搁置）。
- 电流外壳那层"正多边形能量方格"的做法（用户说待定）。
- **"舰体在折跃期间是否有前向运动"**：这一个决定同时决定去程第二阶段与抵达第二阶段能否贴合（两处原版都是"固定面 + 舰体运动"）。
- **已定方向（用户决定）**：SC2 版那一支**保留全屏白闪**、相机策略不动（本工程是自由宇宙视角，模式 1/2 的相机本来就不随舰体走，只有跟随模式才随）。这样改动的范围就只剩舰体侧，命题 2、`camGate` 与白闪的整套推导继续有效。附带一个便利：白闪只覆盖 τ\* 附近（约 0.60 到 0.74），而抵达的"滑入"发生在 1.00 之后，两者不重叠，所以滑入过程不会被闪白吃掉。
