## 一、背景与目标

场景含 **5 万颗实例化小行星**，阴影 Pass 原本使用**几何着色器把每个三角形复制到立方体贴图的 6 个面**：

$$
\text{阴影几何} = N_{\text{剔除后}} \times 192 \times 6
$$

而本场景有一个关键几何事实：

- 太阳（点光源）在 `(-50, 50, -600)`，行星在 `(0, -3, 0)`；
- 恒星→行星方向 `(50,-53,600)/604` 的主轴是 **+Z**，与该轴夹角仅 **6.9°**；
- 小行星带半径 200（+offset 20 → 220），从太阳看过去的锥半角 ≈ **21.4°**；

$$
\Rightarrow\ \text{全部投射体离 +Z 轴最远 } 6.9° + 21.4° = 28.3° < 45°\ (\text{一个立方体面的覆盖})
$$

**结论：全部阴影投射体只落在 1 个面里，其余 5 个面完全是空的。**

**目标**：只渲染那 1 个面，把阴影几何从 `×6` 降到 `×1`（**6× 削减**），且：
- 保持 17.A 的 **A（相机视锥剔除）+ C（光锥判据剔除）** 完整不变；
- 采样端回到单图，精度与分辨率（4096）不变。

inline std::vector<glm::mat4> gRockMatrices;        // 全量 5 万实例矩阵(CPU)

inline std::vector<glm::mat4> gShadowVisible;       // C：能投影到可见面
inline unsigned int rockShadowVisibleCount = 0;

// 双层方案遗留（现停用，保留作骨架）
inline bool shadowStaticDirty = true;
inline unsigned int depthDynFBO = 0, depthDynMap = 0;

### 2.2 剔除工具（`Procedural.h/.cpp`，声明在 .h、实现在 .cpp）

```cpp
struct FrustumPlanes { glm::vec4 p[6]; };           // xyz=法线, w=距离
FrustumPlanes ExtractFrustum(const glm::mat4& m);   // Gribb-Hartmann 提平面
bool SphereInFrustum(const FrustumPlanes& fp, const glm::vec3& c, float r);   // A 判据
bool CanCastVisibleShadow(const FrustumPlanes& fp, const glm::vec3& lightPos, const glm::vec3& p); // C 判据
```

> 提平面时**只归一化法线(3D)**，不能用 `glm::normalize(vec4)`（会让球测试的 `+r` 量纲错）。

### 2.3 阴影 shader 组（`00_SpaceShip/depth_point3.0/`）

| 文件 | 作用 |
|---|---|
| `depth_point_ver2.2.shader` | 顶点：`instanced` 分支取 `aInstanceMatrix` 或 `model`；输出世界位置的 clip 形式 |
| `depth_point_geo.shader` | **几何：按 `faceIndex` 只写 1 面**（或 -1 = 全 6 面） |
| `depth_point_frag.shader` | 片元：`gl_FragDepth = length(FragPos - lightPos) / far_plane` |

### 2.4 采样端（4 个 `*2.0` shader）

`defer_light_ssao_frag2.0.shader` / `planet_frag2.0.shader` / `spaceship_frag2.0.shader` / `ring_frag2.0.shader`，各含：

```glsl
uniform samplerCube depthMap;
uniform samplerCube depthDynMap;          // 双层遗留，现已不参与
float ShadowDepthMin(vec3 dir) {
    return texture(depthMap, dir).r;      // 单层
}
```

## 三、启动阶段（只跑一次）

| 顺序 | 代码 | 产出 |
|---|---|---|
| 1 | `RocksModelMatricesInit(amount, rock)` | 5 万实例矩阵 → `gRockMatrices`；每实例包围球 → `gRockSpheres`；建 `rockInstanceVBO`（`GL_DYNAMIC_DRAW`），并按 **location 3~6 + divisor 1** 绑到 rock 各 mesh 的 VAO |
| 2 | `DepthCubeMapInit()` | 建 **4096 cubemap**（6 面、`GL_DEPTH_COMPONENT`）+ `depthCubeFBO`，用 `glFramebufferTexture` **分层挂载**（供 GS 的 `gl_Layer` 选面） |
| 3 | `Shader simpleDepthShader(VS, FS, GS)` | 阴影三件套编译链接（GS 含 `faceIndex`） |
| 4 | 各 shader `setInt(...)` | 纹理单元绑定（`depthMap` = 前向 9 / 光照 4；`depthDynMap` = 10，现已无实际作用） |

## 四、每帧主循环的程序流

### ① 输入与物理

```cpp
processInput(window);
ship.Update(deltaTime);
if (currentMode == MODE_FOLLOW) { /* 相机位置/朝向更新 */ }
```

> **follow 相机块必须在剔除之前**执行，否则剔除用的是上一帧相机（我们曾修过这个 1 帧错位）。

### ② `RockViewFrustumCull(window, pointSunPositions)` —— 纯 CPU，只算集合、不画东西

```cpp
int cw, ch; glfwGetFramebufferSize(window, &cw, &ch);
float cAspect = (float)cw / (float)ch;
glm::mat4 cullProj = glm::perspective(glm::radians(camera.Fov), cAspect, 0.1f, 2000.0f);
glm::mat4 cullView = camera.GetViewMatrix();
FrustumPlanes fp = ExtractFrustum(cullProj * cullView);

gVisible.clear();  gShadowVisible.clear();
for (size_t i = 0; i < gRockSpheres.size(); ++i) {
    glm::vec3 c = glm::vec3(gRockSpheres[i]);
    float r = gRockSpheres[i].w;
    if (SphereInFrustum(fp, c, r))                 gVisible.push_back(gRockMatrices[i]);        // A
    if (CanCastVisibleShadow(fp, lightPos, c))     gShadowVisible.push_back(gRockMatrices[i]);  // C
}
rockVisibleCount       = (unsigned int)gVisible.size();
rockShadowVisibleCount = (unsigned int)gShadowVisible.size();
```

- **A 判据**：包围球是否与相机视锥相交（给 G-Buffer 用）；
- **C 判据**：光源→球心射线是否"越过该小行星之后"进入相机视锥（是否能投影到可见面，给阴影用）；
- 两者理论关系：`C ⊇ A`（"能投影"包含"能看见"）。
- **本步骤与 17.A 完全一致，未被本次阴影改动触及。**

### ③ 阴影 Pass —— 本次改动的核心

```cpp
// 1) 投影矩阵（aspect=1，因为立方体面是方的）
glm::mat4 shadowProj = glm::perspective(
    glm::radians(90.0f), 1.0f, shadow_near, shadow_far);

// 2) 建 6 个面矩阵 + 绑 FBO + 清屏
std::vector<glm::mat4> shadowTransforms;
ShadowPassBegin(depthCubeFBO, SHADOW_WIDTH, shadowProj, shadowTransforms, pointSunPositions);
//   ├─ push 6 个 shadowProj * lookAt(lightPos, lightPos + 面轴向, 面上方向)
//   ├─ glViewport(0, 0, 4096, 4096)
//   ├─ glBindFramebuffer(GL_FRAMEBUFFER, depthCubeFBO)
//   ├─ glDepthMask(GL_TRUE); glClearDepth(1.0)
//   └─ glClear(GL_DEPTH_BUFFER_BIT)   ← 分层附件：一次清掉 6 个面

// 3) 只写几何所在的那 1 个面
simpleDepthShader.use();
simpleDepthShader.setInt("faceIndex", StaticShadowFace(pointSunPositions, planetPosition));
for (unsigned int i = 0; i < 6; ++i)
    simpleDepthShader.setMat4("shadowMatrices[" + std::to_string(i) + "]", shadowTransforms[i]);
simpleDepthShader.setFloat("far_plane", shadow_far);
simpleDepthShader.setVec3("lightPos", pointSunPositions);

// 4) 小行星：上传 C 集合 → 按 C 数量绘制
if (!gShadowVisible.empty()) {
    glBindBuffer(GL_ARRAY_BUFFER, rockInstanceVBO);
    glBufferSubData(GL_ARRAY_BUFFER, 0,
        gShadowVisible.size() * sizeof(glm::mat4), gShadowVisible.data());
}
simpleDepthShader.setBool("instanced", true);
for (unsigned int i = 0; i < rock.meshes.size(); i++) {
    glBindVertexArray(rock.meshes[i].VAO);
    glDrawElementsInstanced(GL_TRIANGLES,
        (GLsizei)rock.meshes[i].indices.size(), GL_UNSIGNED_INT, 0, rockShadowVisibleCount);
    glBindVertexArray(0);
}

// 5) 行星
simpleDepthShader.setBool("instanced", false);
glm::mat4 sdModel = glm::mat4(1.0f);
sdModel = glm::translate(sdModel, planetPosition);
sdModel = glm::scale(sdModel, planetScale);
simpleDepthShader.setMat4("model", sdModel);
planet.Draw(simpleDepthShader);

// 6) 飞船
simpleDepthShader.setMat4("model", ship.GetModelMatrix());
spaceship.Draw(simpleDepthShader);

glBindFramebuffer(GL_FRAMEBUFFER, 0);
glCullFace(GL_BACK);
```

**与 17.A 的差异只有三处**：
1. `ShadowPassRender` → `ShadowPassBegin`（多传目标 `fbo` 与 `res`，便于指定渲染目标并清屏）；
2. **新增一行** `setInt("faceIndex", StaticShadowFace(...))`；
3. 绘制集合仍是 `gShadowVisible` / `rockShadowVisibleCount`（**不变**），区别只是不再画 6 个面。

### ④ G-Buffer Pass（未变）

```cpp
gBufferAsteroidShader.use();
gBufferAsteroidShader.setMat4("projection", projection);
gBufferAsteroidShader.setMat4("view", view);
// ... 绑材质纹理 ...
if (!gVisible.empty()) {
    glBindBuffer(GL_ARRAY_BUFFER, rockInstanceVBO);
    glBufferSubData(GL_ARRAY_BUFFER, 0, gVisible.size() * sizeof(glm::mat4), gVisible.data());
}
for (unsigned int i = 0; i < rock.meshes.size(); i++) {
    glBindVertexArray(rock.meshes[i].VAO);
    glDrawElementsInstanced(GL_TRIANGLES,
        (GLsizei)rock.meshes[i].indices.size(), GL_UNSIGNED_INT, 0, rockVisibleCount);
    glBindVertexArray(0);
}
```

> ⚠️ **实例缓冲是阴影 Pass 与 G-Buffer 共用的**，所以每个 Pass 绘制前都要把自己的子集重新 `glBufferSubData` 一次——这是"两处上传"存在的原因，不是冗余。

### ⑤ 光照 / 前向 / 星环（采样端）

```glsl
float closestDepth = ShadowDepthMin(fragToLight);   // 实为 texture(depthMap, dir).r
```

## 五、GPU 侧配套机制

### 5.1 几何着色器：按 `faceIndex` 只写 1 面

```glsl
uniform mat4 shadowMatrices[6];
uniform int  faceIndex;          // -1 = 全 6 面；0..5 = 只写该面
out vec4 FragPos;
void main() {
    int f0 = (faceIndex < 0) ? 0 : faceIndex;
    int f1 = (faceIndex < 0) ? 5 : faceIndex;
    for (int face = f0; face <= f1; ++face) {
        gl_Layer = face;                                  // ← 决定写入哪个立方体面
        for (int i = 0; i < 3; ++i) {
            FragPos = gl_in[i].gl_Position;
            gl_Position = shadowMatrices[face] * FragPos;
            EmitVertex();
        }
        EndPrimitive();
    }
}
```

- `gl_Layer` 配合**分层挂载**的 FBO，把这一批三角形写入指定面；
- 传 `faceIndex = 4`（+Z）时，几何量为原来的 **1/6**。

### 5.2 未使用的 5 个面为什么不会造成伪影

`glClear(GL_DEPTH_BUFFER_BIT)` 作用在**分层附件**上 → **一次把 6 个面全清成 1.0（最远）**，之后只有被选中的那 1 个面被写入。于是未使用的 5 个面读出的是"最远"，等价于"该方向没有遮挡物"——**不会被误判为阴影**。

### 5.3 采样端为什么不用改

- 深度编码未变：仍是 `length(fragPos - lightPos) / far_plane`；
- 采样方式未变：仍是 `texture(depthMap, fragToLight)` —— 立方体贴图按**方向**自动选面；
- 而所有接收者（火星、尘埃星环、小行星、飞船）都在几何锥内 → 其 `fragToLight` 方向必然命中**被渲染的那一面** → 读到有效数据。

## 六、相对 17.A 的净差异

| 项 | 17.A | 19.0（本次） |
|---|---|---|
| G-Buffer 剔除（A） | `gVisible` / `rockVisibleCount` | **相同** |
| 阴影剔除（C） | `gShadowVisible` / `rockShadowVisibleCount` | **相同** |
| 阴影面数 | **6 面**（GS 复制） | **1 面**（`faceIndex`） |
| 阴影几何/帧 | `N×192×6` | `N×192×1` |
| 采样端 | 单图 | 单图（helper 单层化后一致） |
| 精度 | 4096 / 0.23 单位每 texel | **相同** |
| 飞船投影 | ✓ | ✓ |

**净改动 = 主循环阴影块（换 Begin + 加 faceIndex）+ GS 加 uniform + 4 个 helper 单层化。**

## 七、数据流总结

```
[启动一次]
  RocksModelMatricesInit → gRockMatrices(5万矩阵) / gRockSpheres(包围球) / rockInstanceVBO
  DepthCubeMapInit       → depthCubeMap(4096 cubemap) + depthCubeFBO(分层)

[每帧]
  输入 + ship.Update + follow 相机
        │
        ▼
  RockViewFrustumCull(CPU)
        ├─→ gVisible        (A: 相机看得见)        ─→ rockVisibleCount
        └─→ gShadowVisible  (C: 能投影到可见面)     ─→ rockShadowVisibleCount
        │
        ▼
  阴影 Pass
        ShadowPassBegin: 6 面矩阵 + 绑 FBO + 清 6 面
        faceIndex = StaticShadowFace(太阳, 行星)      ← 只写 1 面
        上传 gShadowVisible → 画 rockShadowVisibleCount
        + 行星 + 飞船
        │
        ▼
  G-Buffer Pass
        上传 gVisible → 画 rockVisibleCount
        │
        ▼
  光照 / 火星 / 飞船 / 星环 ──采样──→ texture(depthMap, fragToLight)
```

## 八、前提与未来注意

1. **不变量**：本优化成立的前提是"**所有阴影投射体都落在光源的某一个 90° 面内**"。
   本场景：锥半角 28.3° < 45°，成立。
   **以后若引力系统把物体撒开到多个面**，把 `faceIndex` 从"1 面"扩成"2~6 面"即可（同一个 GS，改 `f0/f1`），不会推倒重来。建议在该行旁留注释写明此前提。
2. **停用的遗留**：
   - 双层方案（静态烘焙 + 动态层 + `min` 采样）已停用，`depthDynMap` / `depthDynFBO` / `DYN_SHADOW_SIZE` / `shadowStaticDirty` 与那 4 处绑定保留为"可切换骨架"（约 25MB 显存），将来如需"每帧阴影几何≈0"可切回；
   - LOD（`lodEnabled = false`）同样保留为骨架。
3. **收益语气要准确**：本次是"结构性 6× 削减"（保留未来加物体的余量），**不等于当帧率立刻大涨**；实际帧时间收益取决于当前瓶颈（几何/GS 或像素/ALU）。
