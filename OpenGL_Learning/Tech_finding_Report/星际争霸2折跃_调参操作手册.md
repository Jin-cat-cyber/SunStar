## 0. 三十秒版本

1. 四份头文件分工：**时间与几何**在 `WarpSC.h`，**观感常量**在 `WarpTuning.h`，**光柱**在 `WarpPillar.h`，
   **碎屑**在 `WarpDebris.h`（只有 `24.0` 用）。`SpaceShip24.A.cpp` 里**不放新字面量**。
2. 绝大多数诉求改 `WarpSC.h` 顶部的**六个主旋钮**（`T_CHARGE` / `T_VANISH` / `GROW_SPAN` / `HOLD_TIME` /
   `PILLAR_LEAD` / `T_APPEAR`），其余全是派生量自动跟随。
3. 看片时把 `TIME_SCALE` 调小（它是**整段慢放**，不动任何几何关系）；**交版前必须回 1.0**。
4. **`TIME_SCALE` 现在是 `0.5f`**，不是 1.0 —— 你上一次看片留下的，别忘了。

## 1. 一次改动的完整流程

| 步 | 做什么 | 注意 |
|---|---|---|
| 1 | 在 VS 里改常量（`Ctrl+F` 常量名） | 中文注释用 VS 保存时**选"中文简体 (GB2312) - 代码页 936"**，不要另存为 UTF-8：工程没有 `/utf-8`，MSVC 按系统 ANSI 解码，存成 UTF-8 会让所有中文注释变乱码，极端情况下某个字节撞上 `0x5C` 还会把下一行吞掉 |
| 2 | 重编（`Release|x64` 看画面、`Debug|x64` 跑自测） | Debug 启动时控制台应出现 `===== ... self test =====`；**没有这行说明宏没开、自测是空函数** |
| 3 | 进游戏，切到**跟随模式**，按 `T` | 白闪、FOV 冲击、抖动**只在跟随模式生效**（`camGate = (currentMode == MODE_FOLLOW) ? 1 : 0`）。用固定/WASD 相机看这一段会以为效果没做 |
| 4 | 要看细节就慢放：`TIME_SCALE = 0.2f` | 慢放不改时间线本身，只把同一条曲线拉长；判"时长对不对"必须回到 1.0 |
| 5 | 再按 `T` 要等冷却 | `Globals.h` 的 `WARP_COOLDOWN = 6.0f`，**自 τ\* 起算**，不是自按键起算 |

**低帧率陷阱（重要）。** 折跃时钟每帧走

```cpp
dt = min(frameDt, DT_MAX);   dt *= TIME_SCALE;      // WarpSC.h 的 advance
```

`DT_MAX = 1.0f / 30.0f`。**机器跑不到 30 fps 时，折跃会比真实时间慢**（速率约等于 `fps / 30`）：
帧率 15 就慢一半，看起来像"所有时长都被拉长了"。60 fps 的机器则完全真实。
它本来是"尖峰保护"，被当成了限速器。**想让低帧率机器也按真实时长播，把 `DT_MAX` 改成 `0.1f`**
（代价：一次 100 ms 的卡顿会让折跃跳掉 0.1 秒）。判定"我这次是不是被它坑了"的办法是看帧率，
不是看画面。

## 2. 参数住在哪

| 文件 | 管什么 | 编码 | 谁用 |
|---|---|---|---|
| `src/WarpSC.h` | 时间线、几何、幅度、通道表、各效果的包络 | GBK 无 BOM | `24.0` / `24.A` |
| `src/WarpTuning.h` | 喂给 GPU 的观感常量：颜色、强度、频率、宽度、厚度 | GBK 无 BOM | `24.0` / `24.A` |
| `src/WarpPillar.h` | 光柱运动学（出生、伸长、漂移、包络） | GBK 无 BOM | `24.A` |
| `src/WarpDebris.h` | 碎屑运动学 | GBK 无 BOM | `24.0`（`24.A` 里已退场） |
| `src/Globals.h` | `WARP_DISTANCE` / `WARP_COOLDOWN` / `gShipBowOffset` / `gPlanetRadius` | GBK 无 BOM | 全局 |
| `src/SpaceShip24.A.cpp` | **只放"常量乘运行时量"的现算**（如 `shipBoundR * U_SHELL_WORLD_K`） | UTF-8 BOM | 活跃版本 |

**规矩**：新增可调量一律进前三份头文件，`24.A.cpp` 里只做乘法。
理由是调试方式不同 —— 前三类是"看数字/看自测"，第四类是"看画面"，混在一起会让每次调色都要翻过一堆时间线常量。

## 4. 诉求索引：想让 X 变成 Y，动哪个数

### 4.1 节奏与时长

| 想要 | 动它 | 现在 | 怎么动 | 副作用 |
|---|---|---|---|---|
| 整段快/慢一点看细节 | `TIME_SCALE` | `0.5` | 填 `0.2` 看细节 | **不是真时长**，几何关系完全不变；交版回 1.0 |
| 后半段整体收紧 | `HOLD_TIME` | `2.87` | 这是**骨架静止等待**的长度；调到 `1.5` 后半段整体前移 1.37 | 光柱出现、材质填充、`T_TOTAL` 全跟着走；约束见 §6 |
| 蓄能期更长（电弧看更久） | `T_CHARGE` | `1.35` | 加大 | τ\* 整体后移，**前半段所有量（白闪/前冲/拉伸/扫描起点）跟着平移** |
| 骨架长得更快/更慢 | `GROW_SPAN` | `0.47` | 这是**时长** | 影响 `WIRE_GROW_TIME`、`T_WIRE`、光柱出现时刻 |
| 材质填充更快/更慢 | `FILL_TIME` | `0.30` | 加大 | 滑入、拉伸复原、前沿退回、`SOLIDIFY_TIME` **全部**与它同期；`WIRE_TAIL` 会自动减少 |
| 骨架余韵留更久 | `T_APPEAR` | `0.63` | 加大 | 只影响 `T_TOTAL` 与骨架淡出；`FILL_TIME` 不动则填充速度不变 |
| 光柱更早/更晚于材质 | `PILLAR_LEAD` | `0.10` | 加大就早更多 | 唯一控制"光柱先于材质"的量 |
| 去程扫描更快 | `SCAN_TIME` | `0.60` | 减小 | 前沿扫得更快；同时是"外壳归零进度 0.18"的换算基准 |

## 附：一句话记住每份文件

- **`WarpSC.h` 管"什么时候发生、多大"** —— 时间、几何、幅度、包络。
- **`WarpTuning.h` 管"看起来什么样"** —— 颜色、强度、频率、宽度、厚度。**调色只翻这一个文件。**
- **`WarpPillar.h` 管"光柱怎么动"** —— 出生、伸长、漂移、生死。三个方向量（伸长 / 轴向漂移 / 径向漂移）**互相独立**。
- **`WarpDebris.h` 管"碎屑怎么动"** —— 只有 `24.0` 用。
- **`24.A.cpp` 只做乘法** —— 常量乘运行时量，不放新数字。
