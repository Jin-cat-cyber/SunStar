## 〇、本文要解决什么

在讨论大气散射、阴影、延迟/前向渲染时，出现了一批**反复出现、且非常典型**的理解偏差。本文用标准定义 + 严谨公式把它们一次性讲清，并统一到**"两条腿"求值模型**下。

**讨论中实际出现的 8 个偏差**（见第七节详述）：
1. 以为大气散射要"从点光源发射射线"；
2. 以为"视线求交 = 判断片段可见性"；
3. 以为消光包含了"光源→采样点"那一段；
4. 以为"光到片段的信息"是一个值；
5. 以为前向/延迟的区别是"数据是否统一发送给 GPU"；
6. 以为延迟渲染对"重复物体"有帮助；
7. 以为"光线步进"是与前向/延迟并列的另一种管线；
8. 以为大气散射里也有"从光源出发"的计算。

## 一、统一框架：渲染方程与"两条腿"

### 1.1 渲染方程（Kajiya, 1986）

对**表面**，出射辐射度等于自发光加所有入射方向的贡献：

$$
L_o(x,\omega_o) \;=\; L_e(x,\omega_o) \;+\; \int_{\Omega^+} f_r(x,\omega_i,\omega_o)\,L_i(x,\omega_i)\,(\mathbf n\cdot\omega_i)\,d\omega_i
$$

| 符号 | 含义 |
|---|---|
| $x$ | 表面点 |
| $\omega_o$ | 出射方向（指向眼睛） |
| $\omega_i$ | 入射方向 |
| $f_r$ | **BRDF**：把入射方向的光重新分配到出射方向 |
| $L_i$ | 入射辐射度 |
| $\mathbf n\cdot\omega_i$ | 余弦项（投影面积） |

### 1.2 物理路径 vs 求值方向（**第一个关键认知**）

- **物理上**：光子从光源出发 → 在介质/表面发生散射吸收 → 到达眼睛；
- **渲染上**：我们**不追光子**，而是**从眼睛反向求值**——"沿这条视线，有多少辐射度最终到达眼睛？"

$$
\boxed{\text{物理相同、求值反向、覆盖范围可裁剪}}
$$

这不是两种物理，而是**同一条路径的两种求值方向**（gather vs scatter）。对**直接光**而言两者结果应当一致。

### 1.3 "两条腿"模型

物理路径"光 → 片段 → 人眼"在渲染里被**拆成两条腿分别求值**：

$$
L_o(x,\omega_o) \;=\; \underbrace{T(x\!\to\!\text{eye})}_{\text{腿A：出射衰减}}\;\int_{\Omega} f(x,\omega_i,\omega_o)\;\underbrace{L_i(x,\omega_i)}_{\text{腿B：入射光}}\;\cos\theta_i\,d\omega_i
$$

**腿 B（光 → 点）** 不是一个标量，而是一个**方向分布**，且其中包含可见性与光路衰减：

$$
L_i(x,\omega_i) \;=\; \underbrace{V(x,\omega_i)}_{\text{可见性（阴影）}}\;\cdot\;\underbrace{T(x\!\to\!\text{光源})}_{\text{光路透射}}\;\cdot\;\Phi_{\text{light}}
$$

**腿 A（点 → 眼）** 除给出出射方向 $\omega_o$，还附带出射衰减：

$$
T(x\!\to\!\text{eye}) \;=\; \exp\!\Big(-\!\int_x^{\text{eye}}\sigma_t\,ds\Big)
$$

**耦合项 $f(\omega_i,\omega_o)$ 同时依赖两个方向** —— 这是"视觉信息"随视线变化而变化的**唯一来源**：

- 表面：$f$ = BRDF（高光叶瓣、粗糙度、金属度）；
- 介质：$f$ = 相位函数 $p(\cos\theta)$，$\cos\theta=\hat V\cdot\hat L$（米氏前向峰即由此而来）。

> **一句话**：不是"算出光的信息、换个角度看它"；**换视线方向会改变 $f$ 的权重**，这才是视觉结果变化的原因。

## 二、表面与介质：点求值 vs 线积分

| | 表面 | 介质（体积） |
|---|---|---|
| 厚度 | 零厚度 | 有厚度 |
| 处理对象 | **一个点** | **一整条射线穿过的那段体积** |
| 数学形式 | **点求值**：方向积分（BRDF） | **线积分**：沿射线累加 |
| 工程对应 | 火星、飞船、小行星 | 大气散射、尘埃星环、恒星日冕 |

### 2.1 介质：辐射传输方程与单次散射

介质沿视线的出射辐射度（简化到**单次散射**）：

$$
L_{out} \;=\; \underbrace{T(P\!\to\!E)\,L_{bg}}_{\text{背景透过}} \;+\; \int_{t_0}^{t_1} \underbrace{T(P\!\to\!x)}_{\text{腿A 内}}\;\underbrace{\sigma_s(x)}_{\text{散射系数}}\;\underbrace{\Phi_{sun}\,p(\theta_x)}_{\text{腿B + 耦合}}\;\underbrace{T(x\!\to\!\text{sun})}_{\text{腿B 光路}}\;ds
$$

**透射率（Beer–Lambert）**：

$$
T(a\!\to\!b)=\exp\!\Big(-\!\int_a^b \sigma_t\,\rho\,ds\Big),\qquad \sigma_t=\sigma_s+\sigma_a
$$

### 2.2 相位函数（介质的"BRDF"）

$$
p_R(\theta)=\frac{3}{16\pi}\big(1+\cos^2\theta\big)
\qquad
p_M(\theta)=\frac{1}{4\pi}\frac{1-g^2}{\big(1+g^2-2g\cos\theta\big)^{3/2}}
$$

- 瑞利：前后对称 → 柔和蓝白边；
- 米氏（$g>0$ 前向峰）：背光侧的透光弧。

### 2.3 Ray Marching 的准确定位（**偏差 7**）

> **Ray Marching 不是一种渲染管线，而是"线积分没有解析解时，沿射线打点做数值积分"的算法手段。**

它可以用于：
- **视线方向**（体积散射，本工程的大气/星环）；
- **光源方向**（光路透射率 $T(x\to\text{sun})$ —— 本工程曾实现后放弃的"光程消光版"就是**嵌套 ray marching**：每条视线上、每个采样点再发一条 ray）。这也解释了它为什么更耗性能。

## 三、前向渲染 vs 延迟渲染（**偏差 5、6**）

### 3.1 真正的区别：光照在哪算、算几次

**先纠正**：两者的 **CPU→GPU 数据提交方式是一样的**（每帧提交同样的 draw call、同样的 uniform；静态 VBO 都在初始化时上传一次）。**"是否统一发送数据"不是它们的区别。**

真正的区别：

| | 前向 Forward | 延迟 Deferred |
|---|---|---|
| 光照计算位置 | **物体片元着色器内** | **全屏 pass，按屏幕像素** |
| 光照计算次数 | 物体数 × 覆盖像素（**超绘照付**） | **每屏幕像素一次** |
| 多光源扩展性 | 差 | 好（与物体数解耦） |
| 屏幕空间效果（SSAO 等） | 需额外输出几何信息 | **直接读 G-Buffer** |
| MSAA | 天然支持 | **困难**（MRT + 延迟光照需处理采样解析） |
| 透明/体积 | 正常 | **不行**，必须回前向 |
| 带宽 | 低 | 高（多 MRT） |

### 3.2 "中继/打包"的准确含义

"打包一次、多用多次"确实存在，但对象是 **GPU 内部的 G-Buffer**，不是 CPU→GPU 的传输：

```
几何 pass ──写一次──▶ G-Buffer ──被读多次──▶ 延迟光照 / SSAO / 后续屏幕空间效果
```

### 3.3 延迟渲染的收益与"重复物体"无关（**偏差 6**）

| 问题 | 正确工具 |
|---|---|
| 物体**重复**、数量巨大 | **实例化（Instancing）** |
| **光源多**、光照复杂 | **延迟渲染** |
| **过度绘制**严重 | 延迟渲染（光照只算可见层） |
| 多个屏幕空间效果复用几何 | 延迟渲染（G-Buffer） |

### 3.4 本工程的混合管线

| 内容 | 走哪条 |
|---|---|
| 小行星（不透明、实例化、量大） | **延迟** |
| 火星、飞船（不透明、材质复杂） | **前向** |
| 大气、尘埃星环、镜头光晕（半透明/体积） | **前向 + 加法混合** |

> 这正是"延迟处理不了透明/体积"的直接体现。

## 四、屏幕空间的本质：2D 平面上的"3D 信息载体"是什么（**偏差 2**）

### 4.1 术语对照

| 通俗说法 | 标准术语 |
|---|---|
| 带 3D 信息的那张图 | **G-Buffer**；一类 **screen-space / image-space 表示** |
| 俗称 | **"2.5D"**（2D 图像 + 每像素深度/几何） |
| 每个像素存的东西 | **屏幕空间采样**（位置/法线/材质…） |
| 最本质的说法 | **plenoptic function（全光函数）的一个二维切片** |

**全光函数**（Adelson & Bergen, 1991）$P(\theta,\varphi,\lambda,V_x,V_y,V_z,t)$ 描述"任意位置、任意方向、任意波长、任意时刻"的辐射度。渲染出的一张图 = **固定视点、固定时刻、对波长积分**后的一个二维切片：

$$
\text{Image}(u,v) \;=\; L\big(\text{eye},\ \omega(u,v)\big)
$$

**即：每个像素 = "从眼点沿某方向"的一次辐射度采样。**

### 4.2 三个必须记住的限定

| 限定 | 含义 | 后果 |
|---|---|---|
| **视角相关** | 换相机整张 G-Buffer 就变了 | 它不是场景表示 |
| **单层** | 只存该视角下**最前面的那个面** | 背面/被遮挡物**完全不在里面** |
| **有损** | 分辨率有限 | 亚像素几何丢失（= 远距离闪点噪点的根因） |

> **结论**：它是"**屏幕空间的缓存/采样**"，**不是**场景的 3D 表示。

## 五、片元在流水线中的角色

- **光栅化**：由投影 + 光栅化决定哪些**片段**被覆盖；属性（位置/法线/UV）是**插值**得到的；视线是隐含的（需要时可反投影重建）。
- **体渲染**：显式**重建视线射线**，与几何体求交，沿射线积分。
- **片元是"最终成像的采样点"，但不总是"计算发生的点"**——体积情形下计算发生在整条射线上。

## 六、本工程各 pass 在"两条腿"模型下的映射

| Pass | 腿 B（光→点） | 腿 A（点→眼） | 耦合 $f$ |
|---|---|---|---|
| **延迟光照**（小行星） | 点光衰减 + **cubemap 阴影**（可见性） | — | Cook-Torrance BRDF |
| **火星 / 飞船（前向）** | 点光衰减 + cubemap 阴影 + IBL | — | Cook-Torrance BRDF + rim |
| **大气散射** | ⚠️ **被省掉**（无 $T(x\to\text{sun})$） | Beer–Lambert 累加 $T(\text{cam}\to x)$ | 相位函数 $p_R/p_M(\cos\theta)$ |
| **尘埃星环** | cubemap 阴影 + `lit` 近似 | Beer–Lambert | `outward·sunDir` 近似（无真相位函数） |
| **阴影系统** | **唯一"从光源出发"的计算**：cubemap 由光源位置渲染 | — | — |

> 这张表解释了大气那版"亮暗均匀、立体感弱"的根因：**少了一条腿（腿 B 的透射率）**。

## 七、理解偏差清单（讨论中真实出现）

| # | 偏差表述 | 正确认识 |
|---|---|---|
| 1 | "从**点光源**发射的射线与球壳、火星求交" | 射线是**从相机（视线）**出发；求交两次：**大气壳**（定 march 区间）+ **火星球**（截断终点）。且**光是按方向光处理的**（传 `sunDir` 方向，不是位置） |
| 2 | "视线求交是为了判断片段可见性" | 可见性/遮挡是**深度测试与光栅化**的职责；求交是**给体积积分定边界**：打空 → `discard`；壳 → `[tEnter,tExit]`；球 → `tEnd` 截断 |
| 3 | "计算了从点光源到球壳发生的吸收" | **没有**。当前只算"相机→采样点"的透射率；"光源→采样点"的 $T(x\to\text{sun})$ **被省掉了**（那是被放弃的"光程消光版"） |
| 4 | "光到该片段产生的信息"（当作一个值） | 是**方向分布** $L_i(x,\omega_i)$；且输出由 $f(\omega_i,\omega_o)$ **耦合**两个方向，不是"换个角度看同一个值" |
| 5 | "延迟与前向的区别是数据是否统一发送给 GPU" | 区别是**光照在哪算、算几次**；数据提交方式两者相同 |
| 6 | "延迟渲染对大的重复性场景有帮助" | 重复物体靠**实例化**；延迟渲染解决的是**多光源 / 超绘 / 多屏幕空间效果复用** |
| 7 | "光线步进"是与前向/延迟并列的管线 | 它是**线积分的数值手段**；可用于视线方向，也可用于光源方向（嵌套） |
| 8 | "大气散射里也有从光源出发的计算" | 只有**阴影系统**有（cubemap 由光源位置渲染）；大气散射**没有**任何从光源发出的射线 |

## 八、术语速查

| 术语 | 含义 |
|---|---|
| **Fragment（片段）** | 光栅化产生的候选像素，携带插值后的属性 |
| **Framebuffer** | 光栅化目标（颜色/深度/模板等附件） |
| **MRT** | Multiple Render Targets，一次绘制写多个颜色附件（G-Buffer 的基础） |
| **G-Buffer** | 存几何/材质属性的多张屏幕空间纹理 |
| **Screen-space / image-space** | 以屏幕像素为索引的数据与算法 |
| **2.5D** | 2D 图像 + 每像素深度/几何的俗称 |
| **Plenoptic function（全光函数）** | 描述任意位置/方向/波长/时刻辐射度的函数；一张图是其二维切片 |
| **BRDF** | 双向反射分布函数 $f_r(\omega_i,\omega_o)$（表面） |
| **Phase function（相位函数）** | 介质中的方向散射分布 $p(\cos\theta)$ |
| **Beer–Lambert** | 透射率 $T=\exp(-\int\sigma_t\,ds)$ |
| **Ray marching** | 沿射线打点做线积分的数值方法 |
| **Instancing** | 一次 draw call 绘制大量同一网格的不同变换 |
| **Overdraw** | 同一像素被多次着色（前向渲染的额外成本） |
| **Rendering Equation** | $L_o=L_e+\int f_r L_i\cos\theta\,d\omega$ |
| **RTE** | Radiative Transfer Equation，介质中的辐射传输方程 |
