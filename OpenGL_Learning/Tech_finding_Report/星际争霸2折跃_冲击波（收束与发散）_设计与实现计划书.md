## 0. 结论摘要

折跃的两个阶段各有一道**平面圆环状**的冲击波。两道的共同点是：

1. 环躺在一张**垂直于舰体纵轴**的平面里，圆心落在那条轴上；
2. 环半径沿半径方向**匀速**推进，两端钳死；
3. 亮度 = 固定增益 × **能量律** × **窗口包络**，包络在窗口两端**精确归零**；
4. 可见的那条亮带是片元按半径"切"出来的，世界宽度恒定；
5. 色相由**窗口进度**驱动，与波峰同步移动；
6. 波前附近做**屏幕空间径向扭曲**，需要可采样的深度纹理。

去程波从 50 收到 0，抵达波从 0 散到 70。两波的时间窗互不相交，因此同一帧最多一道活着，
`WarpShockDraw` 用一次三元选择取半径即可，不需要任何"同时画两道"的合成逻辑。

## 1. 形态判定：为什么是平面圆环

### 1.1 三次形态重构

第一版做成**圆柱壳**（沿纵轴有轴向半长 `S_HALF_LEN_K`），侧视读作一道竖直的墙；第二版做成**球壳**，
观感像气泡从舰体上鼓出来；第三版改成**平面圆环**，与参考画面的水波式同心圆一致。
三次都以参考画面为准，因此几何定义不写在这里"推导"，而是**照抄参考**，只把它的两个自由度讲清楚：

- 环所在的平面**垂直于舰体纵轴**（不是垂直于视线，也不是任意朝向）；
- 圆心在**那条纵轴上**。

这两句话一旦确定，几何就没有别的自由度了：环是"平面上的圆"，它的位置由平面决定、大小由半径决定。
实现上不需要任何朝向参数，因为锚点矩阵的 Y 轴就是纵轴、原点就是环心：

```
去程：axisModel = shipWireModel     （环心 = 舰体逻辑位置，平面过舰体中心，把舰体拦腰切开）
抵达：axisModel = 光柱那张逻辑面     （环心 = 逻辑面原点，与光柱出生面同一张面）
```

### 1.2 平面圆环的固有代价

**命题 1**：零厚度的平面圆环，当视线方向落在环所在平面内时，环在屏幕上的投影退化为一条线段。

**证明**：环上的点集是 $\{(c + r\mathbf{u}) : \mathbf{u} \perp \mathbf{n},\ |\mathbf{u}| = 1\}$，其中 $\mathbf{n}$ 是平面法线。
把这个集合投影到任意方向 $\mathbf{d}$ 上，得到的像是长度 $2r\sqrt{1 - (\mathbf{d}\cdot\mathbf{u}^*)^2}$ 的线段，
其中 $\mathbf{u}^*$ 是与 $\mathbf{d}$ 最接近平行的面内单位向量。当 $\mathbf{d}$ 落在平面内时，
$\mathbf{d} \perp \mathbf{n}$，可取 $\mathbf{u}^* = \mathbf{d}$，于是 $\mathbf{d}\cdot\mathbf{u}^* = 1$，像的长度为 $0$。证毕。

这说明"侧对时环消失"不是数值问题，而是投影的必然结果，无法靠着色技巧消除，只能**补偿**：
片元里用 `facing = abs(dot(normalize(vNormal), V))` 在侧对时给一个亮度下限
（`S_FACING_FLOOR = 0.35`，取 0 就是"纯的"、侧看即消失）。

## 3. 时间线：两个窗口

### 3.1 去程窗口取"扫描全程"

去程窗口的两端都**不是自由参数**，而是被已有时间线钉死的：

$$t_0^{\mathrm{out}} = \texttt{FRONT\_GEO\_START} = \texttt{TAU\_STAR} - \texttt{SCAN\_TIME} \tag{1}$$

$$t_1^{\mathrm{out}} = \texttt{TAU\_STAR} \tag{2}$$

代入 $\texttt{TAU\_STAR} = \texttt{T\_CHARGE} + \texttt{T\_VANISH} = 1.35 + 0.20 = 1.55$ 与
$\texttt{SCAN\_TIME} = 0.60$，得 $t_0^{\mathrm{out}} = 0.95$、$t_1^{\mathrm{out}} = 1.55$，窗口长度 $0.60$ s。

**为什么不用 `T_VANISH` 那 0.20 s**：舰体不是蓄能完了才开始消失的，扫描从 $\texttt{FRONT\_GEO\_START} = 0.95$
就已经开始，蓄能段 $[0,\ 1.35]$ 与扫描段 $[0.95,\ 1.55]$ 是**重叠**的。若只取 $[1.35,\ 1.55]$，
则 60 单位半径对应 $60 / 0.20 = 300$ 单位每秒，30 fps 下只有 6 帧，读出来是"闪一下"而不是"一道波"。

### 3.2 抵达窗口

抵达波的起点与光柱出生面重合，终点比线框消失早 0.10 s：

$$t_0^{\mathrm{in}} = \texttt{P\_ARRIVE\_T0} = \texttt{WIRE\_GROW\_TIME} + \texttt{HOLD\_TIME} \tag{3}$$

$$t_1^{\mathrm{in}} = \texttt{T\_TOTAL} - 0.10 \tag{4}$$

代入 $\texttt{WIRE\_GROW\_TIME} = \texttt{T\_WIRE\_END} - \texttt{HOLD\_TIME} = 4.99 - 2.87 = 2.02$ 与
$\texttt{HOLD\_TIME} = 2.87$，得 $t_0^{\mathrm{in}} = 4.89$；
代入 $\texttt{T\_TOTAL} = 4.99 + 0.63 = 5.62$，得 $t_1^{\mathrm{in}} = 5.52$，窗口长度 $0.63$ s。

### 3.3 命题 2：两窗口不相交

**命题**：对一切 $\tau$，`shockOutLive(tau)` 与 `shockInLive(tau)` 不同时为真。

**证明**：`shockOutLive` 判据为 $0.95 \le \tau < 1.55$，`shockInLive` 判据为 $4.89 \le \tau < 5.52$。
两个区间都是半开区间，且 $1.55 < 4.89$，故交集为空。证毕。

这条命题是 `WarpShockDraw` 里那次三元选择的**正确性前提**：

```cpp
const float r = out ? warp_sc::shockRadiusOut(gWarp.tau)
                    : warp_sc::shockRadiusIn(gWarp.tau);
```

如果将来有人把某个窗口拉长到与另一道重叠，这段代码会**静默**地只画其中一道，不会有任何报错。

## 4. 半径运动学

### 4.1 匀速，不做缓动

$$r_{\mathrm{out}}(\tau) = R_0\left(1 - p\right), \qquad r_{\mathrm{in}}(\tau) = R_1 p,
\qquad p = \mathrm{clamp01}\!\left(\frac{\tau - t_0}{t_1 - t_0}\right) \tag{5}$$

取匀速（而不是缓入缓出）的理由有两条，都与"这是什么物理现象"有关：水波式的环在参考画面里是**匀速推进**的；
而且缓动会让"半径"与"时间"不再成正比，于是能量律 $I = r_{\mathrm{ref}}/r$ 的时间形状会**二次变形**
（见 §5），调参时无法把"什么时候变亮"与"什么时候到某半径"分开谈。

`dClamp01` 把 $p$ 钳在 $[0,1]$，因此 $\tau$ 落到窗口之外时半径不会外推成负值或超过 $R_1$ —— 这是必要的，
因为 `WarpShockDraw` 之外没有任何地方再钳一次。

### 4.2 速度

| 波 | 窗口长度 | 半径行程 | 速度 |
|---|---|---|---|
| 去程收束 | 0.60 s | 50 | $50/0.60 = 83.33$ 单位/秒 |
| 抵达发散 | 0.63 s | 70 | $70/0.63 = 111.11$ 单位/秒 |

30 fps（`DT_MAX = 1/30`，`TIME_SCALE = 1.0`）下，去程 18 帧、每帧走 2.78 单位；抵达 18.9 帧、每帧走 3.70 单位。

**`S_OUT_R0` 曾经是 60**，改成 50 的意图是让去程"更从容"：同样 0.60 s 内走更少的路，屏幕上读起来更慢。
它与另一条可能的意图**方向相反** —— 若目标是"两道波看起来一样快"，应解 $R_0/0.60 = 70/0.63$，得 $R_0 = 66.67$，
即比 60 还大。两种目标必须先说清是哪一种，再动这个数。

代价与连带项：

- 起点更靠内。淡入覆盖窗口前 0.25，即半径从 $R_0$ 走到 $0.75R_0$；$R_0 = 50$ 时是从 50 淡到 37.5，
  相对舰体横向半宽（约 8）仍有 4 倍余量，不会"贴着舰体凭空冒出来"。
- 能量律的起点亮度 $I(R_0) = 60/50 = 1.2$（原为 1.0），仅抬两成，且发生在淡入段内。

## 5. 能量律

### 5.1 指数 $P = 1$ 的来历

设波源每秒向外送出的总功率为 $\mathcal{P}$，且沿圆周方向均匀。半径为 $r$ 的波前是一个周长
$2\pi r$ 的圆，于是**单位长度上摊到的功率**是

$$I(r) = \frac{\mathcal{P}}{2\pi r} \tag{6}$$

取参考半径 $r_{\mathrm{ref}}$ 使 $I(r_{\mathrm{ref}}) = 1$，则 $1 = \mathcal{P}/(2\pi r_{\mathrm{ref}})$，
即 $\mathcal{P} = 2\pi r_{\mathrm{ref}}$。把它代回 (6)：

$$I(r) = \frac{2\pi r_{\mathrm{ref}}}{2\pi r} = \frac{r_{\mathrm{ref}}}{r} \tag{7}$$

式 (7) 的指数就是 $P = 1$。对照三维球面波：同样的总功率摊在半径 $r$ 的球面 $4\pi r^2$ 上，
$I \propto 1/r^2$，即 $P = 2$；而 $P \approx 0.6$ 对应"挂着不散"的人造观感。
**平面圆环是二维波，正确值是 $P = 1$**，这是本效果与球壳版本在数值上唯一的区别。

代码里写作

```cpp
const float q = S_REF_R / (r > 1e-3f ? r : 1e-3f);
const float k = std::pow(q, S_FALL_POW);
return (k < S_ENERGY_LO) ? S_ENERGY_LO : ((k > S_ENERGY_HI) ? S_ENERGY_HI : k);
```

分母那个 $10^{-3}$ 是防止 $r = 0$ 时除零；它只在 $r < 10^{-3}$ 时生效，而 $r$ 是有量纲的世界单位
（舰体半长 26.8），所以这个分支实际上不可达，存在的意义只是"不产生 inf"。

### 5.2 上下限的实际作用

$$I_{\max} = \texttt{S\_ENERGY\_HI} = 8 \quad\Longleftrightarrow\quad r = \frac{60}{8} = 7.5 \tag{8}$$

$$I_{\min} = \texttt{S\_ENERGY\_LO} = 0.15 \quad\Longleftrightarrow\quad r = \frac{60}{0.15} = 400 \tag{9}$$

- 上限在**去程**于 $50(1-p) = 7.5$ 处触发，即 $p = 0.85$（$\tau = 1.46$）之后，占窗口最后 0.09 s；
- 上限在**抵达**于 $70p = 7.5$ 处结束，即 $p = 0.107$（$\tau = 4.958$）之前，落在淡入段里；
- **下限在当前参数下永远不触发**（要到 $r = 400$，而两波的最大半径只有 70）。它是一条保险丝，
  不是观感旋钮 —— 想调"扩散端有多暗"要动 `S_REF_R` 或增益，动这里没有效果。

## 6. 窗口包络

### 6.1 为什么必需

**反例（实测）**：能量律在窗口两端都**不是零**。去程终点 $r$ 归零，由 (7) 得 $I$ 趋于 $+\infty$、被钳到 8，
此时若包络恒为 1，则 $\tau$ 越过 $t_1$ 的那一帧强度从 $G \cdot 8 = 0.2 \times 8 = 1.6$ 直接掉到 0。
在加性 HDR 里这是 1.6 个单位的阶跃，远高于可见阈值，而且 bloom 会先把这 1.6 提出来再模糊一遍，
于是一整片光晕停在半空 —— 读作"最亮的一刻被一刀砍掉"。

这不是曲线形状的问题，而是**"窗口边界"与"能量律零点"不重合**的问题，所以修法不是换缓动函数，
而是**补一个两端归零的包络**。

### 6.2 构造与两端归零的证明

$$u(p) = \mathrm{smooth}\!\left(\mathrm{clamp01}\!\left(\frac{p}{f_{\mathrm{rise}}}\right)\right),
\qquad d(p) = \mathrm{smooth}\!\left(\mathrm{clamp01}\!\left(\frac{p - (1 - f_{\mathrm{fall}})}{f_{\mathrm{fall}}}\right)\right),
\qquad w = u\,(1 - d) \tag{10}$$

其中 $\mathrm{smooth}(x) = x^2(3 - 2x)$ 是标准的三次平滑阶跃，满足 $\mathrm{smooth}(0) = 0$、$\mathrm{smooth}(1) = 1$。

**命题 3**：$w(0) = 0$ 且 $w(1) = 0$，且两端都是 $C^1$ 归零。

**证明**：$p = 0$ 时 $\mathrm{clamp01}(0/f_{\mathrm{rise}}) = 0$，故 $u = \mathrm{smooth}(0) = 0$，于是 $w = 0 \cdot (1-d) = 0$；
又 $\mathrm{smooth}'(0) = 0$，所以 $u$ 在 $p = 0$ 的一阶导为零，$w$ 的一阶导也为零。
$p = 1$ 时 $\mathrm{clamp01}(f_{\mathrm{fall}}/f_{\mathrm{fall}}) = 1$，故 $d = \mathrm{smooth}(1) = 1$，于是 $1 - d = 0$、$w = 0$；
同理 $\mathrm{smooth}'(1) = 0$，故该端一阶导为零。证毕。

"精确为 0"与"接近 0"的差别在加性混合下是实质性的：接近 0 仍要乘上 $G \cdot I$，而 $I$ 在那一端可以达到 8。

**约束**：$f_{\mathrm{rise}} + f_{\mathrm{fall}} \le 1$。否则 $d$ 的上升段会与 $u$ 的上升段重叠，
乘积在整段上都小于 1（"平台"消失，波形退化成两个驼峰之间的凹陷）。当前取值下平台占比为
$1 - f_{\mathrm{rise}} - f_{\mathrm{fall}}$：去程 $1 - 0.25 - 0.12 = 0.63$，抵达 $1 - 0.10 - 0.40 = 0.50$。

### 6.3 四个分数为什么分开给

两道波的**高潮在不同的端**，这是它们唯一需要不同包络形状的原因：

| 波 | 高潮位置 | 淡入 $f_{\mathrm{rise}}$ | 淡出 $f_{\mathrm{fall}}$ | 理由 |
|---|---|---|---|---|
| 去程收束 | **终点**（$r = 0$，能量最大） | 0.25 | **0.12** | 收尾要短，否则把高潮抹平 |
| 抵达发散 | **起点**（$r = 0$，能量最大） | **0.10** | 0.40 | 淡入要短，收尾要长，那才是"消散" |

写成一组常数会让其中一道必然不对：短的淡出用到抵达上就是把消散阶段砍掉，长的淡出用到去程上就是把高潮压平。

## 7. 可见环带

### 7.1 为什么由片元切，而不是由网格做

如果让网格本身只铺出那条带（环面），那么模型的 XZ 缩放一旦等于 $r$，带宽就会随 $r$ 一起被放大 ——
半径小时带子细如发丝、半径大时带子粗成一片。把带子交给片元按**世界半径**判定，宽度就与世界单位绑定：

```glsl
float objR   = length(vObjPos.xz);
float worldR = objR * uRingScale;
float xb     = (worldR - uRingR) / uBandW;
float band   = exp(-xb * xb);
if (band <= 0.002) discard;
```

这里 `uRingScale` 是网格在世界里的外半径，`vObjPos.xz` 是单位圆盘上的物体空间坐标，两者相乘即世界半径。
**必须用 `uRingScale` 而不是 `uRingR`**：网格是被放大过的，用 `uRingR` 会把带子送到错误的位置。

### 7.2 从平顶换成高斯后的厚度换算

旧的剖面是 $b_{\mathrm{old}}(\Delta) = 1 - \mathrm{smoothstep}(0, W, |\Delta|)$，取值区间 $|\Delta| \le W$。
它在 $b = 0.5$ 处满足 $\mathrm{smoothstep}(0,W,|\Delta|) = 0.5$，即 $|\Delta| = W/2$，故半高全宽

$$\mathrm{FWHM}_{\mathrm{old}} = 2 \cdot \frac{W}{2} = W \tag{11}$$

高斯剖面 $b_{\mathrm{new}}(\Delta) = \exp(-(\Delta/W)^2)$ 在 $b = 0.5$ 处满足 $(\Delta/W)^2 = \ln 2$，故

$$\mathrm{FWHM}_{\mathrm{new}} = 2\sqrt{\ln 2}\,W = 1.6651\,W \tag{12}$$

取 $W = \texttt{S\_BAND\_W} = 3.0$ 时，$\mathrm{FWHM}_{\mathrm{old}} = 3.00$ 而 $\mathrm{FWHM}_{\mathrm{new}} = 5.00$，
即**换成高斯后亮带厚了 67%**。这不是参数写错，而是两种剖面"同样的宽度参数"代表不同的视觉厚度。
若要保持原来的厚度，应取 $W = 3.00/1.6651 = 1.80$。

采用高斯的理由是它与扭曲用的剖面**是同一个形状**（两处都是 $\exp(-x^2)$），
于是"看起来在动的地方"与"真的在扭的地方"用同一种分布描述，两处读起来才像一件事；
而且高斯没有硬边界，不会在带宽处留下一个可被 bloom 放大的台阶。

注：`WarpShock.h` 里那个 CPU 侧的同名辅助函数 `shockProfile()` 在 2026-10-03 全项目扫描时
**没有任何调用点**（扭曲是片元里自己算的高斯），因此它只是"形状的声明"，不参与管线；
`S_PROFILE_W` 实际只经 `uProfileW` 喂给片元一处。

### 7.3 丢弃阈值与网格半径必须匹配

**命题 4**：设片元的丢弃判据为 $b \le \varepsilon$，网格外半径系数为 $K$（网格外半径 $r + KW$），
则"网格边缘不产生可见阶跃"的充要条件是

$$K \ge \sqrt{\ln \frac{1}{\varepsilon}} \tag{13}$$

**证明**：丢弃发生在 $\exp(-x_b^2) \le \varepsilon$ 处，两边取对数得 $-x_b^2 \le \ln\varepsilon$，
即 $x_b^2 \ge \ln(1/\varepsilon)$。网格覆盖 $x_b \le K$，所以"丢弃先于网格边缘发生"要求
$K \ge \sqrt{\ln(1/\varepsilon)}$。此时最外侧仍被绘制的像素满足 $b \le \varepsilon$，
它与"什么都没有"之间的差不超过 $\varepsilon G I$，可视作零。条件不满足时，
网格最外一圈的 $b$ 值为 $\exp(-K^2) > \varepsilon$，而它之外没有任何几何，
于是留下一条高度为 $\exp(-K^2) G I$ 的**硬台阶**。证毕。

代入 $\varepsilon = 0.002$：$\sqrt{\ln 500} = 2.49288$。**取 $K = 2.5$ 恰好越过这个门限。**

历史取值 $K = 2.0$ 时，最外圈的 $b = \exp(-4) = 0.018316$，台阶高度为
$0.018316 \times 0.2 \times 8 = 0.0293$（能量取上限 8 时），bloom 会把它放大成看得见的一圈边 ——
这正是"光片看着硬"的成因之一。

**推论**：台阶高度与 $W$ **无关**。因为 $b(KW)/b(0) = \exp(-K^2)$ 里没有 $W$，
所以调 `S_BAND_W`（改厚薄）不会改变这条边是否存在，判定只看 $K$ 与 $\varepsilon$。

网格本身不必细分：`BuildRing` 生成的是从圆心到单位圆的 128 个三角形的**扇形**，
半径方向没有顶点，放大只是改一个 `scale`，三角形数与顶点数都不变。

### 7.4 命题 5：`facing` 不含径向信息

**命题**：圆盘上每个顶点的法线都是 $+\mathbf{n}$（$\mathbf{n}$ 为锚点 Y 轴），
因此 $\texttt{facing} = |\langle \mathbf{n}, \mathbf{V}\rangle|$ 只随**像素的视线方向**变化，
不随像素在环带内的径向位置变化。

**证明**：`BuildRing` 为每个顶点写入的法线都是 $(0,1,0)$，而模型矩阵的线性部分在锚点坐标系里是
$(s, 1, s)$ 的缩放（$s$ 为环半径相关量）。常法线的插值结果仍是同一个常向量，
再经 `mat3(model)` 变换：$(0,1,0)$ 取到的是矩阵第二列，而该列在 $(s,1,s)$ 缩放下不被 XZ 分量污染，
故 `vNormal` 在整张圆盘上是同一个单位向量。于是 `facing` 只通过 $\mathbf{V} = \mathrm{normalize}(\mathbf{camPos} - \mathbf{p})$
依赖像素位置，而后者对"同一圈环上相邻两个像素"造成的差异是二阶小量（相机距离远大于环的尺度）。
换言之，`facing` 是一整片的整体明暗，不是沿半径的剖面。证毕。

结论：**`facing` 可以用来做侧对补偿，不能用来柔化环的边缘**。
它的作用范围是 $\left[\texttt{S\_FACING\_FLOOR},\ 1\right]$，取 0 表示"侧看即消失"。
`pow(facing, 0.7)` 这类幂次只改变"随视角下降的快慢"，改变不了它在径向是常数这一事实。

### 7.5 混合方式：加法、纯 α、预乘 α

环带亮度层有三种合成方式（本节为了不动 §8 之后的公式编号，不插入带编号的公式）。约定四个量：

- $c$：环的颜色，$\texttt{uDebrisColor} \times \texttt{vTint}$；
- $b$：该像素处已经在缓冲里的背景；
- $a$：膜的不透明度，$\mathrm{clamp}(\texttt{U\_SHOCK\_ALPHA\_MAX} \times \texttt{band} \times \texttt{facing} \times \texttt{vAlpha} \times \texttt{uShockEnv},\ 0,\ 1)$；
- $g$：亮脊，$c \times \texttt{band} \times \texttt{facing} \times \texttt{vAlpha} \times \texttt{uDebrisStrength}$，
  其中 $\texttt{uDebrisStrength} = \texttt{U\_SHOCK\_GAIN} \times I(r) \times \texttt{uShockEnv}$（$I$ 为 §5 的能量律）。

| 方式 | 片元输出 | 混合方程 | 合成结果 |
|---|---|---|---|
| 加法（原版） | $(g,\ 1)$ | `GL_ONE, GL_ONE` | $b + g$ |
| 纯 α | $(c,\ a)$ | `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA` | $c\,a + b\,(1-a)$ |
| 预乘 α（现行） | $(c\,a + g,\ a)$ | `GL_ONE, GL_ONE_MINUS_SRC_ALPHA` | $c\,a + g + b\,(1-a)$ |

三种结果都能由混合方程直接读出：`GL_ONE, GL_ONE` 表示源整体加到目标上；预乘那一行的"源"**已经乘过 $a$**，
所以着色器里不能再乘一次，C++ 侧也必须相应换成 `GL_ONE, GL_ONE_MINUS_SRC_ALPHA`。

**为什么最后是预乘 α。** 加法项的系数恒为 1，它只能把背景**照亮**；只有含 $b\,(1-a)$ 的方式才能把背景**压暗并染色**。
预乘把两者放进同一遍：$c\,a$ 给膜、$g$ 给亮脊，而且能量律重新回到亮度里 ——
加法时代"去程收到中心时极亮"的读感随之保留。

**纯 α 那一版为什么被否掉（实测）。** 它不读 `uDebrisStrength`，环的亮度与"波的能量"脱钩。
$\texttt{U\_SHOCK\_ALPHA\_MAX} = 0.45$ 时，膜自身的亮度（$c\,a \approx 0.42$）盖过了 $b\,(1-a)$ 的压暗，
观感与加法版**无从分辨**；把 $a$ 压到 $0.05 \sim 0.10$ 才看得出差别，而那个差别恰恰来自 $b\,(1-a)$，
即"压暗"这一项。这条经验直接指向预乘：**膜要读得出来，就不能让膜自身的亮度盖掉背景的衰减**。

**两个旋钮的交点。** 在 $r = \texttt{S\_REF\_R}$ 处能量律恰为 1，于是 $a \approx \texttt{U\_SHOCK\_ALPHA\_MAX}$
（取 `band`、`facing`、`uShockEnv` 均为 1）、$g$ 的峰值 $\approx \texttt{U\_SHOCK\_GAIN}$ —— 两者的贡献相等。
所以"更膜"与"更亮"各有一个独立旋钮，交点位置由 `S_REF_R` 决定，而不是由两个旋钮的比例决定。

**一条硬约束（配对）。** 预乘输出**必须**配 `GL_ONE, GL_ONE_MINUS_SRC_ALPHA`；
而加法那份着色器输出 $\alpha = 1$，**绝不能**配它 —— $1-a = 0$ 会把环带内的背景整个抹掉。
配错**不报错**，只是画面变样（膜悄悄消失，或环带变成一圈"洞"），所以两侧源码里都写了这条注释。

**接口形态。** 这件事落在两个文件上：着色器 `shock/warp_shock_frag2.0.shader`（预乘输出）
与 `WarpDebris.cpp` 的 `WarpShockDraw`。后者拆成两个重载（6 参 = 加法，7 参 = 多一个 `bool alphaRing`），
**只保留一份实现**：6 参版转调 7 参版并传 `false`，于是 `24.B/C/D` 的调用点一个字节都不用改。

## 8. 行进色

### 8.1 相对色的必要性

片元的颜色是

$$\mathbf{c} = \mathbf{c}_{\mathrm{base}} \cdot \mathbf{t} \cdot b \cdot \texttt{facing} \tag{14}$$

其中 $\mathbf{c}_{\mathrm{base}}$ 与 $\mathbf{t}$ 分别是 `uDebrisColor`（值 `U_PILLAR_COLOR = (0.45, 0.82, 1.00)`）
与 `uShockTint`。式 (14) 的乘法链上有**两个**颜色项，所以只把其中一个换成绝对色，读到的色相是两个量相乘的结果。
为避免"调色时算不明白"，新的两端色按**相对色**给出，分量 1.0 表示"不变"：

$$\mathbf{c}_{\mathrm{end}} = \mathbf{c}_{\mathrm{base}} \odot \mathbf{t}_{\mathrm{rel}} \tag{15}$$

| 端点 | 相对色 `U_SHOCK_TINT_*` | 实际终色 $\mathbf{c}_{\mathrm{end}}$ | Rec.709 亮度 |
|---|---|---|---|
| 基准（不作色变） | $(1,\ 1,\ 1)$ | $(0.45,\ 0.82,\ 1.00)$ | 0.900 |
| `NEAR`（$r$ 小，白热） | $(2.10,\ 1.15,\ 0.95)$ | $(0.945,\ 0.943,\ 0.95)$ | 0.944 |
| `FAR`（$r$ 大，冷蓝） | $(0.80,\ 0.92,\ 1.00)$ | $(0.36,\ 0.754,\ 1.00)$ | 0.688 |

`NEAR` 的三个通道被压到几乎相等（0.94 附近），读作中性白；`FAR` 压掉红通道，读作更深的冷蓝、
亮度低 24%。两端亮度都不等于基准，这是**有意**的：扩散端本来就该更暗，与能量律同向。

### 8.2 驱动量：从半径换成窗口进度

设半径键为 $k_r = r/r_{\mathrm{ref}}$、进度键为 $k_p$。

**命题 6**：去程上 $k_r \equiv k_p \equiv 1 - p$ 当且仅当 $R_0 = r_{\mathrm{ref}}$；
抵达上 $k_r \equiv k_p \equiv p$ 当且仅当 $R_1 = r_{\mathrm{ref}}$。

**证明**：由 (5)，去程 $r = R_0(1-p)$，故 $k_r = (R_0/r_{\mathrm{ref}})(1-p)$。
它与 $1-p$ 对一切 $p$ 相等的充要条件是系数为 1，即 $R_0 = r_{\mathrm{ref}}$。
抵达同理：$r = R_1 p$，$k_r = (R_1/r_{\mathrm{ref}})p$，恒等于 $p$ 的充要条件是 $R_1 = r_{\mathrm{ref}}$。证毕。

代进当前值：去程 $R_0 = 50$ 而 $r_{\mathrm{ref}} = 60$，两者**不**相等，所以两个键此刻给出不同的画面；
抵达 $R_1 = 70$、$r_{\mathrm{ref}} = 60$，$k_r$ 在 $p = 60/70 = 0.857$ 处就被 `clamp` 顶住，
也就是说抵达那道波在进度走到 85.7% 之后颜色**不再变化**，而波还在继续外扩。

改用进度键之后：

```cpp
const float colorP = out ? warp_sc::shockProgress(gWarp.tau, warp_sc::S_OUT_T0, warp_sc::S_OUT_T1)
                         : warp_sc::shockProgress(gWarp.tau, warp_sc::S_IN_T0, warp_sc::S_IN_T1);
const float colorK = out ? (1.0f - colorP) : colorP;
```

**收益**：$R_0$、$R_1$ 变成**纯观感旋钮**，改它们不会再连累配色；同时 $r_{\mathrm{ref}}$ 回到只服务能量律一条语义
（一个常量服务两个语义是踩过的坑，见 §12.3）。

### 8.3 实际读得到的色变区间

包络的平台段决定"满亮度"的时间，把它换算成 $k_p$：

| 波 | 平台 $p$ 区间 | 对应 $\tau$ | 满亮度段的 $k$ 区间 | 读感 |
|---|---|---|---|---|
| 去程 | $[0.25,\ 0.88]$ | $[1.10,\ 1.478]$ | $[0.12,\ 0.75]$ | 冷蓝推向白热 |
| 抵达 | $[0.10,\ 0.60]$ | $[4.953,\ 5.268]$ | $[0.10,\ 0.60]$（继续到 1 时已在淡出） | 白热推向冷蓝 |

两端的极端值（$k = 1$ 的全蓝、$k = 0$ 的全白）都落在包络的淡入或淡出段里，看不出，
但中间跨度分别是 0.63 与 0.50，足以读出方向。

### 8.4 与全屏白闪的时间重合

`FLASH_RISE = TAU_STAR - 0.05 = 1.50`，峰值正好在 `TAU_STAR = 1.55`，
即**白闪的峰值与去程波收到圆心是同一刻**。看起来像冲突，实际影响很小：

- 白闪从 1.50 才开始上升；而在 $\tau = 1.50$ 处 $p = (1.50 - 0.95)/0.60 = 0.9167$，$k = 0.0833$，颜色已经接近全白；
- 真正有色变的 $[1.10,\ 1.478]$ 那一段，白闪恒为 0。

因此重合的只是"最白的那一帧"，而那一帧本来就是白的。不需要为此额外处理；
若将来把 `FLASH_RISE` 提前到 1.10 之前，这个结论就不再成立。

## 9. 屏幕空间扭曲

### 9.1 为什么需要可采样的深度

扭曲是"逐像素求出它到波前的世界距离，再按这个距离把采样点沿屏幕径向挪一点"。
要得到"像素的世界坐标"，只能从**深度缓冲**反算，而 `GL_TEXTURE_2D` 的 `texture()` 要求深度是
**纹理**；renderbuffer（`hdrDepthRBO`）根本不可采样，没有任何折中方案。
因此 hdrFBO 的深度附件换成 `hdrDepthTex`：

```
GL_DEPTH_COMPONENT24, GL_NEAREST, GL_TEXTURE_COMPARE_MODE = GL_NONE
```

`GL_NEAREST` 是因为要读精确深度值（比较模式会返回比较结果而不是深度，因此必须显式关掉）。
`hdrDepthRBO` 的创建与删除代码以注释形式留档。

### 9.2 世界坐标反算

窗口深度 $d \in [0,1]$ 对应 NDC 深度 $2d - 1$，像素的 NDC 坐标由纹理坐标给出：

$$\mathbf{q}_{\mathrm{ndc}} = (2u - 1,\ 2v - 1,\ 2d - 1) \tag{16}$$

$$\mathbf{p}_{\mathrm{world}} = \frac{(\mathbf{M}_{\mathrm{VP}})^{-1}\mathbf{q}_{\mathrm{ndc}}}{w} \tag{17}$$

式 (17) 里除以 $w$ 是因为逆矩阵作用在齐次坐标上得到的是"相差一个缩放的世界点"，
只有除以第四分量才回到仿射坐标。$d \ge 1$ 表示该像素没有几何（星空/背景），
此时反算无意义，直接输出原图。

### 9.3 到圆环的距离

设环心 $\mathbf{c}$、单位法线 $\mathbf{n}$（锚点 Y 轴）、当前半径 $r$。
把像素相对环心的向量 $\mathbf{v} = \mathbf{p} - \mathbf{c}$ 分解为面外分量与面内分量：

$$h = \langle \mathbf{v}, \mathbf{n}\rangle, \qquad \mathbf{q} = \mathbf{v} - h\mathbf{n} \tag{18}$$

因为 $\mathbf{n}$ 是单位向量，$|\mathbf{q}|$ 就是像素到纵轴的**面内半径**，记作 $d_p$。
环上离该像素最近的点在同一个面内方向上、半径为 $r$ 处：

$$\mathbf{p}_{\mathrm{nearest}} = \mathbf{c} + \frac{\mathbf{q}}{d_p} r + h\mathbf{n} \tag{19}$$

$$\varepsilon_{\mathrm{dist}} = \left|\mathbf{p} - \mathbf{p}_{\mathrm{nearest}}\right| \tag{20}$$

式 (20) 就是"离波前多远"（片元里叫 `eps`，**不能叫 `d`** —— 那个名字已经被窗口深度占用，见 §12.2）。
$d_p < 10^{-4}$ 的像素落在轴线上，面内方向无定义，直接输出原图。

### 9.4 屏幕空间的径向方向与幅度

剖面取与环带同形状的高斯：$w_{\mathrm{prof}} = \exp(-(\varepsilon_{\mathrm{dist}} / \texttt{uProfileW})^2)$。

"径向"在世界空间里是 $\delta / \varepsilon_{\mathrm{dist}}$（$\delta$ 是像素到最近点的向量），
但把它直接当屏幕方向是错的：圆柱/圆环投到屏幕上不是圆，相机一转方向就变。
正确做法是把世界位移**投到屏幕上取差分**：

$$\mathbf{s}_0 = \pi\!\left(\mathbf{M}_{\mathrm{VP}}\mathbf{p}\right), \qquad
\mathbf{s}_1 = \pi\!\left(\mathbf{M}_{\mathrm{VP}}\left(\mathbf{p} + \frac{\delta}{\varepsilon_{\mathrm{dist}}}\max(r, 1)\right)\right) \tag{21}$$

其中 $\pi$ 表示"乘 VP 后除以 $w$、再乘 0.5 加 0.5"的视口变换。
差分 $\mathbf{s}_1 - \mathbf{s}_0$ 乘以屏幕分辨率即得像素空间方向，归一化后记作 $\mathbf{u}$。
$\max(r,1)$ 的步长作用是把差分放大到数值上可靠的程度；$r$ 很小时方向会不稳定，
所以当 $|\mathbf{s}_1 - \mathbf{s}_0| < 10^{-6}$ 时也直接输出原图（这对应"环的径向几乎沿视线"，
那种像素本来也不该被推）。

幅度按分辨率等比缩放，并换算回 UV：

$$\texttt{offset} = \mathbf{u} \cdot \frac{\texttt{uPush} \cdot \texttt{uDistortPx} \cdot \frac{H}{1080} \cdot w_{\mathrm{prof}}}{\mathbf{screen}} \tag{22}$$

$\texttt{uDistortPx} = 20$（`S_DISTORT_PX`）是"@1080p 的像素数"，除以屏幕尺寸后变成 UV 偏移，
于是同样的参数在 4K 上仍然是"12 个 1080p 像素放大到 4K"的比例。
方向由 `uPush` 给出：去程波向内收，故 `S_OUT_PUSH = -1`；抵达波向外散，故 `S_IN_PUSH = +1`。
两者互为反号，写反了会读成"波把画面往反方向吸"。

位移幅度**不**乘环带亮度那条窗口包络，而是走**自己的一条**曲线（`shockDistortRamp`）：

$$w_{\mathrm{dist}}(p) = S\!\left(\frac{p}{f_{\mathrm{rise}}}\right)\left[1 - S\!\left(\frac{p - (1 - f_{\mathrm{dist}})}{f_{\mathrm{dist}}}\right)\right],
\qquad S(x) = \mathrm{smooth}(\mathrm{clamp01}(x)) \tag{23}$$

$f_{\mathrm{rise}}$ 取**该道波自己的**淡入占比（去程 `S_OUT_RISE_F = 0.25`、抵达 `S_IN_RISE_F = 0.10`），
$f_{\mathrm{dist}} = \texttt{S\_DIST\_FALL\_F} = 0.15$ 是位移幅度自己的收尾占比。两端**精确为 0**：
$p = 0$ 时 $S(0) = 0$，整个乘积为 0；$p = 1$ 时方括号内的自变量为 1，$S(1) = 1$，故方括号为 0。

**起点与亮度同源，终点与亮度无关**：起点同源是为了不出现"还没见光、背景先扭"；终点用自己的占比，
是为了不与亮度同步变淡（那正是被否掉的那一版）。

| | 亮度收尾起点 | 位移收尾起点 | 关系 |
|---|---|---|---|
| 去程 | $p = 0.88$（τ = 1.478） | $p = 0.85$（τ = 1.460） | 位移略早 0.018 s；两者都只剩最后 0.07–0.09 s，且压在白闪上升段上 |
| 抵达 | $p = 0.60$（τ = 5.268） | $p = 0.85$（τ = 5.426） | 位移晚 0.157 s，即"光淡了、扰动还在"；位移开始收尾时亮度只剩平台的 32% |

**不变量**：$f_{\mathrm{rise}} + f_{\mathrm{dist}} \le 1$，否则淡入与淡出重叠、峰值到不了 1。
现在两波分别是 $0.25 + 0.15 = 0.40$ 与 $0.10 + 0.15 = 0.25$，安全。

**两个反面**：① 完全没有这条曲线时，位移在窗口两端都是"一帧跳变"（起点由 0 跳到满幅 12 px、终点由 12 px 跳到 0）；
② 2026-10-04 试过直接复用亮度那条包络（`uDistortPx * env`），结果更差 —— 抵达末段 40%（约 0.252 s）里
亮度与扰动**同步**变暗，两者塌成"一团一起淡掉的东西"，参照系消失，扰动不再读作"跟着亮脊的形变"，故撤销。

2026-10-03 的取值是 $W_{\mathrm{prof}} = 8$（原 12）与 $A = 12$（原 8）：一窄一强合起来让
"亮脊自己在扭"更清楚，扰动圈与亮带的 FWHM 之比从 $20.0/5.0 = 4.0$ 降到 $13.3/5.0 = 2.67$
（再往下压会丢掉"细亮脊 + 更宽扰动带"的分工：亮脊先抓住眼睛、扰动在它两侧铺开）。
最大位移梯度相应从 $0.8578 \times 8/12 = 0.57$ 升到 $0.8578 \times 12/8 = 1.29$ 像素/世界单位，
而折叠（同一源像素被采两次）要求梯度达到"一个世界单位占多少像素"的量级 —— 跟随相机下约 16 像素/世界单位，
所以差一个数量级，不会出现几何撕裂，剩下的只是跨深度采样的拖影。

**2026-10-06 的现行取值**：$W_{\mathrm{prof}} = 8$（不动）、$A = 20$。
$A$ 从 12 提到 20 不是因为观感变了，而是因为**这幅画面是在 960$\times$600 的窗口里跑的**：
式 (22) 的因子 $H/1080$ 把名义值压到 $0.556$ 倍，于是名义 12 只剩 6.7 像素、偏弱；20 对应的实际峰值约 $11.1$ 像素，
与"@1080p 下 12 像素"等效。现行最大梯度 $0.8578 \times 20 \times 0.556/8 = 1.19$ 像素/世界单位，离折叠阈值仍差一个数量级。
$W$ 保持 8 的理由是 2026-10-03 那次已经定过（比值 $8/3 = 2.67$ 落在推荐区间 $1.5 \sim 5$ 的中位）。

### 9.5 为什么不用多峰剖面（2026-10-06 实试记录）

§9.4 的剖面只有一个峰，位移只出现在波前两侧各约 $2W_{\mathrm{prof}}$ 之内，读作"一圈透镜"。
参考画面里"整个波面都在扭"，于是自然的猜想是把它**沿 $\varepsilon$ 周期化**，得到一串同心涟漪：

$$w_{\mathrm{multi}}(\varepsilon) = \cos\!\left(\frac{2\pi\varepsilon}{L}\right)\exp\!\left(-\frac{\varepsilon}{F}\right) \tag{24}$$

式 (24) 在式 (22) 里的**位置与 $w_{\mathrm{prof}}$ 完全相同**，其余一切（反算世界坐标、差分求方向、
分辨率缩放、幅度包络）都不用动 —— 这是它一开始被认为"成本最低"的原因。

| 符号 | 含义 | 单位 |
|---|---|---|
| $L$ | 波纹波长，式 (24) 里余弦的周期 | 世界单位 |
| $F$ | 包络衰减长度：$\varepsilon = F$ 处包络降到 $e^{-1} = 0.368$ | 世界单位 |
| $N_{\mathrm{one}}$ | 单侧可见峰数 | 无量纲 |

这三个只在本节使用，故不并入 §2 的主符号表。

**① 相位不需要额外项。** 式 (24) 的宗量是 $\varepsilon$，而 $\varepsilon$ 是"到**当前**圆环的距离"（式 (20)）。
环半径 $r(\tau)$ 自己就在动，所以波纹天然跟着波前走。
若改用"到环心的距离"当宗量，就必须手写相位 $r(\tau)$，而且半径停住时波纹也会停 —— 那已经是另一个效果。

**② $w$ 可以取负，这是第一个信号。** 式 (22) 里包络是乘在偏移上的，**符号就是方向**。
单峰 $w \ge 0$，整道波的位移只朝一个方向；式 (24) 的 $w$ 取值在 $[-1, 1]$ 内，波谷处位移**反向**。
物理上这叫稀疏与压缩交替，确实像水；但这套几何是**平的薄圆环**（§1），
一帧里只有一个半径 $r(\tau)$ 是有意义的 —— 在同一处叠出多条互相反相的位移，画面里并没有对应的几何。

**③ 峰数只由 $F/L$ 决定，而两个旋钮的方向相反。** 余弦在每个长度 $L$ 上有一个峰，
包络在 $\varepsilon \in [0, F]$ 内仍有可观幅度，故单侧峰数为

$$N_{\mathrm{one}} = \frac{F}{L} \tag{25}$$

两侧相加即"一屏能数出几道"。三次实试：

| $L$ | $F$ | $N_{\mathrm{one}}$ | 全屏大致 | 结果 |
|---|---|---|---|---|
| 18 | 60 | 3.3 | 6.7 | 太密 |
| 26 | 80 | 3.1 | 6.2 | 仍密 |
| 40 | 50 | 1.25 | 2.5 | 疏密已可接受，但读感仍不如单峰 |

**加大 $L$ 是变疏，加大 $F$ 反而是变密**：$F$ 把"有幅度"的范围推远，于是屏幕上同时出现的道数按式 (25) 变多。
第一轮调参把两者**同时**往大调（$18/60 \to 26/80$），两个效应正好抵消、观感几乎没变 —— 这是本次实验里最容易复现的一处误判。

**④ 幅度的语义被破坏。** 单峰只有一个峰，$A = \texttt{uDistortPx} = 12$（当时的现行值；2026-10-06 定稿为 20，见 §9.4）就是"这道波的最大偏移"。
多峰把同一个幅值复制到 $N$ 处，"12 像素的偏移"一屏出现约 $2F/L$ 次，视觉强度成倍上升，
所以实测不得不把 $A$ 砍到 6。于是 $A$ 的含义从"最大偏移"变成"每个峰的最大偏移"，
**两个方案的 $A$ 不可比**：换剖面必须同时改 $A$，否则会把"剖面变了"与"幅度变了"混在一起判断。

**⑤ 结论（三条判据）。**

1. **读感**：单峰读作"**一条**波前的形变"，扰动与亮脊共用同一个中心；多峰读作"一圈圈涟漪"，眼睛找不到"波前在哪"。
2. **与几何的对应**：这套几何一帧里只有一个半径在动（式 (5)），多峰等于宣称"有 $2F/L$ 个半径同时在做功"。
3. **调参收敛**：$F/L$ 一路调到约 2.5 道仍不占优，说明不是参数没调对，而是剖面的形状本身不合。

**⑥ 留档与再试的成本。** 多峰那份整体留档为 `warp_shock_distort_frag2.0.shader`，
两个旋钮 `S_RIPPLE_L` / `S_RIPPLE_FALL` 留在 `src/WarpShock.h`。
现行剖面（单峰）**不读**这两个 uniform，所以它们当前不生效；
`WarpDebris.cpp` 里那两行 `setFloat("uRippleL"/"uRippleFall")` 保留着，
对着不存在的 uniform 是**静默 no-op**（`glUniform*` 收到位置 $-1$ 时按规范忽略），不用删。
再试只需把 `.cpp` 里 `warpShockDistortShader` 构造的第二个路径参数换成 `_2.0` 那份，并把 $A$ 调回 6。

**⑦ 没有走的那条路。** 另一条候选是"在环心加一个半球隆起"。它需要一个**新的方向**：
式 (21) 的差分给出的是"从环上最近点指向像素"，环内像素拿到的是朝内的方向，而隆起要求统一朝外；
而且隆起正好压在舰体所在的深度上，屏幕空间位移会把舰体轮廓拉花（§9.1 的跨深度拖影在轮廓处最强）。留待后续。

**这次实验真正的产物**：§9.4 那条单峰剖面不是"随手选的形状"，而是"**这一帧只有一条波前**"这个语义在屏幕空间的实现。
剖面函数的形状，本质上是在声明"有几条波前"。

## 10. 渲染顺序与 FBO 契约

1. **波带本体**（`WarpShockDraw`，`WarpDebris.cpp`）：加法混合（`GL_ONE, GL_ONE`）、
   `glDepthMask(GL_FALSE)` 但**保留深度测试**，因此它被舰体正确遮挡、又不写深度。
   画在舰体 pass 之后、后处理之前。
2. **扭曲 pass**（`WarpShockDistort`）：读 `hdrColorBuffer`（单位 0）与 `hdrDepthTex`（单位 1），
   渲染到 `pingpongFBO[0]`，再 `glBlitFramebuffer` 回 `hdrFBO` 的颜色附件。
   两者同为 `GL_RGBA16F`，所以 blit 合法。
3. **后处理**（`PostProcessing`）：必须排在扭曲**之后**，否则 bloom 从**未扭曲**的图像里提取，
   波带的光晕就不会跟着一起扭 —— 而"光晕跟着扭"正是这个效果最有说服力的部分。

约束：扭曲 pass 结束时把 `GL_DEPTH_TEST` 重新打开。这是一次**基于假设**的恢复
（假设进来时它是开的），当前调用点满足这个假设，但它属于"保存-恢复必须用真值"这条规矩的例外面，
改动主循环顺序时要重新确认。

扭曲 pass 不写深度（只 blit 颜色），所以 `hdrDepthTex` 在整个过程中保持有效，
`PostProcess` 里那次"把 hdrFBO 的深度 blit 到默认帧缓冲"的行为不受影响。

## 12. 验收判据与踩坑记录

### 12.1 判据

1. 去程的环色由冷蓝推向白热，**最白的时刻就是半径最小、最亮的时刻**（$\tau = 1.55$），不是时间中点。
2. 抵达反向，白热推向冷蓝，且变蓝的那一段正好落在变暗消散的阶段（两者同向，不应出现"变亮的同时变蓝"）。
3. 两道波都不应在窗口两端"戛然而止"：越过窗口边界时强度必须**恰好**是 0。
4. 圆盘外缘不应出现一条比环带更硬的边（命题 4 的 $K \ge 2.4929$）。
5. 去程开场的 5 帧（30 fps 下 0.15 s 的淡入）内，不应看到一条完整的亮环从虚无里冒出来；
   若出现，说明 $R_0$ 太靠内。
6. 扭曲的方向：去程把画面**向内**吸、抵达**向外**推；若相反，检查 `S_OUT_PUSH` / `S_IN_PUSH` 的符号。

### 12.2 踩坑记录

| 现象 | 根因 | 修法 |
|---|---|---|
| 着色器编译失败 `C1038: declaration of "d" conflicts with previous declaration` | 新写的"到环的距离"用了 `float d`，而 `d` 已装窗口深度 | 改名 `dp`；往已有着色器里加量前先扫已用变量名 |
| 波在最亮处戛然而止 | 能量律在窗口两端非零，而当时没有包络 | 补 `shockWindowOut/In`，两端精确归零（命题 3） |
| 圆盘外缘一圈硬边 | 网格系数 2.0 小于 $\sqrt{\ln 500} = 2.4929$ | 改 2.5；把这条不等式写进注释 |
| 改了调色却"看起来没生效"，`U_SHOCK_TINT` 又"好像还在用" | 新的 `setVec3("uShockTint", ...)` 加在旧赋值**之后**，后设的赢，旧行成了死代码 | 注释掉旧行；判据是"同一函数里同一个名字出现了几次 set" |
| 把 $R_0$ 调小之后，配色的蓝端读不出来了 | `S_REF_R` 同时当能量律与配色的参考半径 | 配色改用窗口进度（命题 6） |
| 侧对时环消失 | 平面圆环的投影退化（命题 1），几何固有 | `S_FACING_FLOOR = 0.35` 补偿；不要试图用 `facing` 柔化边缘（命题 5） |

### 12.3 一条通用教训

**一个常量服务两个语义，早晚会咬人。** `S_REF_R` 原本同时是"能量律的参考半径"和"配色的参考半径"，
于是"把去程半径调小"这个纯几何改动会顺手改掉配色。修法不是调数值，而是**换驱动量**：
半径读"走多远"、进度读"走到哪一刻"，两者都是同一个波峰的读数，但只有一个与半径这一侧的参数耦合。
