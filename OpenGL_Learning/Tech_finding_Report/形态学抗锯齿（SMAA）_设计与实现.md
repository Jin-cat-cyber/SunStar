# 形态学抗锯齿（SMAA）设计与实现

> 对象：`src/SMAA.{h,cpp}`、`res/shader/00_SpaceShip/SMAA/{smaa_ver,smaa_edge_frag,smaa_blend_frag}.shader`；已接在活跃版本 `SpaceShip27.0.cpp`（合成之后、镜头光晕之前）。
> 配套：`时间抗锯齿（TAA）_失败记录与方向性复盘.md` —— 那一篇记时间维为什么放弃，本篇记空间维这一条怎么落地。
> 一句话：两遍全屏，在**合成之后的 LDR 图**上按边型把邻居颜色混进来，修的是栅格化台阶的**角**。

---

## 0. 结论

1. **它治的是几何边缘的台阶。** 一条斜边被栅格化成一串整像素台阶，SMAA 在台阶的端点上按覆盖率把邻居颜色混进来，把直角磨成斜角。
2. **它不重采样。** 不改采样数、不需要时间维，因此不会鬼影、不会沸腾、不需要速度缓冲与历史 —— 这正是 TAA 弃用之后需要的性质。
3. **落点必须在合成之后（LDR）**：阈值是绝对量、混合是感知混合，两条都要求图像已经过 tonemap 与 gamma（§2）。
4. **核心只有一条解析式**：run 长度为 $L$ 的边，其端点像素的覆盖率误差恰为 $1/(2L)$，故端点按 $w = 1/(2L)$ 混入邻居色（§4，含三个逐像素算例）。
5. **与官方 SMAA 1x 的差别是不查表**：官方用 `AreaTex`（160×560）与 `SearchTex`（64×16）两张预计算表，把每像素开销压到 4 至 8 次采样并覆盖拐角图案；本方案改用解析式加线性搜索，零外部资源、代码自持，代价是每像素最多 32 次边缘采样（有早退）与复杂拐角处略逊（§5）。
6. **它治不了两件事**：亚像素尺度的小物体（星带里最坏的情形）与 SSAO／体积光噪声。这两类都不是"边型"问题，只有空间超采样能治（§8）。

---

## 1. 与 TAA 的分工：为什么这一轮选空间方案

失败复盘 `时间抗锯齿（TAA）_失败记录与方向性复盘.md` §2 的结论是：被抱怨的"小光点随相机移动闪"属于**采样不足**（每像素每帧只有一个样本），不是"边缘不平滑"。SMAA 属于修边，不增加样本，所以它同样治不了那一类。

但它治的是另一类真实存在的缺陷：斜边的栅格化台阶。这一类不需要增加样本，只需要把角磨圆，代价是两遍全屏，且没有时间维的那一串麻烦（鬼影、沸腾、糊、速度缓冲、历史失效判据）。

所以两者的关系必须说清楚：**SMAA 是"便宜地修边、且不带来时间维副作用"，它不是 TAA 的替代品**；采样不足那一类仍然空着，去向见 §8。

## 2. 为什么落在合成之后（LDR）

### 2.1 阈值的量纲

边缘判据是"两侧亮度差超过阈值 $\tau$"（式 1）。本方案取 $\tau = 0.06$，含义是"亮度差 $6\%$"。

合成输出满足两个前提：`composite_frag2.0.shader` 的最后一步是 Uncharted2 tonemap（白点 $W = 11.2$）与 $\gamma = 2.2$ 编码，因此取值落在 $[0,1]$，且在这个区间里亮度差大致对应感知差。$0.06$ 这个数只有这样才成立。

若改喂 HDR：本工程高光可到 $10$ 量级（太阳与白闪），暗部细节可到 $10^{-3}$ 量级。同一个绝对差在两端的相对意义是

$$\frac{0.06}{10} = 0.6\%,\qquad \frac{0.06}{10^{-3}} = 6000\%$$

即在高光区相邻像素的正常噪声就能越过阈值（**满屏是边**），而在暗部真实的边一个都测不到。要让绝对阈值在 HDR 下成立，必须把它改成相对量 —— 那正是式 (1) 里第二项在做的事，而那是另一套标定。

结论：形态学 AA 吃 LDR 不是图省事，是**阈值的量纲要求**。

### 2.2 混合空间带来的偏差（诚实交代）

在编码空间按覆盖率平均，与"先在线性光下按覆盖率平均、再编码"并不等价。取最坏情形：一个像素被一条 $45°$ 边界一分为二，一侧白（编码值 $1.0$）、一侧黑（编码值 $0$）。

物理正确的做法是在线性光下平均，得到线性亮度 $0.5$，再编码存储。本工程的编码函数是 $E(x) = x^{1/\gamma}$，$\gamma = 2.2$，故

$$E(0.5) = 0.5^{1/2.2} = e^{-0.693147/2.2} = e^{-0.315067} = 0.7297$$

依据：$0.5 = e^{-0.693147}$（自然对数定义），逐项代入即得。

编码空间直接平均（本方案与所有后处理 AA 的做法）得到 $(1.0 + 0)/2 = 0.5$，它解码回线性是

$$0.5^{2.2} = e^{-1.524924} = 0.2176$$

两者之比

$$\frac{0.2176}{0.5} = 0.435$$

也就是：**在编码空间里按覆盖率混，边缘像素的线性亮度只有正确值的 $43.5\%$（暗 $56.5\%$）**。

这是形态学 AA 的固有近似，业界都在 tonemap 之后做（理由见 2.1）。要消掉它只有一条路：把覆盖率平均放回线性光下做，那正是空间超采样在做的事。这条也解释了为什么 AA 的"正确落点"在物理上是 tonemap 之前。

### 2.3 落点对照

| 技术 | 落点 | 该落在那里的原因 |
|---|---|---|
| SMAA / FXAA（形态学、后处理修边） | **合成之后**（LDR，默认帧缓冲上的成品） | 阈值是绝对量、需要感知均匀的 $[0,1]$；混合按感知权重才有意义 |
| SSAA / MSAA（多采样 + 降采样） | **合成之前**（HDR 线性，`hdrFBO` 一侧） | 降采样就是覆盖率积分，必须先于 tonemap，否则高光已被压掉、平均之后回不来 |

两者的落点相差一个 tonemap，不能互换；这条在改动管线顺序时是硬约束。

## 3. 算法结构：两遍全屏 + 两次 blit

### 3.1 第一遍：边缘检测

对每个像素取亮度 $L(\cdot)$（Rec.709 权重 $0.2126,\ 0.7152,\ 0.0722$），记左邻居为 $P_{\text{L}}$、下邻居为 $P_{\text{D}}$，判据

$$E(P) = \big[\,|L(P) - L(N)| > \max\big(\tau,\ k\max(L(P), L(N))\big)\,\big] \tag{1}$$

依据：方括号内是绝对阈值 $\tau$ 与相对阈值 $k\max(L(P),L(N))$ 取大者。第一项照 2.1 的量纲设定；第二项处理"高亮区相邻像素差天然更大"这件事，用相对阈值把那里的门槛抬高，避免把纹理细节当成边（本方案取 $k = 0.15$，即 $15\%$ 的相对差）。

输出两个布尔标记（本工程用 RG8 纹理，NEAREST 采样）：

- `.r`：与**左**邻居之间是边 —— 这是一条**竖直方向**的边（左右两侧不同），它的 run 沿**竖直**方向延伸，端点处做**上下**混合；
- `.g`：与**下**邻居之间是边 —— 这是一条**水平方向**的边，run 沿**水平**方向延伸，端点处做**左右**混合。

只记"左／下"一侧是刻意的：同一条边在另一侧的像素那里会被记成它自己的另一侧，于是"连续的同侧标记"恰好就是这条边的一段，第二遍沿它走就能找到端点。

### 3.2 为什么必须两遍

第二遍要读**邻居**的标记才能判断 run 的端点，而同一个 draw call 内没有跨像素通信，所以第一遍必须先落成纹理。第二遍是逐纹素读标记，故边缘图必须 NEAREST —— 线性过滤会把布尔标记插值成小数，端点判断随之失真。

### 3.3 第二遍：搜端点、加权、四邻混合

对像素 $P$：若某方向的边标记成立，则沿该边的方向向两侧搜到这条 run 的两个端点（步数上限 $N$，本方案取 $8$），得到两侧长度 $a$、$b$（各自含 $P$，故 $a, b \ge 1$），run 长度

$$L = a + b - 1 \tag{2}$$

依据：两个方向都把 $P$ 数进去了，直接相加会重复计一次。

只在端点上加权（理由见 §4），权重

$$w = \frac{1}{2L} \tag{3}$$

混合写成"以本像素为基准往邻居挪"的形式：

$$c' = c + w_{\text{up}}(c_{\text{up}} - c) + w_{\text{down}}(c_{\text{down}} - c) + w_{\text{left}}(c_{\text{left}} - c) + w_{\text{right}}(c_{\text{right}} - c) \tag{4}$$

依据：$c + w(n - c) = (1-w)c + wn$，即"按比例 $w$ 把颜色挪向邻居"，$w$ 的含义就是"这个像素里该有多少是邻居的颜色"。

四个权重之和超过 $1$ 时等比缩放：拐角处两轴会同时给权（各 $1/4$），不缩放会把像素混成纯邻居色。

## 4. 权重 $1/(2L)$ 的推导

### 4.1 模型与假设

三条假设，缺一条结论就要改：

- **(A1)** 被处理的边界在局部是**直线**，并在所考察的 run 范围内把栅格切成"一侧实体、另一侧空"；
- **(A2)** 栅格化规则是**像素中心判定**（中心在实体侧则整像素判为实体）。标准光栅器在无多重采样时就是这样，本工程正是如此（全工程没有启用 MSAA，`GLFW_SAMPLES` 只作用于默认帧缓冲，而场景全部渲到离屏，最后往默认帧缓冲画的是一张与屏幕对齐的全屏 quad）；
- **(A3)** run 内的边界完全落在像素内部（不越出像素的上下边界），于是覆盖率就是"像素内边界一侧的面积"，不需要截断。

取像素单位坐标 $u$（水平）、$v$（竖直），像素 $(i,j)$ 覆盖 $[i,i+1) \times [j,j+1)$。把一条近乎水平的边界写成

$$v = \frac{u}{L}, \qquad u \in [0, L] \tag{5}$$

即它在 $L$ 列里上升 $1$ 个像素。这正是"run 长度为 $L$"的形状：依据是水平边在每个像素行里连续覆盖 $L$ 列，与 run 长度的定义一致。

### 4.2 命题与证明

实体取边界下方（$v < u/L$）。像素 $(i,0)$（$0 \le i \le L-1$）的真实覆盖率是像素内实体部分的面积：

$$C_i = \int_i^{i+1} \frac{u}{L}\,\mathrm{d}u = \frac{(i+1)^2 - i^2}{2L} = \frac{2i+1}{2L} \tag{6}$$

依据：被积函数的原函数是 $u^2/(2L)$，用牛顿-莱布尼茨公式即得；由 (A3)，$u \in [i, i+1] \subset [0, L]$ 时 $u/L \in [0,1]$ 不会越出像素，故积分无须截断。

端点像素的误差（栅格判定值为 $0$ 或 $1$）为

$$\Delta_0 = |C_0 - 0| = \frac{1}{2L}, \qquad
\Delta_{L-1} = \left|C_{L-1} - 1\right| = \left|\frac{2L-1}{2L} - 1\right| = \frac{1}{2L} \tag{7}$$

依据：$C_0 = (2\cdot 0 + 1)/(2L) = 1/(2L)$，$C_{L-1} = (2L-1)/(2L) = 1 - 1/(2L)$；栅格值由 (A2) 给出 —— 像素 $(0,0)$ 的中心是 $(0.5,\ 0.5)$，判据 $0.5 < 0.5/L$ 对 $L \ge 1$ 恒为假，故判空（值 $0$）；像素 $(L-1, 0)$ 的中心是 $(L - 0.5,\ 0.5)$，判据 $0.5 < (L-0.5)/L$ 对 $L \ge 1$ 恒为真，故判实体（值 $1$）。

**命题**：在 (A1)(A2)(A3) 下，run 端点像素的真实覆盖率与栅格判定值之差恰为 $1/(2L)$。把邻居颜色按 $w = 1/(2L)$ 混入，端点像素的颜色就等于该模型下的真实平均色。

这就是式 (3) 的依据：系数里的 $1/2$ 来自"半个像素的台阶高度"，分母的 $L$ 来自"这条边在栅格上延续 $L$ 个像素"。

### 4.3 三个算例

$w = 1/(2L)$ 的取值与式 (6) 的逐像素验算（栅格值由 (A2) 给出）：

| $L$ | $C_0$ | $C_1$ | $C_2$ | $C_3$ | 栅格值 | 逐像素误差 | $1/(2L)$ |
|---|---|---|---|---|---|---|---|
| 1 | $1/2$ | | | | 0 | $1/2$ | $1/2$ |
| 2 | $1/4$ | $3/4$ | | | 0, 1 | $1/4,\ 1/4$ | $1/4$ |
| 4 | $1/8$ | $3/8$ | $5/8$ | $7/8$ | 0, 0, 1, 1 | $1/8,\ 3/8,\ 3/8,\ 1/8$ | $1/8$ |

$L = 1$ 与 $L = 2$ 两行里，每个像素的误差都等于 $1/(2L)$；$L = 4$ 一行里端点误差等于 $1/(2L)$，中间两个像素的误差更大（$3/8$）但不被修正，原因见 §4.4。

### 4.4 中间像素为什么不修

$L = 4$ 那一行说明了一件必须交代清楚的事：**本方案不是"逐像素重算覆盖率"的精确解，它只修端点。**

形态学 AA 的定位就是"把台阶的角磨圆"：可见的锯齿是台阶的两端（直角），把它们按覆盖率磨成斜角，观感上的台阶就消失了。中间像素的偏差属于"每像素只有一个样本"的固有误差 —— 那需要更多样本才能消掉，也就是超采样。

由此得到一条定量说法：$L = 4$（较平缓的边界）时中间像素仍有 $3/8$ 的覆盖率误差未修正。它们之所以视觉代价小，是因为 $L$ 越大台阶越浅（台阶高度恒为 $1$ 个像素，被摊在 $L$ 列上）。

### 4.5 $L = 1$ 的处置

$L = 1$ 时两个端点重合（孤立台阶或 $45°$ 斜边），式 (7) 给出的 $1/2$ 无法判断该给哪一侧，因为模型在这一格里不含"边界往哪拐"的信息。

处置：把 $1/2$ 平摊给上下（或左右）两个邻居，各 $1/4$。两条依据：

1. 总权重仍是 $1/2$，与式 (7) 一致；
2. 总权重被压在 $1/2$ 以内，于是**一个像素宽的细亮线至少保住自身一半亮度**（细线两侧都是背景时，混入的是 $1/4 + 1/4 = 1/2$）。若把 $1/2$ 全给一侧，细线会掉到 $50\%$ 以下甚至更暗。

官方实现用专门的拐角图案分辨这种情况；我们用这个保守的平摊代替，代价是拐角处的观感略逊（§5）。

## 5. 与官方 SMAA 1x 的差别

| 项 | 官方 SMAA 1x | 本方案 |
|---|---|---|
| 遍数 | 3（边缘、权重、邻域混合） | 2（边缘、邻域混合） |
| 覆盖面积来源 | `AreaTex`（160×560，两通道）预计算表 | 式 (7) 解析计算 |
| 搜索 | `SearchTex`（64×16）做提前退出 | 线性搜索 + 步数上限 $N = 8$ |
| 两端长度不同的组合 | 面积表按 $(a, b)$ 二维索引，逐组合给出面积 | 两端各自独立取自己那一侧的 $L$，即只用式 (7) 的端点支 |
| 拐角 | 有专门图案 | 退化成"两轴各 $1/4$"（§4.5） |
| 外部资源 | 两张预计算表（需随工程分发） | 无 |
| 每像素采样上限 | 4 至 8 次 | 最多 $4 \times 8 = 32$ 次边缘采样（有早退，实际远少）＋ 4 次颜色采样 |

补充一条订正：`smaa_blend_frag.shader` 文件头写的"把'一个像素量级的台阶误差'分摊到 $L$ 个像素上"是当时的定性说法，**精确表述以 §4.2 的命题为准** —— 修正落在端点，端点的误差恰为 $1/(2L)$，中间像素不动（§4.4）。那条注释在下次改动该着色器时应一并订正。

## 6. 参数（三处常量 + 一个开关，全在 `Globals.h`）

| 名称 | 起点值 | 作用与耦合 |
|---|---|---|
| `SMAA_THRESHOLD` | `0.06f` | 式 (1) 的绝对阈值 $\tau$。调低则更多边被处理，代价是纹理细节跟着被磨（这是 SMAA 与 FXAA 的分界，也是它最像"糊"的方向）；调高则只处理强边，台阶有残留 |
| `SMAA_LOCAL_CONTRAST` | `0.15f` | 式 (1) 的相对阈值系数 $k$。取 $0$ 等于关掉自适应，那时亮部（高光、太阳附近）的纹理会被当成边 |
| `SMAA_MAX_STEPS` | `8` | 搜索上限 $N$，三重作用：限制开销；限制 $L$ 的估计（撞上限时 $L$ 偏小、权重偏大，但量级很小）；端点判定只看紧邻那一个像素，故长边（平缓边界，本就看不出台阶）自动不被处理 |
| `smaaEnabled`（`M` 键） | `true` | 整段开关。关掉时连两次 blit 都不做，画面与"根本没接 SMAA"逐像素一致，是做对照用的干净开关 |

## 7. 判据

失败复盘 §4.8 的教训是"没有量化判据的时间滤波不许开工"。这一套虽无时间维，判据仍然要有，分两类。

### 7.1 三条肉眼可判（已通过）

1. 斜边台阶变软 —— 这是唯一目标；
2. **纹理细节没有跟着糊** —— 糊了就说明 $\tau$ 偏低；
3. 一像素宽的细亮线没被抹淡 —— 细线保色以 $50\%$ 为设计上限（§4.5），实测应远好于此。

### 7.2 两条可测（建议显式跑一次，替代"看着不错"）

**(a) 定点对照**：把相机对准一个**边界干净的大物体**（火星边缘最合适；折跃时那条一像素宽的线框也行），在**同一视口位置**截两张图，`M` 开与 `M` 关各一张，只比较那一处。

原稿曾提出"统计全屏边缘像素数 $N_{\text{edge}}$ 的下降"，**该判据已撤销**。理由是这个统计量数的是全屏所有高频内容的总和（星带的岩石纹理、SSAO 噪声、恒星点全部计入），而 SMAA 对一条边只改动两个端点像素，信号会被纹理淹没；要让它有意义必须把统计范围限定到"只含几何边缘"的区域，那就不是"随便截一张图"能做，而且需要一个**新的计数工具**（截屏后按式 (1) 离线统计）。判据的价值在低成本，一旦需要新工具就不成立。

**(b) 细线保色**：在同一次定点对照里读数即可 —— 折跃线框那一像素宽的亮线，比较开／关 SMAA 时的峰值亮度。由 §4.5 推得的最坏下降是 $50\%$，实测应显著小于此；若接近 $50\%$，说明 `SMAA_MAX_STEPS` 偏小（$L$ 被低估、权重偏大）。

两条判据都只需要两次运行与两次截图，不引入新代码路径、也不需要新工具。

## 8. 它治不了什么，以及去向

- **亚像素小物体**：形态学 AA 的前提是"能辨认出一条边型"。星带里投影小于一个像素的高光点在栅格化里就是一个亮像素，没有边型可辨认，也就无从修起。这一类只有**空间超采样**能治，因为它的解法是"用更多样本把那个点采到"（与失败复盘 §2 的结论一致：那是采样问题）。
- **噪声**：SSAO 与体积光的噪声不是边型，SMAA 不动它。降噪在 `27.0` 里由 SSAO 自己的空间模糊承担（4×4 盒式模糊在该版本是活的；TAA 那版曾把它停用，随废弃一并回到原状）。
- **落点对照**：SMAA／FXAA 在合成之后（LDR），SSAA／MSAA 在合成之前（HDR 线性），见 §2.3。
- **若要治星带那一类**：走 SSAA（离屏渲染尺寸放大、合成时降采样），落点在 `PostProcessing` **之前**，与 SMAA 互补而非互斥 —— 两者可以同时开，也可以只留一个。
